# MD053: Unneeded link and image definitions

Status: analysis and configuration implemented for CommonMark and GFM. Findings are report-only; there are no automatic fixes.

Area: [Links and images](index.md).

## Behavior

Report definitions with no matching parsed reference, and later definitions shadowed by the first definition of the same normalized label.

A definition is used when a parsed full, collapsed or shortcut link or image
reference anywhere in the document resolves through the completed definition
lookup to that definition. Only references the parser recognized count:
bracket text in code spans, fenced or indented code, HTML blocks, raw HTML or
frontmatter is never a use, and inline links never use a definition.
Definitions inside block quotes and list items, at any depth, are treated like
top-level ones. Cross-file uses are not considered.

Every definition after the first one with the same normalized label (Unicode
case folding and whitespace collapse) is shadowed and gets one finding, whether
or not the label is used. A first definition that no reference uses gets one
unused finding. No definition gets both.

`ignored_labels` entries are label text without brackets. Each is normalized
like a label, and a first definition whose normalized label matches produces no
unused finding. Shadowed duplicates of an ignored label are still reported. An
entry that normalizes to the empty string matches nothing.

Each finding covers the definition's `[label]:`, from the opening `[` through
the colon, in original bytes and Unicode scalar columns; a single-line label
never includes a line ending, and CRLF input has the same columns as LF input.
The message names the normalized label:
`Definition "<label>" is not used by any reference.` or
`Definition "<label>" is shadowed by an earlier definition of the same label.`
A real suppressed finding counts as used for MD087.

When the definition collection is unavailable, no finding is reported and the
coverage message is
`Reference-definition context is unavailable; the complete MD053 inventory is withheld.`
When definitions are available but the lookup or a reference's resolution is
not, shadowed findings are still reported, unused findings are withheld, and the
coverage message is
`Reference-use context is unavailable; MD053 unused-definition findings are withheld.`

## Configuration

Default enablement: Enabled.

ignored_labels: string list, empty.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
[unused]: guide.md
````

Accepted input:

````markdown
[Guide][manual]

[manual]: guide.md
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

No MD053 edits, replacement documents or deferred fix proposals are produced
yet. The policy below is future work.

Delete only proven unused or shadowed definitions; preserve associated comments and recheck references.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
