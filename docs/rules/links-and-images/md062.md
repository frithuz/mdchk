# MD062: Whitespace in destination URLs

Status: analysis and configuration implemented for CommonMark and GFM. Findings
are report-only; there are no automatic fixes.

Area: [Links and images](index.md).

## Behavior

Recognize flat, fully closed inline link/image candidates with whitespace inside a bare destination, e.g. `[Guide](my guide.md)`, on one physical line. Exclude valid destination-plus-title syntax, permitted angle-bracket destinations, escaped whitespace as specified by the rule, and nested or otherwise ambiguous malformed delimiters. Keep valid parsed destination checks intact; the extra candidate grammar handles forms which otherwise fall back to plain text. No percent-encoding fix is implied.

Define bounded source-candidate recognizers alongside the selected dialect parser. Preserve parser ownership of valid constructs and protected code/raw/control regions. Do not infer author intent. Candidate recognition must not cross block/container boundaries; initially keep unparsed inline candidates to one physical line. Intentionally excluded ambiguous candidates are outside the rule scope and do not themselves cause incomplete coverage. Unreliable parsing or an unavailable required prerequisite still causes affected incomplete coverage.

Only exact, unescaped ASCII delimiter bytes establish the candidate structure:
an optional `!`, a flat `[text]` with no nested or unmatched brackets, and an
immediately adjacent flat `(destination)` with no nested or unmatched
parentheses or brackets. The text may be empty or blank. Escaped and
entity-decoded brackets and parentheses never act as delimiters. Valid parsed
links and images are opaque, so a destination followed by a valid title or a
valid angle-bracket destination is never a candidate.

After leading and trailing literal spaces and tabs are trimmed, the destination
must contain a run of literal ASCII space or tab characters. Content starting
with `<` is excluded, as is content whose first qualifying run is followed by
`"` or `'` (a broken title). A run directly preceded by a literal `\` does not
qualify, though another run in the same destination still can. Whitespace that
comes only from entities, backslash escapes or percent escapes such as `%20`
never qualifies, and neither does non-ASCII Unicode whitespace.

The whole candidate stays inside one contiguous text island on one physical
line. A candidate may sit inside emphasis, a list item, a block quote or a GFM
table cell, but its text and destination must be plain text: emphasis, code
spans, links or inline HTML inside the brackets or parentheses exclude it, so
`*[a](b c)*` reports while `[*a*](b c)` and `[a](*b* c)` do not. Code, HTML blocks, raw HTML lifetimes and tails, recognized
frontmatter and metadata are never scanned. Chains are excluded rather than
guessed: a candidate immediately preceded by `]` or `)`, starting right after a
parsed link or image, or immediately followed by `(`, `[`, `)` or `]` produces
no finding. An escaped `\!` makes the candidate a link candidate that starts at
its first `[`.

Each finding covers the complete original candidate, from `!` or the first `[`
through the closing `)`, and says `Whitespace in link destination.`
Coordinates use original bytes and Unicode scalar columns, and never include a
line ending. A real suppressed finding counts as used for MD087.

Unknown necessary source mapping or raw context before a possible candidate
withholds the entire inventory. The coverage message is
`Link-candidate context is unavailable; the complete MD062 inventory is withheld.`
Intentionally excluded syntax produces complete analysis without a finding.

See the [candidate contract](../../engineering/rule-behavior.md#malformed-syntax-candidates).

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
[Guide](my guide.md)

![Logo](my logo.png)
````

Accepted input:

````markdown
[Guide](my%20guide.md)

[Guide](<my guide.md>)

[Guide](guide.md "My guide")
````

To resolve a finding, percent-encode the whitespace (`%20`) or wrap the
destination in `<...>`, after checking which resource the link should select.

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

No MD062 edits, replacement documents or deferred fix proposals are produced.

Report only; encoding whitespace may select a different resource.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
