# MD011: Swapped link delimiters

Status: analysis and configuration implemented for CommonMark and GFM. Findings
are manual; automatic delimiter replacement remains planned.

Area: [Links and images](index.md).

## Behavior

Recognize flat, immediately adjacent (label)[URL] candidates with nonblank label and a valid absolute HTTP or HTTPS URL with a nonempty host, on one line. Exclude images, escaped outer delimiters, nested/ambiguous delimiters, whitespace in the URL and relative destinations. Existing valid parsed constructs take precedence. Preserve the documented conditional correction policy, requiring reparse and proof of the intended link structure before any later fix.

Define bounded source-candidate recognizers alongside the selected dialect parser. Preserve parser ownership of valid constructs and protected code/raw/control regions. Do not infer author intent. Candidate recognition must not cross block/container boundaries; initially keep unparsed inline candidates to one physical line. Intentionally excluded ambiguous candidates are outside the rule scope and do not themselves cause incomplete coverage. Unreliable parsing or an unavailable required prerequisite still causes affected incomplete coverage.

Only exact, unescaped ASCII delimiter bytes establish the candidate structure.
Entities and escapes inside the label or URL retain their parser-decoded value
once; their decoded brackets do not become delimiters. The label must contain
at least one character outside CommonMark Unicode whitespace. URL schemes are
case-insensitive; the hierarchical HTTP(S) authority must have a nonempty host.
Unicode host/path text, user information and numeric ports are supported when
valid. Whitespace, control characters, malformed percent escapes (including in
queries) and characters outside the permitted URI spelling are excluded. Encoded
spaces remain allowed. Host validity does not depend on Go's legacy-colon
compatibility setting.

Candidates remain inside one actual prose owner, including local emphasis,
strong or strikethrough text. They cannot cross inline ownership boundaries.
Whole parsed links and images are opaque, including image alternatives. Thus a
GFM autolink can protect text that CommonMark leaves eligible. Code, recognized
frontmatter, raw HTML lifetimes and parser-owned HTML tails remain protected.

Nested or unmatched groups do not expose inner candidates. A balanced excluded
group permits later recovery; an unmatched opener excludes the rest of that
text island. An extra closing delimiter immediately after a pair excludes it.
An immediately preceding `)` or `]` also excludes it unless that byte closes the
previous structurally complete flat pair. An exact `!` before the opening `(`
excludes an image-like form; an escaped `!` does not.

Each finding covers the complete original `(label)[URL]` envelope and says
`Link label and destination delimiters are swapped.` Coordinates use original
bytes and Unicode scalar columns. Recognition precedes inspection focus and
suppression; the finding's start selects either filter. A real suppressed
finding counts as used for MD087.

Unknown necessary source mapping or raw context withholds the entire inventory,
including earlier provisional findings. The coverage message is
`Link-candidate context is unavailable; the complete MD011 inventory is withheld.`
Unknown raw context after the last possible original candidate is irrelevant.
Intentionally excluded syntax produces complete analysis without a finding.

See the [candidate contract](../../engineering/rule-behavior.md#malformed-syntax-candidates).

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
(Guide)[https://example.org]
````

Accepted input:

````markdown
[Guide](https://example.org)
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

No MD011 edits, replacement documents or deferred fix proposals are produced.

Future correction may swap delimiter pairs only for unambiguous candidates with
a valid URL, after reparsing proves the intended link structure and shared
preservation checks succeed.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.
