# MD051: Unresolved fragment targets

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Links and images](index.md).

## Behavior

Report links to fragments absent from the target document. Build heading anchors using the selected anchor convention and recognize explicit anchors. External URLs are excluded.

Use the [anchor contract](../index.md#anchor-resolution).

Implemented scope: actual prose Links with a fragment marker in their parser-semantic
destination, inline or full/collapsed/shortcut reference origin. Images, autolinks,
bare URLs, definitions, code, comments, metadata and actual raw HTML payload are
excluded. Remote (`scheme:` and `//`) destinations are ignored. A destination with
an empty path (fragment-only, or query-only such as `?a=1#part`) addresses this
document. The fragment is percent-decoded once as UTF-8 and compared
case-sensitively with generated heading IDs and verified HTML IDs under
`resources.anchor_style`; an empty decoded fragment names the document and is
accepted. An invalid escape or invalid UTF-8 is reported as unresolved with a
distinct message.

Report `Fragment target is not defined in this document.` at the original
destination for inline Links and at the whole Link for reference origins.
A nonempty path is resolved by the shared read-only resource service: the
destination is normalized once, relative to the source, and a spelling that names
the current source (`./self.md#part`, or a directory whose configured
`resources.index_file` is this document) reuses its snapshot even when
`cross_file` is false. Other documents are read only when `cross_file` is true; a
directory tries `resources.index_file` exactly once, including the project root
(MD057's root exemption does not apply to fragments). A found/absent target reports
`Fragment target is not defined in the referenced document.` (or the invalid
percent-encoding message). A confirmed missing document, directory without an
index, or wrong target type is inapplicable: MD057 owns it and MD051 reports
neither a finding nor a coverage deficit. Unknown existence, blocked paths
(root escapes, symbolic links, Git metadata, unsupported forms), unreadable or
non-UTF-8 content and uncertain anchor syntax produce a located
`context-unavailable` coverage record per link, with attributed `io` errors for
actual read failures. The CLI `lint`, `inspect` and `fix` (dry-run and apply)
commands supply this context from the selected repository/configuration root,
binding exactly the acquired targets; it never writes, follows links, loads nested
configuration or lints referenced documents, so a resource lookup can never become
a write target. `lint` and `inspect` resolve against the original snapshots. `fix`
analyzes each candidate against that target's candidate content (other selected
targets keep their original acquisition, because no final overlay exists while
rounds run) and, on apply, re-checks the observed saved overlay (confirmed saved
bytes per target, explicitly unavailable otherwise); findings and coverage carry
the `candidate` or `saved` snapshot. An unreadable neighbor is reported as an
attributed `io` error but does not withhold independent corrections for the
target. Directory links use `resources.index_file`, which the CLI accepts when the
native adapter can name it (`index_file: README.md`); `.git` and other names the
adapter cannot represent are rejected. A non-Markdown target (for example `img.png#x` or `notes.txt#x`) exists but
supplies no anchors, so it is reported as located `context-unavailable` coverage
rather than a finding. Without a resource provider (embedding callers), a link that merely
spells this document (`./self.md#x`) is skipped when `cross_file` is false,
because it cannot be proven to name the current source. A single link whose
destination exceeds a path bound (`path-bytes`/`path-depth`) is not resolvable: it
is skipped when `cross_file` is false and, when true, contributes a document-level
(unlocated) message saying the destination exceeds the path bounds. Budget, deadline and cancellation stops are still
reported as interruptions. Unknown
anchor or raw-HTML context withholds the affected same-document findings with
explicit reduced coverage. Reports use the invocation-relative path, while
resolution uses each target's root-relative key, so results do not depend on the
working directory.

Known missing destination documents belong to MD057; their fragment check is inapplicable, without a duplicate finding or coverage deficit. Disabling MD057 does not transfer existence checking to MD051. Unknown existence, unavailable content, or uncertain anchor parsing makes an applicable fragment check incomplete.

`cross_file: false` skips distinct documents, while fragment-only, query-only, and normalized explicit references back to the current source reuse its snapshot. An empty fragment addresses the document itself. Directory references use shared `resources.index_file` exactly once.

## Configuration

Default enablement: Enabled.

cross_file: boolean, false.

Anchor policy is shared through [`resources.anchor_style`](../../configuration.md#shared-resource-settings), default `github`; this rule has no `anchor_style` option.

All rules also accept the [shared settings](../index.md#configuration-and-findings).
Unknown options and invalid values reject even when the rule is disabled.

## Examples

Violating input:

````markdown
# Install

[Jump](#usage)
````

Accepted input:

````markdown
# Install

[Jump](#install)
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Permanently report only; the intended target cannot be guessed. MD051 has NoFix
metadata and produces no automatic edits, previews or corrected content. Cross-file
checks will require bounded resource access.

## Validation

Reusable literal analysis fixtures cover the examples, `cross_file`, anchor styles,
protected content, nested containers, reference origins, percent decoding, LF and
CRLF input and precise diagnostic ranges for both formats. Engine, inspection and
compiled CLI checks verify defaults, shared directives and unchanged source.
Compiled CLI checks over native fixtures cover found, absent, malformed,
missing-document, directory/index, self-path, symbolic-link, root-escape,
non-UTF-8 and remote cases, and verify that resource lookups never change files.
