# MD095: Lookalike Unicode characters in destinations

Status: planned for implementation.

Area: [Links and images](index.md).

## Behavior

Keep MD095 disabled by default and report-only. Use the shared parsed destination inventory and protected-region rules; do not infer additional links from arbitrary prose.

Check DNS hostnames in hierarchical absolute URLs and protocol-relative destinations with an authority. Separate user information and port before hostname processing. Paths, query strings, fragments, display text, local paths, opaque URIs including mailto, and IPv4/IPv6 literals are outside MD095. This is a character-lookalike heuristic, not brand reputation or proof of malicious intent.

Pin Unicode 17.0.0 hostname processing and normalization alongside the confusable table. Use UTS #46 nontransitional processing with STD3 ASCII rules, label/hyphen/joiner validation, bidi validation and DNS length validation; never silently remove leading dots or empty labels. Validate A-labels and decode them to the normalized Unicode form, checking round trips. Raw Unicode and equivalent xn-- labels receive identical findings. Normalize one final root dot for comparison. IDNA compatibility forms that normalize to ordinary ASCII do not remain separate lookalike-domain findings.

After IDNA normalization, inspect each remaining non-ASCII code point. Report when its direct mapping in the pinned confusables.txt is a nonempty sequence solely of ASCII letters A-Z/a-z. Do not strip accents/combining marks, apply additional transliteration or recursively transform mappings. This is an explicitly scoped table-based rule, not a claim of full UTS #39 security-profile implementation. ASCII-only lookalikes and mappings to digits or punctuation are outside this rule; mixed scripts alone are not a violation.

allowed_hosts entries are bare DNS hostnames, Unicode or A-label form. Apply the same validation and convert to lowercase canonical ASCII IDNA form, removing one final root dot. Match exact whole hosts only, independent of URL port; no implicit subdomain matching, wildcards, URL syntax, whitespace trimming or confusable-skeleton comparison. Invalid entries are configuration errors. Allowlisting the ASCII lookalike does not allow the distinct Unicode host.

Use shared syntax decoding once, with source mapping, including valid percent-encoded UTF-8 in a hostname; do not double-decode or reinterpret authority delimiters. Invalid URL authority, invalid UTF-8, invalid IDNA/Punycode or characters unsupported by the pinned profile produce a located problem and affected incomplete MD095 coverage, rather than guessed validity or a clean result. Continue reliable independent checks.

Report once per destination hostname occurrence, identifying the source hostname and flagged code points/mappings. For punycode or escaped source use the whole original hostname span if there is no precise character span. Shared reference-definition ownership avoids repeating the same source destination. Exact result encoding follows the accepted shared result schema.

Embed reviewed versioned data with its SHA-256 and license; run entirely offline, with no DNS, HTTP, reputation lookup or runtime table update. Upgrades require explicit table/profile version changes and fixture review. Never rewrite a hostname.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

allowed_hosts: hostname list, empty; compare hosts case-insensitively.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
https://exаmple.org where а is Cyrillic U+0430.
````

Accepted input:

````markdown
https://example.org
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; substituting characters may redirect the link to an unintended site.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
