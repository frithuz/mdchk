# MD039: Whitespace surrounding link labels

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Links and images](index.md).

## Behavior

Report literal leading or trailing whitespace in the visible first-bracket label
of an actual inline, full-reference, collapsed-reference or shortcut Link. Inspect
original label contributions before entity or escape decoding. Reference
identifiers, definition labels, unresolved bracket text, angle autolinks and bare
GFM autolinks are excluded. Image alternative text and all its descendants remain
protected; a Link surrounding an Image can still have outer label whitespace.

Whitespace means Unicode Zs plus TAB, LF, FF and CR. VT, NEL, LS and PS are not
edge whitespace. Nested markup, escapes and entities bound the raw edge; rendered
whitespace from `&nbsp;` or `&#32;` does not create a finding. Whitespace inside an
embedded code span is protected, while literal outer label whitespace around that
span remains eligible. Actual code, comments, metadata and raw HTML lifetimes are
protected, including raw state opened or closed inside a link label.

Report each maximal source-contiguous offending edge run with
`Whitespace surrounding link label.`. Logical runs crossing consumed list or
blockquote prefixes produce separate original source ranges, excluding those
prefixes or consumed continuation indentation. Retain CRLF atomically. All-whitespace labels report each run once;
empty labels are clean. Findings use original byte offsets and one-based Unicode
code-point columns with exclusive ends. Unknown required context withholds the
complete MD039 inventory with explicit reduced coverage.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings).
Unknown options and invalid values reject even when the rule is disabled.

## Examples

Violating input (two findings, one for each outer SPACE):

````markdown
[ Guide ](guide.md)
````

Accepted input:

````markdown
[Guide](guide.md)
[` x `](guide.md)
[&nbsp;Guide&#32;](guide.md)
![ Guide ](image.png)
````

Resolved reference labels follow the same rule:

````markdown
[ Guide ][id]

[id]: guide.md
````

The second identifier in `[Guide][ id ]` is not the visible label and is excluded.
Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>`
describe source characters rather than literal Markdown.

## Correction policy

Permanently report only; the visible label may intentionally contain spaces.
MD039 has NoFix metadata and produces no automatic edits, previews, corrected
content or correction eligibility. MD047 remains the sole current fixer.

## Validation

Reusable literal analysis fixtures cover examples, configuration boundaries,
protected content, reference origins, nested containers, LF/CRLF/CR and precise
original diagnostic ranges in both formats. Engine, inspection and compiled CLI
checks verify defaults, directives and unchanged source in analysis and fix dry
runs. MCP adapter parity remains downstream in #196, #200 and #206.
