# MD057: Missing local link targets

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Links and images](index.md).

## Behavior

Report local link destinations that resolve to an accessible nonexistent file or directory index. Exclude remote URLs and fragment-only links. A valid fragment does not excuse a missing target file.

Use the [resource contract](../index.md#resource-dependent-checks). Resolve resources read-only; never create missing targets.

Only authoritative absence or a known file/directory-index type mismatch establishes a finding. A partial standalone map omission, blocked path, denied symlink, or unknown directory index is incomplete coverage, not absence. Existing files need no content for this check, including images. Actual filesystem failures retain an attributed operational error.

Try the configured directory index once, without README/HTML fallback or recursive index lookup. A known file addressed with a directory hint, or a directory at the index-file path, is a mismatch. A malformed fragment does not prevent checking an otherwise valid local file path. See [lookup outcomes](../../engineering/resources.md#outcomes-and-rule-ownership).

Implemented scope: actual prose Link and Image destinations, decoded once by the
parser, with inline or full/collapsed/shortcut reference origin, including Images
inside Links (the description of an Image is not traversed). Autolinks, bare URLs,
unused definitions, code spans and blocks, comments, directives, frontmatter,
table alignment rows and actual raw HTML payload are excluded; HTML `href`/`src`
attributes are not checked. Images are checked unless `check_images` is false.
Remote (`scheme:` and `//`) destinations, empty destinations and destinations with
an empty path (fragment-only, or query-only such as `?a=1#x`) are ignored. Any
fragment and query are removed before the path check, so `missing.md#intro` is
reported and `guide.md#%ZZ` passes when `guide.md` exists; fragment validity
belongs to MD051. A path naming the current document passes without a lookup.

Findings are reported at the original destination for inline origins and at the
whole Link or Image for reference origins, whose destination lives in a
definition. The shared read-only resource service normalizes the destination once
relative to the source and makes one existence-only lookup, which never reads
content, so images and other non-Markdown files pass by existing. The messages are
`Local link target does not exist.` for an authoritatively missing path,
`Local link target is a file, but the destination requires a directory.` for a
file addressed with a trailing slash, `Directory has no configured index file.`
for a directory whose `resources.index_file` is absent, and
`Directory index path is a directory, not a file.` when the index path is a
directory. A directory link, with or without a trailing slash, tries
`resources.index_file` exactly once, with no README or HTML fallback, recursion or
directory scan; an index that is the current document passes. The project root
(the resource root the CLI selected, spelled for example `.`, `./` or `../` from
a subdirectory, or the virtual root of a supplied inventory) is no exception:
like MD051 `cross_file`, it tries `resources.index_file` once and reports
`Directory has no configured index file.` when that index is absent. See the
[resource contract](../../engineering/resources.md#outcomes-and-rule-ownership).

Unknown existence, partial supplied inventories, blocked paths (root escapes,
absolute and drive paths, symbolic links, Git metadata, names the adapter cannot
represent), unknown directory indexes and read failures produce one located
`context-unavailable` coverage record per link and never a finding, with one
attributed `io` error per failed resource. A destination beyond a path bound
(`path-bytes`/`path-depth`), missing resource context (no provider, or a root
that cannot be opened) and an unavailable link inventory each add a document-level
coverage message instead; a document without a local destination to check never
opens a resource root. The CLI `lint`, `inspect` and `fix` (dry-run and apply)
commands supply the context through the same lazy session as MD051, so either
rule works when the other is disabled. MD057 is report-only: it emits no edits,
previews or changed documents, and never creates files.

## Configuration

Default enablement: Enabled.

check_images: boolean, true.

Directory lookup uses shared [`resources.index_file`](../../configuration.md#shared-resource-settings), default `index.md`; this rule has no `index_file` option.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
[Guide](missing.md)
````

Accepted input:

````markdown
[Guide](guide.md) where guide.md exists.
````

Prose examples: `[Docs](docs/)` is reported with
`Directory has no configured index file.` when `docs/` exists without
`resources.index_file`. `[Home](../)` from `docs/a.md` names the project root and
is reported the same way unless the root has `resources.index_file`.

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; do not create files or guess alternative paths.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. MD057 has no corrections; verify that `fix` changes no file because of it.
