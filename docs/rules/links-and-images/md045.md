# MD045: Images without alternative text

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Links and images](index.md).

## Behavior

Check recognized Markdown images, reference images and raw HTML img elements. Missing HTML alt, empty alt and Unicode-whitespace-only alternative text are findings unless the explicit HTML decorative exemption applies. Decode HTML character references before classification; missing and present-empty attributes remain distinct.

When allow_decorative=true, an explicitly present HTML alt attribute whose decoded value is exactly empty declares the image decorative. No additional role is required. Empty HTML attribute syntax equivalent to alt="" is treated by its decoded value; do not trim whitespace-only alt into an empty decorative declaration.

Do not grant the empty-alt exemption if the img has a nonblank title, any role other than an absent/empty role or a single none/presentation token, any aria-* attribute except aria-hidden="true", or a tabindex/usemap/ismap attribute. These are static, local disqualifiers for this narrow exemption, not a full accessible-name or accessibility-tree evaluation. A nonempty alt still satisfies the base MD045 check; unrelated ARIA conflicts are not new MD045 findings.

role="none", role="presentation", aria-hidden="true", hidden, filenames and visual appearance alone never replace the required explicit empty alt declaration. Missing or whitespace-only alt remains reportable even with those attributes.

The exemption applies only to explicitly authored HTML img markup. Empty Markdown image syntax such as `![](image.png)`, including reference forms, remains reportable even with allow_decorative=true.

Malformed or duplicate relevant attributes that prevent reliable interpretation produce a located parsing problem and affected incomplete coverage rather than a guessed exemption or alternative text. Preserve reliably established independent findings.

Do not infer whether an image is truly decorative from pixels or surrounding prose, fetch images, synthesize text, add attributes, or perform full page accessibility validation. Keep all MD045 findings report-only.

See the [complete rule contract](../../engineering/rule-behavior.md).

Markdown alternative text follows the parser's rendered image-description rules:
semantic text and code-span literals contribute text, breaks contribute a newline,
formatting/link/image children contribute their descriptions, and HTML tags do not
contribute text. Check each recognized Image, including nested descriptions, but
never treat HTML spelling inside a description as a separate HTML image.

Report `Image alternative text is missing or blank.` at the original Markdown
label interior or the original HTML alt value. Empty values use a zero-width
insertion point; missing HTML alt uses the point immediately after the tag name.
Ranges retain original entity spellings and multiline container gaps, with
one-based Unicode code-point columns and exclusive ends. Uncertain HTML produces
a located `rule-parser-uncertain` note and affected `parser-uncertain` coverage;
independently established findings remain available.

## Configuration

Default enablement: Enabled.

allow_decorative: boolean, false; when true, explicitly marked decorative HTML images are exempt.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
![](diagram.png)
````

Accepted input:

````markdown
![Deployment diagram](diagram.png)
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; meaningful alternative text must be authored.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
