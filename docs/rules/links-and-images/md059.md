# MD059: Uninformative link labels

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Links and images](index.md).

## Behavior

Report links whose normalized visible label exactly matches a configured uninformative phrase. Image-only links use the image alternative text as their label.

Inline links `[text](url)`, full references `[text][label]`, collapsed
references `[text][]` and shortcut references `[text]` that resolve to a
definition are checked in paragraphs, headings, block quotes, list items and
table cells. Angle autolinks, bare GFM URLs, raw HTML `<a>` elements, bracket
text that is not a link (including an unresolved `[text][missing]`), link
reference definitions, and anything in code spans, code blocks, HTML blocks,
inline raw HTML lifetimes or frontmatter are never checked. A link inside an
image description renders as alternative text, so it is not checked either.
The reference label, `label` in `[text][label]`, never contributes to the
visible label.

The visible label is built like the [MD045](md045.md) image description: text
and code span content are joined in order with entities and escapes decoded,
emphasis, strong emphasis and strikethrough contribute their contents, each
soft or hard line break contributes one whitespace, inline HTML contributes
nothing, and a nested image contributes its own alternative text. A label that
holds only one image and whitespace is therefore the image's alternative text:
`[![here](i.png)](x)` has the label `here`. A label that mixes an image and
text combines them, so `[![icon](i.png) here](x)` has the label `icon here`.

The label is trimmed, and each internal run of whitespace (TAB, LF, FF, CR or a
Unicode space separator) becomes one space. Each phrase is normalized the same
way. A link is reported when its label equals some phrase under Unicode simple
case folding. There is no Unicode normalization, punctuation stripping, or
substring matching, so `[here.](x)`, `[click here now](x)` and `[hère](x)` are
accepted. A phrase that normalizes to the empty string matches nothing.

Each matching link produces one finding, `Link label is uninformative.` The
range covers the original label interior, from just after the opening `[` to
just before its `]`, including any container prefixes such as `> ` inside a
label that spans lines. Coordinates use original bytes and Unicode scalar
columns, and never split a CRLF line ending. A real suppressed finding counts
as used for MD087.

When a link's properties or the raw HTML state are unknown, the whole
inventory is withheld instead of guessed. The coverage message is
`Link label context is unavailable; the complete MD059 inventory is withheld.`

## Configuration

Default enablement: Enabled.

phrases: string list, [click here, here, more, read more]; case-insensitive.

A configured `phrases` list replaces the default list rather than merging with
it. `phrases: []` disables matching: no findings and no coverage deficit.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
[Click here](guide.md)
````

Accepted input:

````markdown
[Installation guide](guide.md)
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; replacement labels require knowledge of the destination.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
