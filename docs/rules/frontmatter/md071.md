# MD071: Blank line following metadata

Status: analysis and configuration implemented. Correction remains manual.

Area: [Frontmatter](index.md).

## Behavior

Require a blank line between recognized frontmatter and the first body block. A header with no body is exempt.

Run only with frontmatter recognition enabled. Metadata is otherwise protected from body rules. Recognition follows the [YAML/TOML frontmatter contract](../../engineering/frontmatter.md); JSON headers are deferred. Structured key inspection requires the corresponding metadata parser.

With recognition disabled, MD071 is inapplicable: it reports no findings and no coverage, and inspection lists it as skipped with reason `inapplicable`. With recognition enabled, a file whose first line is not a selected opener has no header and no MD071 finding. An unterminated header makes analysis incomplete through the engine's parser-uncertain coverage and yields no MD071 finding.

A complete header is followed by the physical line that starts after the closer's line ending. When that line contains only spaces and tabs, or when the closer ends the file, there is no finding. Header-only files are therefore exempt, including a closer at EOF with or without a final line ending and a closer followed only by blank lines. Any other first body line is reported, whatever block it starts, including indented lines and container markers.

Each finding is a zero-width span at the first byte after the closer's line ending: line *closer line + 1*, column 1. The position is the same for LF, CRLF, CR and BOM-prefixed input apart from byte offsets. The message is `Frontmatter requires a blank line before the document body.` Metadata is never decoded.

A `<!-- mdchk:disable MD071 -->` comment on the first body line cannot suppress the finding, because directive transitions begin after the comment's closing marker and the finding sits at the start of the comment line. Disable MD071 through configuration instead.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). Unknown keys, `null` and values of the wrong type are rejected, even when `enabled: false`.

## Examples

Violating input:

````markdown
---
title: Guide
---
# Guide
````

Accepted input:

````markdown
---
title: Guide
---

# Guide
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Findings are manual in this build: no edits or previews are produced. The planned correction inserts one line ending after the closing metadata delimiter and runs only with frontmatter enabled.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
