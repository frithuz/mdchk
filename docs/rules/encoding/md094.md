# MD094: Invalid UTF-8 bytes

Status: analysis and configuration implemented; report only.

Area: [Encoding](index.md).

## Behavior

Validate the original document snapshot as strict UTF-8 before Markdown parsing, metadata recognition or directive interpretation, independent of MD094 enablement and of whether any ordinary rule is enabled. The gate is mandatory core input handling. On failure, retain the original bytes, skip normal parsing and all content edits for that file, and continue independent selected files under existing partial-failure behavior. Never guess an encoding, transcode or substitute replacement characters.

Document directives cannot control the pre-parse UTF-8 gate or MD094 attribution. In a valid parsed document, an otherwise valid directive naming MD094 is an inapplicable effect explained in processing notes, without changing its effective state; other permitted targets in the same comment retain their normal effects. When global directive interpretation is disabled retain existing inactive-candidate behavior. Invalid documents have no interpreted directives, including comments before the first bad byte. MD087 does not assess MD094 suppressions because directives do not apply to it.

Emit a separate encoding error for each invalid maximal subpart of a failed target snapshot, in source order. Subpart boundaries follow Unicode U+FFFD substitution of maximal subparts (Unicode chapter 3, table 3-7): a subpart is the longest prefix of a well-formed sequence, so `E2 82` before ASCII is one subpart, while the surrogate `ED A0 80` and the overlong `C0 AF` are one subpart per byte. `C0`, `C1`, `F5..FF` and a lone continuation byte each stand alone.

Each error's zero-based `byte_offset`, the subpart's leading byte, is the authoritative location, and `byte_range` is its half-open span. The message names the bytes, for example `Invalid UTF-8 byte sequence 0xE2 0x82 at byte offset 7.`. A one-based line and column point comes from the shared physical lines, without transcoding. Each valid scalar, including a BOM and a tab, counts as one column, and each earlier invalid subpart on the line counts as one column, the width U+FFFD would occupy. The `range` is zero-width at that point.

A file retains at most 1,000 of these errors and an operation at most 10,000, with files consuming the operation allowance in path order. A file always keeps its first error. Anything past those caps is counted, not listed, in one `/errors` omission for that file with reason `output-limit`, its `path` and the exact `count`, so a capped report is `complete: false` and never looks complete. Only lint's last-resort minimal report, when essential records exceed `response-bytes`, replaces located errors with category summaries. See [encoding error retention](../../engineering/limits.md#encoding-error-retention).

Store these as operational io errors, not also as ordinary rule violations. One `decoding-failed` coverage record per file links to all of its retained errors. Lint/fix/preview become incomplete with error status and exit 13 unless an existing higher-precedence internal failure applies. Decoding-dependent coverage remains unavailable with the encoding cause attached. Ordinary Markdown findings cannot be produced from a partially decoded file. Exact fields follow the [shared result schema](../../engineering/results.md#shared-result-schema).

If the raw file snapshot can be acquired and the report delivered, inspect retains status inspected and exit 0, includes original byte size/digests and the encoding errors with any retention omission, and marks complete false. AST, parsed directives and decoding-dependent analysis are explicitly unavailable. Do not invent active/inactive state where unavailable directive interpretation could change it; independently resolved configuration data remains visible. Existing argument, target-acquisition, delivery and internal error exits still apply. A byte-based newline index can validate requested line bounds without treating invalid bytes as decoded characters.

Valid UTF-8 encoding of literal U+FFFD is not an encoding error. UTF-8 BOM bytes are also valid; retain their independent metadata/style treatment. Validate byte encoding only, without heuristically declaring a well-formed byte sequence to be another encoding based on apparent content. Empty files are valid UTF-8.

Filesystem resources needed only for read-only context keep the existing generic resource io decode-error and affected source-coverage contract; do not recursively run MD094 as a resource rule. Standalone MCP accepts exact Unicode strings, with malformed raw UTF-8 or unpaired surrogate escapes rejected at the existing request boundary before document analysis. Do not add binary/base64 payloads to create invalid-byte standalone fixtures. Project MCP uses the same target-file decoding gate as CLI.

Keep MD094 in the known catalog and preserve configured active/inactive accounting where state is resolvable. Inspection identifies mandatory input validation separately from configurable rule attribution, so a disabled MD094 entry does not imply that byte validation was skipped. Core validation must exist in every build that accepts document bytes; it is not an optional unavailable parser capability.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Enabled.

No rule-specific options. Shared `enabled` controls attribution only: false emits a generic I/O decoding error. Neither `enabled` nor `allow_directives` can disable strict UTF-8 validation.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
A raw byte FF in a UTF-8 document.
````

Accepted input:

````markdown
UTF-8 encoded text.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only. Emit one I/O error for each retained invalid maximal subpart, attributed to MD094 only when enabled; skip normal parsing and do not transcode.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
