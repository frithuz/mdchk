# MD048: Backtick versus tilde fences

Status: analysis and configuration implemented for CommonMark and GFM. Findings
are manual; automatic delimiter replacement remains planned.

Area: [Code blocks](index.md).

## Behavior

Require actual fenced code blocks to use the configured delimiter. In
`consistent` mode, the first eligible fenced block establishes the delimiter for
the whole document, including nested lists and blockquotes. The baseline does
not reset at containers or headings and does not use majority voting. Empty and
unclosed fences count. Indented code blocks never establish or violate it.

The exemplar comes from the full original document before directive suppression
or inspection focus. Suppressing the first opener does not remove its baseline.
Code payload, inline code, recognized metadata, whole images, comments and actual
raw HTML regions cannot supply nested candidates. Raw-looking payload text does
not establish an outer HTML lifetime. Width, info strings and closing markers do
not determine delimiter identity.

Each mismatch produces one finding over the entire original opening marker,
excluding indentation, container prefixes, info, line ending and closing marker.
Columns count Unicode code points; container tabs remain whole source bytes.
The exact messages are:

- `Fenced code block should use backtick delimiters.`
- `Fenced code block should use tilde delimiters.`

Unknown necessary ownership, delimiter or selected opening mapping withholds the
complete inventory with explicit reduced coverage. Fixed matching fences need
no diagnostic mapping. If every potential fenced owner has the same known
character, every raw-exclusion subset is also consistent; that clean proof needs
no raw or marker mapping. Unknown owner or delimiter metadata disables this
proof. Mixed candidates require actual eligibility before choosing a baseline.
Unused payload, info and closing mappings do not prevent analysis.

## Configuration

Default enablement: Enabled.

`style`: `consistent`, `backtick`, or `tilde`; default `consistent`. Values are
case-sensitive and are not trimmed. Omitted rules and empty mappings retain the
enabled default. Invalid options are rejected even when the rule is disabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
```text
a
```

~~~text
b
~~~
````

Accepted input:

````markdown
```text
a
```

```text
b
```
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Pass 1 emits no MD048 edits, delimiter previews, corrected documents or deferred
proposals. Planned correction metadata does not make findings automatically
fixable. An independently safe MD047 prose-EOF newline correction may coexist
with manual MD048 findings on the candidate snapshot. The conservative refusal
to change a closing-fence EOF remains in place.

Future correction must replace both markers, choose a safe length, preserve
info and payload, and reparse the result before publication.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Frozen literal fixtures cover both supported flavors, all styles, original
opening ranges, LF/CRLF/CR, Unicode, nested containers, atomic tabs, protected
content, metadata and EOF. Supplemental checks cover configuration, suppression,
inspection focus, private authority, atomic unknown context and distinct caller
and origin publication gates. Exact and one-short work/node tests cover empty
producer and facade paths; positive costs are statically documented and positive
publication controls independently prove discard. Compiled CLI checks cover
reporters, manual refusal, MD047 composition and unchanged source state. MCP
transport parity remains downstream.
