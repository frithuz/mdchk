# MD014: Shell prompts without command output

Status: analysis and configuration implemented for CommonMark and GFM. Findings
are manual; automatic correction remains future work.

Area: [Code blocks](index.md).

## Behavior

Inspect actual fenced code blocks whose selected language matches `languages`.
Use the first nonempty token of the parser's already-decoded info string,
separated only by ASCII SPACE/TAB. Compare the whole token exactly and
case-sensitively; do not infer aliases, parse attributes or decode twice.

Ignore empty payload lines and lines containing only ASCII SPACE/TAB. A prompt
starts at payload column zero with an original ASCII `$`, followed by one or
more ASCII SPACE/TAB and at least one non-SPACE/TAB character on the same line.
Do not trim additional retained indentation. A bare `$`, an empty command,
variables such as `$HOME`, escaped/lookalike dollars and continuation lines do
not match. Unicode whitespace is neither an ASCII separator nor an ignored blank.
This is a finite lexical policy, not shell execution or command-intent inference.

Every other nonblank line counts as output. Report every prompt dollar only
when the entire selected block has at least one prompt and no output lines.
Thus a plain command, bare dollar or continuation can exempt other prompts in
that block. Blocks have independent state. Mixed commands and output are allowed.
The finding covers only the original one-byte `$` and says:

> Shell command has a dollar prompt without output.

Payload follows actual parser ownership after container prefixes and opening
fence indentation are removed. Remaining spaces and partial-tab indentation stay
literal; valid unclosed fences run through their actual EOF/container boundary.
LF, CRLF and CR preserve original coordinates. Synthetic terminal LF contributes
no selectable byte or extra line. Directive-looking code remains literal payload
and can count as output. Full block context is evaluated before finding-START
suppression and inspection selection; output outside selected lines still exempts
the block.

Indented code, inline code, recognized opaque headers, HTML-owned spelling,
actual raw lifetimes and whole Image contexts are excluded. Original named raw
lifetimes, actual HTML closure and Image isolation remain authoritative; this rule
does not implement another HTML grammar. Unknown necessary language, ownership or
mapping withholds the complete MD014 inventory, including earlier provisional
findings, with explicit reduced coverage:

> Shell-prompt context is unavailable; the complete MD014 inventory is withheld.

Known unselected fences and an empty language list do not require unrelated raw
context. A withheld inventory proves neither suppression use nor complete absence.

## Configuration

Default enablement: Enabled.

languages: string list, [sh, shell, bash, zsh, console].

A custom list replaces the defaults. An empty list selects no blocks and is a
complete empty analysis. Duplicates never multiply findings. Empty strings,
whitespace/control-containing strings and Unicode strings retain the shared
permissive string-list domain; configured elements are not trimmed or folded.
Missing or known-empty info never selects a fence, even if `""` is configured.
An element containing ASCII separators cannot equal a single nonempty token.
Wrong types, nulls and unknown options reject even when MD014 is disabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
```sh
$ pwd
```
````

Accepted input:

````markdown
```sh
pwd
```
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

This pass produces no MD014 edits, previews, corrected content or deferred edit
proposals. Findings always have `fix_available: false`. Catalog `PlannedFix`
metadata preserves future scope; it does not grant a current fixer. MD047 remains
the separate existing terminating-newline correction producer.

Any future prompt-prefix correction must satisfy the
[shared preservation contract](../index.md#implementation-contract), preserve
meaning and recheck the corrected document. It is not part of this analysis pass.

## Validation

Deterministic analysis fixtures cover the examples, every option, finite lexical
boundaries, protected content, nested containers, original LF/CRLF/CR/EOF mappings,
exact ranges, complete suppression/MD087 inventories and inactive/focused
inspection. Authority, interruption and final publication tests are separate
from literal grammar fixtures. Analysis leaves original bytes unchanged and
emits no corrections. CLI/project/standalone MCP parity remains the downstream
#196/#200/#206 reconciliation; this rule does not add a transport or reporter.
