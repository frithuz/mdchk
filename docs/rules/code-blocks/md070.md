# MD070: Outer fence length for nested examples

Status: planned for implementation.

Area: [Code blocks](index.md).

## Behavior

Require marker-only lines, an opening marker in parser-confirmed eligible comment context outside protected content, and a unique nonnested closing marker in the same surrounding container. Use a bounded source scan for the closing marker so a prematurely closed outer fence cannot decide the intended extent. Do not activate a start marker displayed inside code, frontmatter or other protected content. Multiple separate pairs are allowed; nested, missing or conflicting markers are not guessed.

Between a valid pair, the first and last nonblank lines must be the intended outer opening and closing fences, using the same character. The opener must identify Markdown through md or markdown language metadata recognized by the selected dialect. The last line must be a delimiter-only closer valid for the opener, not a guessed fence later in the document. Missing/invalid outer boundaries produce a located problem and no automatic correction.

Inspect only the declared example body, excluding the two outer delimiter lines. Count source-backed fenced-block opening/closing runs recognized within that Markdown payload by the selected dialect; ignore inline runs, escaped markers and non-fence code strings. Compare only runs using the outer fence character. Emit MD070 when an eligible inner run is at least as long as the outer opening fence.

Require the corrected region to parse as exactly one outer Markdown code block containing the declared body. Preserve content and reliable interpretation outside the region, and obey shared directive, reference and edit-safety checks. If safety cannot be established, retain the finding without applying a correction.

Markers supply MD070 source extents only; they do not change normal Markdown parsing, activate other rules, suppress other findings or grant a new directive mechanism. Any correction that would unexpectedly alter effective directives or protected bindings remains deferred. Unmarked ambiguous prematurely closed fences remain outside MD070 scope rather than being heuristically reconstructed.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

With MD070 explicitly enabled, violating input:

`````markdown
<!-- mdchk-example -->
```markdown
```python
print(1)
```
```
<!-- /mdchk-example -->
`````

Accepted correction (both outer fences lengthened together):

`````markdown
<!-- mdchk-example -->
````markdown
```python
print(1)
```
````
<!-- /mdchk-example -->
`````

Unmarked examples and inner runs of a different fence character are outside this
length comparison. Literal markers displayed inside code do not activate it.

## Correction policy

Set both intended outer delimiters to max(existing opener length, existing closer length, longest eligible same-character inner run + 1). Never shorten either delimiter. Preserve all example-body bytes, language/info/attributes, markers, line endings and container prefixes. Treat the pair as one atomic correction.

Follow the [shared correction contract](../../engineering/fixes.md).

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
