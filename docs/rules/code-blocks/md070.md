# MD070: Outer fence length for nested examples

Status: analysis and configuration implemented for CommonMark and GFM. Findings
are manual; automatic delimiter replacement remains planned.

Area: [Code blocks](index.md).

## Behavior

Require marker-only lines, an opening marker in parser-confirmed eligible comment context outside protected content, and a unique nonnested closing marker in the same surrounding container. Use a bounded source scan for the closing marker so a prematurely closed outer fence cannot decide the intended extent. Do not activate a start marker displayed inside code, frontmatter or other protected content. Multiple separate pairs are allowed; nested, missing or conflicting markers are not guessed.

The exact spellings are `<!-- mdchk-example -->` and
`<!-- /mdchk-example -->`. Only ASCII spaces and tabs may surround a complete
marker after actual ancestor prefixes. Escaped, multiline, case-variant,
prose-prefixed and adjacent-comment spellings do not activate an example.
Whole images and raw HTML also protect opening markers.

Pairing uses the actual surrounding container, so sibling list items cannot
share a pair. A close remains tentative until the next eligible opening or the
container end. Another same-container close invalidates that pair, even when
the original parser placed it inside code. An eligible opening before closure
makes a nested ambiguous group; balance that group without selecting inner
pairs. A protected opening does not nest a group. Thus open-close-open-close
contains two examples, while open-close-close and open-open-close-close contain
none. Known missing or ambiguous extents produce no finding; unknown necessary
ownership produces explicit reduced coverage.

Between a valid pair, the first and last nonblank lines must be the intended outer opening and closing fences, using the same character. The opener must identify Markdown through md or markdown language metadata recognized by the selected dialect. The last line must be a delimiter-only closer valid for the opener, not a guessed fence later in the document. Missing/invalid outer boundaries produce a located problem and no automatic correction.

The first decoded info token must be exactly lowercase `md` or `markdown`,
separated by ASCII spaces or tabs. Later info tokens are allowed. Entity and
escape decoding follows the real fence grammar; `MD` and `{.markdown}` are not
accepted language names. Both boundaries require fewer than four indentation
columns and at least three delimiters; the closer must be at least as wide as
the opener and have only trailing spaces or tabs.

Inspect only the declared example body, excluding the two outer delimiter lines. Count source-backed fenced-block opening/closing runs recognized within that Markdown payload by the selected dialect; ignore inline runs, escaped markers and non-fence code strings. Compare only runs using the outer fence character. Emit MD070 when an eligible inner run is at least as long as the outer opening fence.

The body uses the selected CommonMark or GFM grammar under the original cumulative
operation budget. Only real surrounding-container prefixes and ordinary outer
fence indentation are removed, retaining original provenance and residual tab
columns. Nested payload containers keep their own syntax. Frontmatter recognition
is disabled for this isolated code payload; recognized original document metadata
still protects activation. Raw HTML, whole images and opaque code interiors do
not contribute inner runs. An unclosed inner opening counts, and an inner closing
run may be wider than its opener. A wider outer closer does not raise the limit
established by the outer opener.

Each pair produces at most one finding, with this precedence:

1. `Expected an outer Markdown opening fence.`
2. `Outer example fence must use md or markdown language.`
3. `Expected a matching outer closing fence.`
4. `Outer Markdown fence must be longer than every matching inner fence.`

A length finding selects the complete original outer opening run. Missing
boundaries use a zero-width point immediately before the closing extent marker;
missing language uses the point after the opening run. Invalid language selects
the original first token, preserving atomic entity/escape spelling. Invalid
boundaries select their first offending token; excessive indentation selects its
complete intrinsic whitespace, a wrong/short closing run selects that run, and
an otherwise valid closing run with extra text selects the first suffix token.
All coordinates refer to original bytes and Unicode scalar columns, including
whole tab bytes.

Unknown necessary marker, container, info, raw-lifetime or payload context
withholds the whole MD070 inventory, including earlier provisional findings.
The coverage message is `Nested-example context is unavailable; the complete
MD070 inventory is withheld.` Recognition precedes focus and suppression, so a
hidden real finding counts as a used suppression for MD087.

Future correction must require the corrected region to parse as exactly one outer Markdown code block containing the declared body. Preserve content and reliable interpretation outside the region, and obey shared directive, reference and edit-safety checks. If safety cannot be established, retain the finding without applying a correction.

Markers supply MD070 source extents only; they do not change normal Markdown parsing, activate other rules, suppress other findings or grant a new directive mechanism. Any correction that would unexpectedly alter effective directives or protected bindings remains deferred. Unmarked ambiguous prematurely closed fences remain outside MD070 scope rather than being heuristically reconstructed.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings).
Markers alone do not enable this default-disabled rule. Allowed ordinary enable
directives can enable it; inherited permission restrictions remain in force.

## Examples

With MD070 explicitly enabled, violating input:

`````markdown
<!-- mdchk-example -->
```markdown
```python
print(1)
```
```
<!-- /mdchk-example -->
`````

Accepted correction (both outer fences lengthened together):

`````markdown
<!-- mdchk-example -->
````markdown
```python
print(1)
```
````
<!-- /mdchk-example -->
`````

Unmarked examples and inner runs of a different fence character are outside this
length comparison. Literal markers displayed inside code do not activate it.

## Correction policy

Automatic correction remains planned. Analysis produces no MD070 edits, previews,
corrected documents or deferred correction proposals. An independent safe MD047
prose-EOF correction can coexist with manual MD070 findings.

Set both intended outer delimiters to max(existing opener length, existing closer length, longest eligible same-character inner run + 1). Never shorten either delimiter. Preserve all example-body bytes, language/info/attributes, markers, line endings and container prefixes. Treat the pair as one atomic correction.

Follow the [shared correction contract](../../engineering/fixes.md).

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
