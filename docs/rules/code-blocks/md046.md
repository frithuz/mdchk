# MD046: Indented versus fenced code

Status: analysis and configuration implemented for CommonMark and GFM. Findings
are manual; automatic conversion remains planned.

Area: [Code blocks](index.md).

## Behavior

Require actual code blocks to use one configured representation. `consistent`
adopts the first eligible block's indented or fenced style across the whole
document, including nested lists and blockquotes. It does not reset at container
boundaries or switch to the most common style. Empty and unclosed fenced blocks
count; backtick and tilde fences are both fenced style, regardless of language.

The exemplar comes from the full original document before directive suppression
or inspection focus. A suppressed first block still establishes the style. Code
payload, inline code, recognized metadata, whole images, comments and actual raw
HTML regions cannot supply nested blocks or establish an exemplar. Text that
resembles code but belongs to a paragraph is not an indented code block.

Each mismatching block produces one finding. A fenced block's range is its full
opening fence, excluding indentation, language information and content. An
indented block's range is its first nonblank line's intrinsic indentation marker:
the original bytes consumed for four columns after container prefixes. Extra
indentation is content. A tab remains a whole original byte, even when it also
contributes to a container prefix or residual code indentation. Public columns
count Unicode code points, not visual tab stops.

Messages state the expected representation:

- `Code block should use fenced style.`
- `Code block should use indented style.`

Unknown necessary ownership, style or diagnostic mapping withholds the complete
MD046 inventory with explicit reduced coverage. Unused language or payload
mappings do not prevent a known representation decision. Matching fixed-style
blocks need no diagnostic mapping. In consistent mode, a complete inventory of
known identical styles proves there can be no mismatch under any subset of raw
exclusions; that clean result needs no raw or marker mapping. Unknown style
metadata disables this proof, and mixed styles require actual eligibility before
choosing the exemplar.

## Configuration

Default enablement: Enabled.

`style`: `consistent`, `fenced`, or `indented`; default `consistent`. Values are
case-sensitive and are not trimmed. An omitted rule or empty option mapping
preserves the enabled default. Invalid options are rejected even when disabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input in consistent mode:

````markdown
<4 SPACES>example

```text
other
```
````

The indented block establishes the style; the later opening fence is reported.
With `style: fenced`, the first block's four-space indentation is reported instead.

Accepted input:

````markdown
```text
example
```

```text
other
```
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>`
describe source characters rather than literal Markdown.

## Correction policy

Pass 1 emits no MD046 edits, corrected content, conversion previews or deferred
proposals. Planned correction metadata does not make a finding automatically
fixable. An independently safe MD047 newline correction may coexist with manual
MD046 findings on its candidate snapshot.

Future conversion must preserve content, container membership and language
metadata; otherwise report only. Any future correction must satisfy the
[shared preservation contract](../index.md#implementation-contract), recheck
remaining findings and verify a second pass makes no further changes.

## Validation

Deterministic original-source fixtures cover both representations, every style,
global exemplars, protected content, nested containers, atomic tabs, LF/CRLF/CR,
Unicode, EOF and precise ranges. Supplemental checks cover configuration,
suppression, inspection focus, unknown context, original authority and shared
interruption limits. Compiled CLI checks cover manual previews and unchanged
source/configuration state. MCP transport parity remains downstream.
