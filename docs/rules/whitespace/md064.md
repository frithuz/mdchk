# MD064: Repeated spaces in prose

Status: CommonMark and GFM analysis, configuration and automatic correction
implemented. Findings the shared edit query withholds stay manual.

Area: [Whitespace](index.md).

## Behavior

Report consecutive ASCII spaces between prose words. Exclude indentation, trailing whitespace, code, HTML attributes, metadata, and tables.

Prose is actual final Paragraph and Heading inline content, including nested
lists/quotes and ATX/Setext headings. Actual GFM tables are excluded; pipe-shaped
CommonMark paragraphs remain prose. Emphasis, strong, strike and visible link/image
labels are transparent for word witnesses, including whitespace-only Text children.
Destinations, titles, reference identifiers and removed definitions supply no words
or spaces. Empty labels, code, HTML tags/comments, breaks and block boundaries are
barriers. Ordinary Text inside nonraw tags remains eligible locally. Actual raw-tag
identities protect through their closer or EOF, including HTML comment tails;
image alternative text has isolated raw state. Later closer-line prose is eligible.

A word token is a maximal semantic sequence bounded by Unicode whitespace, Unicode
Cc controls or original NUL. It must contain a Unicode Letter, Number or Mark.
Attached punctuation is allowed; punctuation, emoji or format characters alone do
not supply a word. Cf (including ZWJ) is not implicitly a control. Existing entity
and escape semantics supply word evidence without synthesizing authored spaces:
`one  &#65;` qualifies; `one  &#32;` and `one&#32;&#32;two` do not.

Count one maximal contiguous original ASCII SPACE run on a physical line, wholly
owned by eligible exact Text contributions. Formatting permits flanks but never
joins spaces across markup or source gaps. Immediate TAB, NBSP, semantic whitespace
or controls prevent a directly adjacent word; indentation, continuation prefixes,
trailing spaces and hard-break markers are excluded. For length R greater than
maximum N, report only `[runStart+N, runEnd)`, retaining the first N spaces.
`One  two` at maximum 1 reports byte `[4,5)`, scalar columns `[5,6)`;
`One   two` reports `[4,6)`, or `[5,6)` with maximum 2. The full context precedes
START-based directive suppression and inspection slicing.

## Configuration

Default enablement: Enabled.

maximum: positive integer, 1.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
One  two
````

Accepted input:

````markdown
One two
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` deletes exactly each reported span `[runStart+N, runEnd)`, keeping the
first N spaces of the run: `One  two` becomes `One two`, and `One   two` becomes
`One  two` with maximum 2. Line endings, LF or CRLF, are kept. Spaces in code,
HTML, tables and the other excluded content are never reported, so they are never
touched. Headings are prose: `# One  two` becomes `# One two`, which also changes
the heading's anchor.

A finding is corrected only when its edit passes the shared interior edit query
and the checker proves the corrected document. The query withholds a finding
under a disable directive or protected context, and every finding in a document
that opens with an unrecognized `---` or `+++` block. Those findings stay
reported with `fix_available: false` and their bytes are left alone. The checker
recomputes the expected spans from the original parse, proves that only the
deleted ASCII spaces changed, and compares both parses: node kinds and order,
breaks, heading, list, table, code, link and reference-definition properties
must match, and Text values may differ only in the length of their space runs.

MD064 groups get a round of their own. Other rules' edits go first, and only an
MD047 final-newline edit that analysis already offers shares the MD064 round, so
a document with MD009, MD047 and MD064 findings converges in one `fix` run.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Remaining findings are reported after checking the corrected document again. The [MD064 correction design](../../engineering/fixes.md#md064-corrections) describes the producer and checker.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Correction tests cover maximum 1, 2 and 3, exact deleted spans and corrected bytes, LF and CRLF input, Unicode words, protected code, HTML, tables and directive regions, nested lists and block quotes, ATX and Setext headings, forged edits the checker rejects, `--dry-run` against saved mode, second-run idempotence, and composition with MD009 and MD047.
