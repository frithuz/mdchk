# MD013: Maximum line width

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Whitespace](index.md).

## Behavior

Report lines wider than the limit, counting Unicode code points and expanding tabs to four-column stops. Exempt code, tables, and indivisible URLs by default.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

length: positive integer, 80; code_blocks: boolean, false; tables: boolean, false; headings: boolean, true.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

With `MD013: {enabled: true, length: 80}`, violating input (81 columns):

````markdown
one one one one one one one one one one one one one one one one one one one one x
````

Accepted input:

````markdown
one one one one one one one one one one one one one one one one one one one xxxx
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Source width and findings

Measure each original physical line from column zero, including indentation,
list/quote prefixes, delimiters, escapes, entity spellings, destinations, titles,
reference definitions and trailing whitespace. This source-width rule explicitly
specializes the shared parsed-body, escaped-syntax and container-relative defaults.
LF, CRLF and lone CR endings do not count. Empty input has no content lines; a
terminal ending does not create another line. Actual whitespace-only EOF content
is measured.

Each original Unicode scalar counts one, including CJK, combining marks, emoji
components, variation selectors, ZWJ, BOM and NUL. A TAB advances to the next
physical four-column stop (`4 - width % 4`). This is neither rendered cell width
nor grapheme width; no normalization or semantic decoding changes measurement.
Diagnostic columns count original scalars, including a TAB as one column.

Report at most one finding per physical line, on exactly the first eligible
original scalar whose cumulative width exceeds `length`. Its whole UTF-8 byte
span is responsible, with an exclusive end. A crossing TAB is atomic. The message
is `Line exceeds maximum width.`. Protected/exempt scalars still occupy width but
cannot anchor a finding: continue to ordinary overflow later on the same line.
No suffix includes later protected content, and no zero-width finding is emitted.
`length: 1` and the host's largest positive integer are valid without threshold
sized storage or arithmetic on `length + 1`.

## Protected ownership and options

CodeSpan, InlineHTML and HTMLBlock protection uses actual source Content
contributions and owned literal delimiters/tails. Their coarse multiline envelopes
may contain ordinary enclosing prefixes; those pure prefix gaps remain eligible.
Any protected contribution sharing an original TAB protects that whole atomic TAB.
A prefix marker alone does not establish body ownership.

`code_blocks: false` additionally protects actual CodeBlock Content and genuine
intrinsic indentation. `true` admits those contributions. CodeSpan stays protected
in both modes. Actual fence opening/info and retained closing boundary source is
ordinary in both modes. Failed closers and unclosed payload follow actual retained
Content. Rolled-back trailing blank lines do not acquire code protection.

Actual semantic raw HTML regions remain protected through their matching actual
closer or EOF, including omitted whitespace. Confirmed enclosing prefix replay
subtracts only wholly consumed prefix scalars at original physical TAB phase;
residual raw-body TAB columns protect the whole TAB. Actual HTML comment tails
participate in source order. Image-alt tags cannot open or close outer raw state.
Only final actual prefix markers supply authority; an apparent quote after a BOM
in ordinary Text is not a prefix. Raw protection wins all option opt-ins.
Recognized YAML/TOML header envelopes, including BOM and endings, remain wholly
opaque without metadata decoding. Recognition off follows actual Markdown syntax;
incomplete recognized syntax produces affected coverage.

`tables: false` exempts entire physical rows of actual GFM Tables, including
prefixes, delimiter rows, source-backed excess cells and retained pipe-less rows.
`headings: false` exempts entire physical lines of actual ATX/Setext headings,
including prefixes, multiline content, underline, empty headings and padding.
These are deliberate whole-line category exceptions, unlike contribution-only
literal/code protection. Their true values admit those lines unless stronger
protection applies. Identical pipe source in CommonMark has no table exemption;
marker spelling inside code/raw/header source does not manufacture a category.

## Indivisible destinations

Only actual parser-owned Link/Image destinations, angle autolinks/email, bare GFM
links and every retained reference definition destination (including unused and
duplicate definitions) supply URL atoms. Synthetic reference uses supply no local
atom. Bare CommonMark URL-looking Text remains ordinary and can report; there is
no lexical fallback, general unbroken-word exemption, scheme whitelist, reparse,
renderer, resource resolution or network fetch.

An atom requires nonempty contiguous original source on one physical line and a
nonempty existing semantic destination. Both must be free of Go `unicode.IsSpace`
and `unicode.IsControl` scalars. This predicate governs indivisibility only, not
width or Markdown grammar. Existing semantic values are borrowed without another
decoder or percent unescape. Relative paths, fragments, email/mailto, ftp, xmpp
and all other actual destination classes can qualify. `%20` qualifies; `&#32;`
already decodes to semantic space and does not.

Expand an atom through its actual adjacent destination angle markers first, then
through actual link-open/link-close wrappers only at exact byte adjacency. Never
jump whitespace or titles. A title-separated closing parenthesis stays ordinary.
Labels, titles, trailing whitespace, parser-excluded punctuation and later prose
remain eligible. A long URL followed by ordinary overflowing punctuation can
therefore report that punctuation. Atom exemption changes eligibility only;
all original destination bytes still occupy physical width.

## Context and correction policy

Full original syntax, raw/URL context and width are established before directive
filtering at the chosen finding START or inspection line slicing. A later disable
cannot suppress an earlier chosen scalar. Permitted directives may enable an
explicitly disabled rule with its admitted options retained; inherited global and
per-rule denials remain binding. State resets per document.

Every MD013 finding is manual, with `fix_available: false`. MD013 produces no
edits, previews, writes or corrected content. Reflow can change layout and hard
breaks. MD047 remains the sole current correction producer; its candidate
reanalysis recomputes manual MD013 findings against the candidate snapshot.

## Validation

Reusable deterministic fixtures cover exact 81/80 examples, options/defaults,
Unicode/TAB geometry, mixed endings/EOF, contribution/prefix and raw ownership,
actual category boundaries, every destination origin, directives and metadata.
Direct controls cover original authority, shared accounting, cancellation,
deadlines, atomic publication, detached repeats and independent concurrency.
Production lint/fix dry-run/inspect preserve source and configuration bytes.
