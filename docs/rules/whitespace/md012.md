# MD012: Runs of empty lines

Status: CommonMark and GFM analysis and configuration implemented. Findings are
manual; automatic correction remains future work.

Area: [Whitespace](index.md).

## Behavior

Report one finding for each maximal physically consecutive run of blank body
lines exceeding `maximum`. A blank body is empty or contains only ASCII spaces
and tabs after that line's actual retained quote-prefix, item-prefix and
item-indent bytes. Empty list markers and quote-only lines can count. Task
checkboxes, NUL, Unicode whitespace, escapes, comments, definitions and unconsumed
marker-looking text remain content. Lazy lines acquire no invented prefix.
Container and item transitions do not reset or duplicate a run.

Actual code, CodeSpan, raw HTML, comments and recognized metadata are protected.
A protected or nonblank line breaks a run; protected gaps are never removed to
join neighboring blanks. Fenced payload is bounded by actual retained delimiter
lines; an unclosed fence uses its retained extent. Indented code protects interior
blanks but not parser-rolled-back trailing blanks. Semantic raw tag bodies include
omitted blank source through the actual closer or EOF, including HTML tails;
image-description tags cannot change enclosing raw state. Recognized YAML/TOML
headers are wholly opaque, including BOM and endings. Recognition off follows
the selected flavor; incomplete syntax produces reduced coverage.

Count leading and trailing actual physical blanks. Empty source has no lines;
a terminal LF, CRLF or CR creates no extra line. A real unterminated whitespace
EOF line counts. Preserve original mixed endings and byte/scalar coordinates.

At maximum M, select the first excess line after the first M eligible blanks.
Highlight only its remaining body bytes, excluding consumed prefixes, ending and
later excess lines. Empty bodies have present zero-width ranges: `One\n\n\nTwo\n`
reports [5,5), line 3 column 1; `a\n\n \t\nb\n` reports [3,5), line 3
columns 1..3. Actual consumed whole TAB bytes are excluded even when structural
columns are shared. The message is `Too many consecutive blank body lines.`.
Establish full original runs before directive START filtering or inspection
slicing: hidden earlier blanks still consume the maximum, and later enablement
cannot invent a suffix finding. Zero reports the first blank of each run;
MaxInt admits finite runs without threshold-sized work or storage.

## Configuration

Default enablement: Enabled.

maximum: nonnegative integer, 1.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
One


Two
````

Accepted input:

````markdown
One

Two
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Pass 1 supplies manual findings with `fix_available: false`, no edits, executable
previews, writes or returned corrected content. PlannedFix metadata grants no
correction authority; MD047 remains the sole executable correction. Future
removal must preserve block structure and list tightness.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
