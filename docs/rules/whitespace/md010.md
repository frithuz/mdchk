# MD010: Tab characters

Status: analysis and configuration implemented for CommonMark and GFM. Automatic
correction is implemented for TABs in inline paragraph, heading and table-cell
text.

Area: [Whitespace](index.md).

## Behavior

Report each original TAB byte separately, in source order, with message
`Tab character.`. Each range covers exactly one byte and one Unicode scalar
column, including adjacent TABs. Entities such as `&#9;` create no source TAB;
a preceding backslash does not exempt a TAB. Original Unicode/NUL positions and
LF, CRLF, CR and EOF boundaries are preserved.

At default `code_blocks: false`, protect actual code-block Content contributions
and genuine intrinsic code indentation. A TAB shared by code and a list/quote
prefix is indivisible: any actual code ownership protects the whole byte.
`code_blocks: true` admits those bytes once. Pure enclosing-prefix TABs remain
ordinary, including gaps inside coarse code envelopes. Actual fence opening,
info and retained closing-line TABs are ordinary; failed closers and unclosed
payload follow actual code ownership. Interior blank indentation is code only
when actually retained; rolled-back trailing blanks are ordinary.

Code spans remain protected under both option values. CodeSpan, InlineHTML and
HTMLBlock protection uses actual source contributions and owned delimiters/tails,
leaving pure container-prefix gaps ordinary. HTMLBlock terminating-line tails
remain literal. Whole independently recognized YAML/TOML headers, including BOM
and delimiter TABs, are protected; disabled recognition follows actual Markdown.
Unterminated recognized headers produce explicit incomplete coverage.

Actual private raw-tag boundaries for script/style/pre/textarea protect original
body TABs through their real matching closer or EOF, including whitespace trimmed
from Paragraph/Heading/Text Content and code/fence boundary TABs. Only TABs wholly
consumed by actual enclosing list/quote prefixes remain ordinary. A shared TAB
with any residual body column stays protected, even if the body whitespace was
trimmed. Prefix consumption preserves original physical four-column tab phase;
empty first-list prefixes use their complete actual consumption. Tags in image
descriptions cannot start or end outer raw state. The actual closer releases
following bytes; there is no whole inline closing-line exemption.

Original-source TABs in links, destinations, titles, reference definitions,
table trimming and task separators receive no blanket exemption. All protection
is established before directive START filtering or inspection line slicing.

## Configuration

Default enablement: Enabled.

code_blocks: boolean, false; spaces_per_tab: positive integer, 4.

`spaces_per_tab` has no effect on finding count, ranges, message or parser tab
stops. Values 1, 4 and maximum admitted int produce identical findings; no
allocation or loop depends on that numeric value. It sets the number of spaces a
correction writes, and a value above 8 withholds every correction.
Unknown settings, nulls, wrong types and nonpositive integers fail even while
the rule is disabled. Empty mappings preserve defaults; shared directive
permissions and inherited denials apply.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
Text<TAB>continued
````

Accepted input:

````markdown
Text continued
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` replaces a TAB with exactly `spaces_per_tab` ASCII spaces, with no
tab-stop alignment, only when every condition holds:

- MD010 reports the TAB in the current round, outside any region where a
  directive disables MD010.
- The TAB is in the exact inline Text of a paragraph, an ATX or setext heading or
  a GFM table cell, including such text inside list items and block quotes and
  in link text.
- A non-whitespace byte of the same block comes before it on its line, and one
  comes after it: TABs in line-end whitespace stay with MD009, since spaces there
  could form a hard break.

Each TAB is its own atomic group, `MD010-byte-<offset>`, whose span is exactly
the one-byte finding range. Adjacent TABs are separate groups. Line endings and
the Unicode around a TAB are kept byte for byte.

Every other finding stays manual (`fix_available: false`) and gets no edit:
leading indentation, list, quote and container prefixes, code (including bytes
admitted by `code_blocks: true`), code spans, inline and block HTML, raw-tag
bodies, front matter, link destinations and titles, reference definitions, table
delimiter rows, cell-trimming whitespace, image descriptions and line-end
whitespace.

A TAB in inline text gets a zero-edit group with reason `expansion-limit` when
`spaces_per_tab` exceeds 8 (`parser.MaxTabSpaces`), so the file cannot grow
without bound from one configuration value. The checker recomputes every edit
from the original parse and accepts the round only if the reparse keeps the same
node kinds, order and heading, list, table, code, link and reference-definition
properties, with Text differing only where a TAB became spaces; otherwise the
group is deferred with `meaning-not-preserved`.

MD010 corrections take a round of their own. They wait for a round with no other
edit, MD009 and MD047 included, and every other edit waits for them, so a run
with trailing whitespace or a missing final newline settles in later rounds of
the same `fix`.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
