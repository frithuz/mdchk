# MD085: Indented paragraph continuation lines

Status: analysis and configuration implemented for CommonMark and GFM. Automatic
correction is implemented: `fix` deletes the reported surplus indentation when
the line stays a paragraph continuation.

Area: [Whitespace](index.md).

## Behavior

Report additional indentation on continuation lines of a parsed prose paragraph relative to its first line's content column. Exclude containers, code, and hard-break continuation layouts.

Only actual final Paragraph owners qualify. Exclude an entire paragraph under
any blockquote, list or list-item ancestor, including lazy continuation lines.
This is an exception to the shared container-relative spacing default. Headings,
tables, code, HTML blocks and removed reference definitions supply no baseline.

The first physical line contributing nonempty actual Paragraph content fixes the
baseline, including opening inline markup or code. Measure only original leading
ASCII SPACE/TAB indentation; tabs advance to four-column physical stops. Other
bytes stop indentation. Later lines never reset the baseline, including after a
hard break, directive or inspection selection.

A continuation needs ordinary nonblank Text on that physical line, including
visible formatting and link/image labels. Unicode whitespace, Cc controls and
original NUL do not witness prose; punctuation, literal U+FFFD and otherwise
eligible Cf scalars do. Code, HTML/comment bytes and semantic raw payload do not.
A prefix already inside a multiline protected owner remains exempt even if its
closer has later ordinary Text on the same line. Newly opening ordinary inline
HTML, or inline code followed by ordinary Text, can qualify. Actual raw tag state
continues across paragraphs and HTML tails; image alternative state is isolated.

Only the immediate physical successor of an actual unprotected prose HardBreak
is exempt. Spaces and backslash origins qualify; SoftBreak and protected spelling
do not. The fixed baseline survives this exemption. CRLF is one atomic ending.

Report one smallest surplus-only SPACE/TAB suffix per eligible line. Retain
complete indentation scalars ending within the baseline; include a crossing TAB
whole. Public columns count original Unicode scalars, with a TAB counting as one.
No trailing-space, line-ending or virtual EOF range is reported. Findings use
`Additional indentation on paragraph continuation.`

Full original context precedes directive filtering at the chosen range start and
inspection slicing. Recognized opaque YAML/TOML headers need no metadata decoding;
unreliable required syntax produces incomplete coverage.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
A paragraph
  continues here.
````

Accepted input:

````markdown
A paragraph
continues here.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` deletes exactly the reported SPACE/TAB suffix, including a crossing TAB
whole, only when every condition holds:

- MD085 reports the line in the current round, outside any region where a
  directive disables MD085.
- The document does not open with an unrecognized block.
- Without the suffix, the line stays a paragraph continuation: it does not start
  a list, block quote, heading, fence, thematic break or HTML block, and does not
  become a setext underline or table delimiter row.

Each line is its own atomic group, `MD085-byte-<offset>`, whose span is exactly
the finding range and whose replacement is empty. The rest of the line, its
ending and the Unicode around it are kept byte for byte, so
`a<NEWLINE><SPACE><TAB>b<NEWLINE>` becomes `a<NEWLINE>b<NEWLINE>` and CRLF stays
CRLF.

A finding that fails a condition stays reported with `fix_available: false` and
gets no edit. The checker recomputes every edit from the original parse and
accepts the round only if the reparse keeps the same node kinds, order,
properties and visible text; otherwise the group is deferred with
`meaning-not-preserved`. Protected content, incomplete parses, conflicts and
disabled intervals defer through the shared validation.

MD085 corrections share their round with MD009 and MD047, so
`a<SPACE><NEWLINE><SPACE><SPACE>b<EOF>` becomes `a<NEWLINE>b<NEWLINE>` in one
`fix`. They wait for heading and list corrections that compare whole parses,
and MD012, MD010, MD027 and MD064 wait for them.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning, deferral where the structure would change or a directive disables the rule, composition with MD009 and MD047, and a second fix run with no further changes.
