# MD009: Whitespace at line ends

Status: planned for implementation.

Area: [Whitespace](index.md).

## Behavior

Let N be `hard_break_spaces`, an exact count, not a minimum. Lines without trailing whitespace pass in both modes. Exactly N ASCII spaces are allowed with `strict: false`, including at EOF; with `strict: true` they are allowed only for a parser-confirmed hard break. Every other positive space count, trailing tab, or mixed space/tab suffix is reported.

Report whitespace-only lines in both strict modes; there is no hard-break allowance for them. Preserve any parser-owned structural indentation or container prefix when correcting.

By default, code is excluded. With code_blocks=true, report trailing spaces or tabs in literal code without applying a Markdown hard-break allowance. Keep literal-code findings report-only; code_blocks opts into analysis, not modification of code bytes.

Frontmatter, raw payloads and other protected regions retain their established protections; parser certainty remains required for automatic corrections.

MD009 treats only ASCII spaces and tabs as trailing whitespace. Other Unicode spacing characters remain content and are not stripped by this rule.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Enabled.

hard_break_spaces: integer at least 2, 2; strict: boolean, false; code_blocks: boolean, false. Strict mode rejects trailing spaces that do not produce a hard break.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
Text<SPACE>
````

Accepted input:

````markdown
Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

For flagged whitespace that currently produces a real hard break, normalize to exactly N ASCII spaces. For other flagged trailing whitespace, remove it only after reparsing confirms preserved interpretation. Never introduce or remove a hard break or change container structure as a side effect. Already permitted whitespace is left alone. Preserve source newline conventions.

Follow the [shared correction contract](../../engineering/fixes.md).

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
