# MD047: Exactly one terminating newline

Status: CommonMark and GFM analysis, configuration, safe previews and native application implemented. Apply requires Darwin arm64+cgo/local APFS; other native adapters refuse writes with `13`. Protected and task-adopting EOF contexts remain manual as described below.

Area: [Whitespace](index.md).

## Behavior

Require a nonempty file to end with exactly one physical line-ending sequence:
LF, CRLF, or lone CR. A CRLF pair counts as one sequence, including in mixed
ending input. Only a zero-byte file is exempt; blank-only files are nonempty.
Spaces and tabs are content and are never trimmed: `text<NEWLINE><SPACE><NEWLINE>`
passes, while `text<NEWLINE><SPACE><EOF>` lacks a terminal ending.

This is a whole-file byte-boundary check, including code, raw HTML, comments,
and nested containers. The general parsed-body/protected-content exclusions do
not exempt these endings. Analysis uses the original source and physical line
index; it does not infer newline spelling from normalized parser text.

A missing ending is reported at the zero-width EOF insertion point. For a run
of two or more adjacent terminal endings, retain the first complete sequence and
report only the excess suffix through EOF. For example, `x\r\n\r\n` has
byte range `[3,5)`, and `x\r\n\n` has `[3,4)`. This also applies to
all-ending files: `\r\n\n` reports `[2,3)`. Suppression uses that original
finding start, which is EOF for missing material and the excess suffix start
for surplus material. No source bytes or edits are produced by analysis.

## Examples

Violating input:

````markdown
Text<EOF>
````

Accepted input:

````markdown
Text<NEWLINE>
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix --dry-run` proposes a missing terminator or removes only the minimal excess
suffix. Missing endings use the nearest original complete LF, CRLF or lone CR,
with the preceding sequence winning ties and LF used when none exists. At EOF
this is the last existing terminator. Every unrelated ending, space and tab stays
byte-identical. Empty files remain exempt.

`fix_available` is true only with complete reliable syntax, shared directive
permission for the original anchor and entire edit, and affirmative protection
assessment. Code, HTML and comment envelopes touching the EOF edit conservatively
remain report-only. A closed fence followed by surplus blank endings can be
corrected when its complete envelope is unchanged. Source-only analysis still
reports findings when syntax is unavailable, with false eligibility. In GFM,
a literal task spelling without a separator at EOF, such as `- [x]`, `- [ ]`
or `> - [X]`, must also remain manual: a new ending would supply the separator
and remove the visible marker text in favor of task syntax. This includes
multiline markers and container gaps recognized by the actual parser. Choose
the intended text or task meaning before editing; fix does not escape or rewrite
the marker. Existing tasks with a real separator and ordinary prose remain
eligible when the other requirements hold. CommonMark retains its core meaning.

Lint and inspect assess GFM insertion eligibility by parsing a prospective ending
on the same residual operation budget, without constructing a correction group.

The production proposal passes common planning, independent exact suffix proof,
mapped protected payload/binding and directive checks, and full reanalysis. The
independent suffix proof compares task classification, original marker/token
spelling and visible paragraph contributions from both actual round parses;
an advertised eligibility flag cannot authorize a task-adopting candidate.
A completed safety deferral leaves the finding manual; it does not itself make
analysis incomplete. With `--dry-run`, candidate diffs and remaining findings
describe predicted content, and no target bytes are written. Apply reports observed
saved content through the verified Darwin arm64+cgo/local APFS adapter; other
native adapters refuse writes.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.
