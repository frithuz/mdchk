# MD047: Exactly one terminating newline

Status: analysis and configuration implemented for CommonMark. Automatic correction remains planned.

Area: [Whitespace](index.md).

## Behavior

Require a nonempty file to end with exactly one physical line-ending sequence:
LF, CRLF, or lone CR. A CRLF pair counts as one sequence, including in mixed
ending input. Only a zero-byte file is exempt; blank-only files are nonempty.
Spaces and tabs are content and are never trimmed: `text<NEWLINE><SPACE><NEWLINE>`
passes, while `text<NEWLINE><SPACE><EOF>` lacks a terminal ending.

This is a whole-file byte-boundary check, including code, raw HTML, comments,
and nested containers. The general parsed-body/protected-content exclusions do
not exempt these endings. Analysis uses the original source and physical line
index; it does not infer newline spelling from normalized parser text.

A missing ending is reported at the zero-width EOF insertion point. For a run
of two or more adjacent terminal endings, retain the first complete sequence and
report only the excess suffix through EOF. For example, `x\r\n\r\n` has
byte range `[3,5)`, and `x\r\n\n` has `[3,4)`. This also applies to
all-ending files: `\r\n\n` reports `[2,3)`. Suppression uses that original
finding start, which is EOF for missing material and the excess suffix start
for surplus material. No source bytes or edits are produced by analysis.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). These defaults are implemented.

## Examples

Violating input:

````markdown
Text<EOF>
````

Accepted input:

````markdown
Text<NEWLINE>
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

The following policy is deferred to the correction pass; current diagnostics
have `fix_available: false` and do not produce proposals or corrected content.

Add or remove terminating newlines using the file's established LF or CRLF convention.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
