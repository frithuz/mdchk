# MD028: Empty lines separating blockquotes

Status: CommonMark and GFM analysis and configuration implemented; manual findings.

Area: [Whitespace](index.md).

## Behavior

Report each ordinary blank physical line between consecutive actual blockquote
siblings with the same direct Document, BlockQuote or ListItem parent. The entire
gap must contain only ASCII SPACE/TAB body bytes after actual retained ancestor
quote/item prefixes. Removed reference definitions, comments and any other
intervening content break adjacency. Distinct items and ancestor quotes cannot
pair their descendants. A completely missing ancestor prefix reports only the
actual outer pair, without duplicate inner findings.

Quote child kinds do not limit eligibility: empty, heading, code, table and HTML
quotations all participate. Quote-like text inside protected syntax supplies no
quote witness. Actual literal, semantic raw-body and opaque header ownership
protects gaps, including raw tags spanning two real quotes. Image-alt tags cannot
change enclosing raw state. Recognized YAML/TOML/BOM headers remain opaque;
recognition off uses actual Markdown and incomplete context reduces coverage.

Each finding says `Blank line separates adjacent blockquotes.` and selects the
remaining original blank body after all actual retained ancestor prefixes,
excluding LF, CRLF or CR. An empty body has a present zero-width range after the
atomic prefix, or at physical line start. A prefix-owned TAB is excluded whole,
even when it also represents residual logical indentation; `item-blank` includes
the ending and is never a prefix boundary. No virtual EOF blank is introduced.
Full original pair and protection context precedes finding-START directive
suppression and inspection slicing.

## Configuration

Default enablement: Enabled.

No rule-specific options.

## Examples

Violating input:

````markdown
> One

> Two
````

Accepted input:

````markdown
> One
>
> Two
````

`> One\n\n> Two` reports [6,6), line 2 column 1. Two blank lines
report separately. `>> One\n>\n>> Two` reports [8,8), line 2
column 2, while `>> One\n>\t\n>> Two` reports [9,9), column 3,
after the complete retained TAB. `>> One\n\n>> Two` reports once
at [7,7), for the actual outer pair.

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; joining quotes changes whether they are one quotation. MD028 has
NoFix metadata and supplies no edits, previews or returned content. MD047 remains
the sole correction provider and its separately identified candidates receive
fresh manual MD028 analysis.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Verify manual findings, exact remaining-body ranges and unchanged bytes; no MD028 correction or fix idempotence is claimed.
