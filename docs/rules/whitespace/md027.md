# MD027: Whitespace after blockquote markers

Status: analysis and configuration implemented for CommonMark and GFM. Findings are manual.

Area: [Whitespace](index.md).

## Behavior

Report more than one ASCII separator SPACE after an actual blockquote marker
before a physical contribution of a final ordinary Paragraph. Report exactly the
excess spaces after retaining the first SPACE, with message
`Extra spaces after blockquote marker.`. For `>  Text`, the original byte range
is `[2,3)`, public line 1 columns 3 through 4 (exclusive end).

Only the actual innermost prose-facing marker on each physical line qualifies.
Spacing consumed by intervening quote/list/item prefixes, pre-marker indentation
and list indentation is excluded. A quote inside a list can qualify. Lazy lines
have no invented marker, but a real outer marker can face a lazily continued inner
paragraph: `> > Text<LF>>  lazy` reports the second line's excess SPACE.

The entire maximal consecutive ASCII SPACE/TAB separator immediately after `>`
must contain no TAB. Any TAB, including a mixed or shared residual TAB, exempts
that separator. No expansion or tab-width option applies. NUL and non-ASCII source scalars such as NBSP are content, not separator whitespace. Zero or one SPACE
is accepted; there is no minimum-space requirement.

Final syntax ownership decides prose. Headings (including promoted Setext text
and underline), GFM table structure, removed reference definitions, thematic
breaks, actual code blocks and fence boundaries, HTML blocks, blank/marker-only
bodies and recognized opaque headers do not qualify. CommonMark pipe text that
remains a Paragraph does qualify. `>     Text` is indented code and exempt;
`> a<LF>>     Text` is a Paragraph continuation and reports bytes `[6,10)`.

New inline CodeSpan (even code-only paragraphs), emphasis, strike, link and image
syntax keep an external paragraph separator eligible. A contribution containing
only InlineHTML/comments and ASCII whitespace/breaks has no prose; a new inline
tag with ordinary paragraph text can qualify. Contributions beginning inside an
already-open multiline CodeSpan, InlineHTML/comment or semantic raw HTML body
remain protected, including a line with ordinary text after its closer. Actual
raw tags, source order, HTML comment tails and isolated image descriptions decide
raw ownership through the matching actual close or EOF. Literal payload is never
rescanned for markers. Recognized YAML/TOML/BOM headers are opaque, without metadata
decoding; recognition off follows actual Markdown, and incomplete parsing reduces
coverage.

Full original ownership and protection precede directive filtering and inspection
slicing. The excess range's original START controls suppression; a same-line
comment after it cannot retroactively suppress the finding.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). Empty mappings retain defaults. Unknown options and invalid shared values are rejected even when disabled.

## Examples

Violating input:

````markdown
>  Text
````

Accepted input:

````markdown
> Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Automatic corrections are deferred. Every current finding has
`fix_available: false`; MD027 produces no edits, previews or returned content.
Its PlannedFix catalog metadata is not executable correction authority. MD047
remains the first and sole production correction provider and recomputes manual
MD027 evidence against its separately identified candidate.

A future correction may reduce spacing only if block structure and content are preserved.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Future corrections require preserved meaning and a second fix run with no further changes. Current fixtures verify exact original excess ranges, both flavors, CR endings, Unicode, actual nested/lazy ownership, protected continuation, shared settings and manual output.
