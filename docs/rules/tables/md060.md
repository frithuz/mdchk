# MD060: Table column layout

Status: analysis and configuration implemented for GFM.

Area: [Tables](index.md).

## Behavior

Require table padding to match the selected layout. Aligned pads each column to its widest cell or delimiter; compact uses one space on either side of cell text; tight uses none. Measure width in Unicode code points.

Use the selected dialect's parser-owned separator positions and original cell spans. Do not split normalized inline text to locate cells. In GFM, a content pipe must be escaped even inside a code span.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

mdchk checks every row the GFM parser places in a table: the header row, the
delimiter row and each body row, including tables inside block quotes and list
items. The rule reads the cell boundaries the parser recorded for each row and
never rescans the text for pipes. Pipe text in fenced or indented code, HTML
blocks, paragraphs without a valid delimiter row, and lines the parser does not
make table rows is never checked. Under `flavor: commonmark` there are no pipe
tables, so the rule does not apply and reports neither findings nor coverage.

Each source cell has a field, its text and its padding:

- The field is the source between the cell's two pipes. For a first cell
  without a leading pipe it starts at the row's first character, after any
  container prefix and indentation; for a last cell without a trailing pipe it
  ends at the row's last character, before trailing spaces or tabs.
- The text is the field without its leading and trailing spaces and tabs. Its
  width is the number of Unicode code points as written, so an escaped `\|`
  counts 2 and `é` or `中` counts 1. A delimiter cell's text is its colon and
  dash run.
- The padding is the spaces and tabs between the field edge and the text. A
  side without a pipe has no padding. An empty cell has no text; it always has a
  pipe on both sides.

The column width W is the widest text in that column across the header,
delimiter and body rows of one table, so each table is measured on its own.
Cells past the table's width form their own columns. Cells the parser adds to
a short row have no source and are never measured or reported.

Each style checks every cell, on every side that has a pipe:

- `tight`: no padding. An empty cell must be `||`.
- `compact`: exactly one space. An empty cell must be one space.
- `aligned`: spaces only, and
  - a cell with a pipe on both sides has at least one space on each side and a
    field of exactly W + 2 code points, so left-, right- and center-placed text
    all pass;
  - a first cell without a leading pipe has at least one space before its pipe
    and a field of exactly W + 1 code points;
  - a last cell without a trailing pipe has exactly one space after its pipe,
    and no width requirement;
  - an empty cell is exactly W + 2 spaces.
- A tab in padding is a finding in every style. A cell with no pipe on either
  side has no padding to check.

Each violating cell produces one finding over its field, with rows in document
order and cells left to right. An empty `||` field is a zero-width position
between its pipes. A range never includes a line ending, so a CRLF is never
split. Coordinates use original bytes and Unicode scalar columns.

The three messages are:

- `Cell padding does not match the aligned style; column width is <W>.`
- `Cell padding does not match the compact style.`
- `Cell padding does not match the tight style.`

Findings are manual and report-only: `fix_available` is false and `fix` makes
no changes. A real suppressed finding counts as used for MD087. When the
parser's table, row or cell facts are unavailable, the whole inventory is
withheld instead of guessed, with the coverage message
`Table row context is unavailable; the complete MD060 inventory is withheld.`
Corrections are future work; the correction policy below is their contract.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

style: aligned, compact, or tight; default aligned.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
| A| B |
|---|---|
|1|2|
````

Accepted input:

````markdown
| A   | B   |
| --- | --- |
| 1   | 2   |
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Adjust padding only; preserve cell text, alignment colons, escapes, and inline code. Preserve original row cell counts and all excess source cells; do not materialize padded cells or discard cells omitted from rendered output. Reparse the candidate to verify preserved table structure and meaning, and leave a correction unapplied when those properties cannot be established.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.

Include escaped and unescaped pipes inside code spans, unequal body-row widths, and multibyte cell text. Verify source-based width measurement and preservation of content omitted from rendered output.
