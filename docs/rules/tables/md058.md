# MD058: Blank lines around tables

Status: analysis and configuration implemented for GFM. Corrections remain deferred.

Area: [Tables](index.md).

## Behavior

Require a blank body line around a parsed table except at document or container boundaries.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

mdchk checks every table the GFM parser builds, including tables inside block
quotes and list items. Pipe text in fenced or indented code, HTML blocks and
paragraphs the parser does not turn into a table is never a target; MD075
covers rows the parser leaves out. A table under an open raw HTML lifetime is
not a target either. Under `flavor: commonmark` there are no pipe tables, so the
rule does not apply and reports neither findings nor coverage.

The table's immediate Document, BlockQuote or ListItem body supplies the
neighbours; a List only groups items. Only the line directly before the
table's first line and the line directly after its last line count. Retained
link reference definitions are neighbours in source order, so a definition
directly before a table is a violation. The first and last participant of a
body have their outward side exempt, which covers document starts and ends and
the edges of block quotes and list items. A recognized frontmatter header is
outside the root body.

A line is blank when it is empty, or holds only ASCII SPACE and TAB, after the
prefixes of the owning body and its ancestors are removed. A prefix-only `>`
line in a block quote is therefore a blank body line.

Each missing side produces one manual finding. The exact messages are
`Table requires a blank body line before it.` and
`Table requires a blank body line after it.` Both are zero-width points on the
table's own lines, matching MD031 and MD065. The before point is at the start
of the table's first line, after any container prefixes and before the row's
own indentation. The after point is at the physical content end of the table's
last line, after any trailing SPACE or TAB and before the whole LF, CRLF or CR
ending. For `# Title\n| a |\n| - |\n# Next\n`, they are [8,8) at (2,1) and
[19,19) at (3,6).

Directives and inspection line filters apply at each point's own start. A real
suppressed finding counts as used for MD087. Any budget exhaustion,
cancellation or model error withholds the whole MD058 inventory; unreliable
required syntax produces reduced coverage. Findings are report-only:
`fix_available` is false, and `lint`, `inspect` and `fix` emit no edits,
previews or changed bytes for MD058.

Pandoc table captions and attributes are not part of the table extent. They wait
for a Pandoc flavor.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). Unknown options and invalid shared settings are rejected even when disabled. Omitted settings and an empty mapping use defaults; null is invalid.

## Examples

Violating input:

````markdown
# Heading
A | B
--- | ---
````

Accepted input:

````markdown
# Heading

A | B
--- | ---
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Future work: insert blank lines while preserving enclosing container prefixes. The current analysis implementation is report-only; PlannedFix metadata grants no correction authority.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
