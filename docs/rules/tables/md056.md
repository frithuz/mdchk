# MD056: Mismatched cell counts

Status: analysis and configuration implemented for GFM.

Area: [Tables](index.md).

## Behavior

Report a body row whose original parsed cell count differs from its table's width. Count source cells before rendering pads missing cells or drops excess cells. Use the selected dialect's parsed separator positions: in GFM, escaped pipes are cell content, but an unescaped pipe splits cells even between backticks.

GFM requires equal header and delimiter cell counts to recognize a table. When those counts differ, there is no parsed table for MD056 to check; [MD075](md075.md) handles the source if it meets that rule's pipe-row candidate criteria.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

mdchk checks every body row the GFM parser places in a table, including tables
inside block quotes and list items. The rule reads the source cell count the
parser recorded for each row and the table's width, and never rescans the text.
Header and delimiter rows are never reported. Pipe text in fenced or indented
code, HTML blocks, paragraphs without a valid delimiter row, and lines the
parser does not make table rows is never checked. Under `flavor: commonmark`
there are no pipe tables, so the rule does not apply and reports neither
findings nor coverage.

Each body row with fewer or more source cells than its table's width produces
one finding, with rows in document order. The finding covers the row from its
first character after any container prefix and indentation to its last
character, before any trailing spaces or tabs and before the line ending, so a
CRLF is never split. Coordinates use original bytes and Unicode scalar columns.

The message is `Row has <n> cells; table has <w> columns.`, with the singular
`cell` or `column` when the count is 1, for example
`Row has 1 cell; table has 2 columns.`

Findings are manual and report-only: `fix_available` is false and `fix` makes
no changes. A real suppressed finding counts as used for MD087. When the
parser's table or row facts are unavailable, the whole inventory is withheld
instead of guessed, with the coverage message
`Table row context is unavailable; the complete MD056 inventory is withheld.`

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
A | B
--- | ---
1 | 2 | 3
````

Accepted input:

````markdown
A | B
--- | ---
1 | 2
````

In GFM, the following body row has three source cells and violates the two-column width, even though the excess cell is omitted from rendered output:

````markdown
| A | B |
| --- | --- |
| `a|b` | c |
````

Escaping the content pipe produces two cells and preserves the code span:

````markdown
| A | B |
| --- | --- |
| `a\|b` | c |
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; inventing or deleting cells changes content.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.

Cover both short and long body rows, escaped and unescaped code-span pipes, and GFM header/delimiter mismatches that remain outside MD056. Assert counts and diagnostic spans against original source cells, including cells omitted from rendered output.
