# MD056: Mismatched cell counts

Status: planned for implementation.

Area: [Tables](index.md).

## Behavior

Report a body row whose original parsed cell count differs from its table's width. Count source cells before rendering pads missing cells or drops excess cells. Use the selected dialect's parsed separator positions: in GFM, escaped pipes are cell content, but an unescaped pipe splits cells even between backticks.

GFM requires equal header and delimiter cell counts to recognize a table. When those counts differ, there is no parsed table for MD056 to check; [MD075](md075.md) handles the source if it meets that rule's pipe-row candidate criteria.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

Pandoc permits unequal header and delimiter counts and derives table width from the delimiter row. Check the original header count as well as body counts against that width, before padding or truncation. A recognized Pandoc header mismatch belongs to MD056, not MD075. Use the [Pandoc contract](../../engineering/pandoc-compatibility.md) scanner, including protected inline pipes, single-dash delimiters, and orgtbl-style `+` separators.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
A | B
--- | ---
1 | 2 | 3
````

Accepted input:

````markdown
A | B
--- | ---
1 | 2
````

In GFM, the following body row has three source cells and violates the two-column width, even though the excess cell is omitted from rendered output:

````markdown
| A | B |
| --- | --- |
| `a|b` | c |
````

Escaping the content pipe produces two cells and preserves the code span:

````markdown
| A | B |
| --- | --- |
| `a\|b` | c |
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; inventing or deleting cells changes content.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.

Cover both short and long body rows, escaped and unescaped code-span pipes, and GFM header/delimiter mismatches that remain outside MD056. Cover recognized Pandoc header mismatches within MD056, including short and long source headers. Assert counts and diagnostic spans against original source cells, including cells omitted from rendered output.
