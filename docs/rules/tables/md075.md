# MD075: Pipe rows without a table header

Status: planned for implementation.

Area: [Tables](index.md).

## Behavior

Report sequences of pipe-row candidates without a header and delimiter pair, or pipe rows adjacent to but outside a parsed table. Exclude code and ordinary prose containing an incidental pipe.

Apply the selected dialect's table-recognition rules. In GFM, unequal header and delimiter cell counts prevent table recognition; check those rows here when they meet the candidate criteria, rather than creating a table for [MD056](md056.md). Short or long body rows in an otherwise recognized GFM table belong to MD056.

Require at least two consecutive pipe-row candidates in one container, or a candidate row immediately adjacent to but outside a parsed table. A run has clear row structure when its rows have matching cell counts of at least two, or all rows have both outer pipes, or it contains a dialect-valid delimiter-shaped row adjacent to a pipe row. Single unconnected prose pipes are excluded. Use dialect-owned structural pipes, escaping, protected inline spans and separator classification. Rows already inside a parsed table belong to MD056 rather than MD075; do not manufacture a table from malformed rows.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
A | B
1 | 2
````

A GFM header/delimiter mismatch also leaves a sequence of pipe-row candidates outside a parsed table:

````markdown
| A | B |
| --- |
| 1 |
````

Accepted input:

````markdown
A | B
--- | ---
1 | 2
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; choosing a header or attaching rows requires author intent.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.

Cover GFM header/delimiter count mismatches, incidental prose pipes, protected content, and short or long rows that remain inside a valid table. Verify that MD075 and MD056 use the same parser classification without duplicating findings for a parsed body row.
