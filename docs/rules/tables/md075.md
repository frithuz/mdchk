# MD075: Pipe rows without a table header

Status: analysis and configuration implemented for GFM.

Area: [Tables](index.md).

## Behavior

Report sequences of pipe-row candidates without a header and delimiter pair, or pipe rows adjacent to but outside a parsed table. Exclude code and ordinary prose containing an incidental pipe.

Apply the selected dialect's table-recognition rules. In GFM, unequal header and delimiter cell counts prevent table recognition; check those rows here when they meet the candidate criteria, rather than creating a table for [MD056](md056.md). Short or long body rows in an otherwise recognized GFM table belong to MD056.

Require at least two consecutive pipe-row candidates in one container, or a candidate row immediately adjacent to but outside a parsed table. A run has clear row structure when its rows have matching cell counts of at least two, or all rows have both outer pipes, or it contains a dialect-valid delimiter-shaped row adjacent to a pipe row. Single unconnected prose pipes are excluded. Use dialect-owned structural pipes, escaping, protected inline spans and separator classification. Rows already inside a parsed table belong to MD056 rather than MD075; do not manufacture a table from malformed rows.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

mdchk checks every physical line of every paragraph, including paragraphs
inside block quotes and list items. A line is a pipe-row candidate when it has
at least one structural pipe, classified exactly as the GFM table parser
classifies a row: a pipe after an odd run of backslashes is escaped content, a
pipe after an even run is structural, and a pipe inside a code span is still
structural. Each candidate keeps its source cell count, whether it has a
leading and a trailing pipe, and whether it is delimiter-shaped: every cell
matches `:?-+:?` and the line starts with `|`, `:` or `-`. Table rows,
headings, fenced and indented code, HTML blocks, front matter and link
reference definitions are never checked. Under `flavor: commonmark` there are
no pipe tables, so the rule does not apply and reports neither findings nor
coverage.

A run is a maximal sequence of candidate lines on consecutive physical lines of
one paragraph; any line without a structural pipe, a blank line or a container
boundary ends it. A run of two or more lines is reported when all its lines
have the same cell count of at least two, when every line has both a leading
and a trailing pipe, or when at least one line is delimiter-shaped. A run in a
paragraph directly beside a table, on the physical line just before or after
it, is reported even when it has one line; under the GFM parser a pipe line
directly before a table makes the whole block one paragraph, which is reported
as one run instead. A run that fails every test is not split into smaller runs.

Each reported run produces one finding, with runs in document order. The
finding covers the run from the first line's first character after any
container prefix and indentation to the last line's last character, before any
trailing spaces or tabs and before the line ending, so a CRLF is never split.
Coordinates use original bytes and Unicode scalar columns. The message is
`Pipe rows are not part of a table.`

Findings are manual and report-only: `fix_available` is false and `fix` makes
no changes. A real suppressed finding counts as used for MD087. When the
parser's paragraph provenance is unavailable, the whole inventory is withheld
instead of guessed, with the coverage message
`Paragraph pipe-row context is unavailable; the complete MD075 inventory is withheld.`

An empty task item, such as `- [x]`, `- [ ]` or either with trailing spaces or
tabs, has no lines to check and does not withhold coverage. The rest of the
document is still checked as usual.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
A | B
1 | 2
````

A GFM header/delimiter mismatch also leaves a sequence of pipe-row candidates outside a parsed table:

````markdown
| A | B |
| --- |
| 1 |
````

Accepted input:

````markdown
A | B
--- | ---
1 | 2
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; choosing a header or attaching rows requires author intent.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.

Cover GFM header/delimiter count mismatches, incidental prose pipes, protected content, and short or long rows that remain inside a valid table. Verify that MD075 and MD056 use the same parser classification without duplicating findings for a parsed body row.
