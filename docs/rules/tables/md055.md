# MD055: Outer table pipe convention

Status: analysis and configuration implemented for GFM.

Area: [Tables](index.md).

## Behavior

Require parsed table rows to follow one outer-pipe convention. Consistent mode adopts the header row. Use the selected dialect's parsed separator positions: in GFM, escaped pipes are cell content, but an unescaped pipe splits cells even between backticks.

Run only when the selected format recognizes pipe tables. Candidate checks must respect code blocks, escaping, and container boundaries.

mdchk checks every row the GFM parser places in a table: the header row, the
delimiter row and each body row, including tables inside block quotes and list
items. The rule reads the outer pipes the parser recorded for each row and
never rescans the text. An escaped `\|` at a row edge is cell content, not an
outer pipe. Pipe text in fenced or indented code, HTML blocks, paragraphs
without a valid delimiter row, and lines the parser does not make table rows
is never checked. Under `flavor: commonmark` there are no pipe tables, so the
rule does not apply and reports neither findings nor coverage.

Each table has an expected pair: whether a leading pipe is expected, and
whether a trailing pipe is expected. `leading_and_trailing` expects both and
`none` expects neither; every row, including the header, is checked against
that pair. `consistent` copies each edge from the table's own header row, so
the header row itself is never reported, and each table in a document has its
own convention.

Each edge that differs from the expected pair produces one finding, the leading
edge before the trailing edge, with rows in document order. An unexpected pipe
is reported on the pipe byte itself. A missing pipe is reported as a zero-width
position where the pipe would go: at the first character of the row after any
container prefix and indentation, or just after the last character of the row,
before any trailing spaces or tabs and before the line ending, so a CRLF is
never split. Coordinates use original bytes and Unicode scalar columns.

The four messages are:

- `Missing leading pipe; expected <convention>.`
- `Unexpected leading pipe; expected <convention>.`
- `Missing trailing pipe; expected <convention>.`
- `Unexpected trailing pipe; expected <convention>.`

`<convention>` names the expected pair: `leading and trailing pipes`,
`a leading pipe only`, `a trailing pipe only` or `no outer pipes`.

Findings are manual and report-only: `fix_available` is false and `fix` makes
no changes. A real suppressed finding counts as used for MD087. When the
parser's row facts are unavailable, the whole inventory is withheld instead of
guessed, with the coverage message
`Table row context is unavailable; the complete MD055 inventory is withheld.`

## Configuration

Default enablement: Enabled.

style: consistent, leading_and_trailing, or none; default consistent.

All rules also accept the [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
A | B
--- | ---
| 1 | 2 |
````

Accepted input:

````markdown
A | B
--- | ---
1 | 2
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Corrections are future work; no MD055 correction is produced yet.

Add or remove outer syntax pipes only, using parser-owned separator positions and original cell spans. Preserve all cell content, escapes, and cell counts, including excess source cells. Reparse the candidate to verify that table structure and meaning are preserved.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.

Include escaped and unescaped pipes inside inline code, empty edge cells, and rows with excess cells. Verify that correction changes only outer syntax pipes and never treats a cell-content pipe as an outer delimiter.
