# MD038: Whitespace within inline code delimiters

Status: analysis and configuration implemented for CommonMark and GFM. Automatic
corrections remain deferred.

Area: [Formatting](index.md).

## Behavior

Inspect actual parsed inline code spans. Both original delimiter-adjacent edges
must have ASCII SPACE runs; one-sided runs of any length are accepted as meaningful
content. All-SPACE normalized code values are accepted. Tabs, other Unicode
whitespace and physical line endings are never diagnostic padding.

For other paired runs, preserve one innermost SPACE at each edge when the actual
normalized code value starts or ends with SPACE or a backtick. Report only the
outer excess. Otherwise report both complete edge runs. Each excess run has its
own original source range and the message `Whitespace within inline code delimiters.`.
For example, ` text ` reports both single spaces, while `  text  ` reports the
outermost space at each edge. A style finding does not prove that deletion would
preserve the code value; all findings remain manual.

Nested parsed Markdown children, link labels, image alternatives and GFM cells
participate. Code blocks, HTML attributes/comments and raw HTML lifetimes remain
protected. Multiline code spans use original edge bytes without including endings
or removed container prefixes. Recognized frontmatter is opaque.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
`  text  `
````

Accepted input:

````markdown
`text`
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only unless the parsed code value remains byte-for-byte identical after normalization.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
