# MD044: Capitalization of configured names

Status: analysis and configuration implemented for CommonMark and GFM.
Automatic correction remains planned; all current findings are manual.

Area: [Formatting](index.md).

## Behavior

Report case-insensitive matches of configured proper names whose spelling differs in case. Match whole Unicode word sequences and prefer the longest match.

Matching uses pinned Unicode 17 full default C/F case folding, without
normalization, locale tailoring, trimming or whitespace changes. Endpoints are
original scalar boundaries, never inside an expanded fold. A whole occurrence
requires both outside semantic neighbors to be absent or outside Unicode Letter,
Number, Mark and ASCII underscore. Other connector punctuation is not a word
scalar. Separators in multiword and punctuation-bearing names are literal.

Scan left to right; at each eligible start consume the match reaching the farthest
original endpoint, including correctly capitalized matches. Findings never overlap.
Fold-equal configured spellings are accepted exact alternatives, independent of
list order: names `[GitHub, Github]` accepts either spelling, while `GITHUB`
reports once. The fixed message is `Configured name uses different capitalization.`
and the range covers the complete offending original occurrence.

Analyze Exact Text contributions in one owner, with touching original ranges on
one physical line. Adjacent Text allocations may join; markup, gaps, line breaks,
blocks and cells split islands. `**github**` is eligible; `git**hub**` never joins.
Entities, escapes, normalized NUL and partial tabs are excluded barriers. Their
semantic outside-neighbor word facts remain binding: `&#97;github` and
`github\_x` do not create false whole-word matches. Literal U+FFFD stays Exact.
No text is decoded again.

Authored link labels and image alternatives are eligible independent owners.
Destinations, titles, reference identifiers/definitions, angle autolinks and actual
GFM bare links are protected. CommonMark bare `https://github.com` is ordinary
Text and reports `github`; an authored `[https://github.com](x)` label also reports.
Raw HTML lifetimes through actual closer or EOF, closing tails, comments and
recognized metadata headers remain protected. Image-alt raw state is local.
Unreliable required syntax produces affected incomplete coverage.

The examples use names: [GitHub]. No proper names are enforced without configuration.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

names: string list, empty; code_blocks: boolean, false.

Every name must be valid UTF-8, even when disabled. Empty names are inert;
duplicates are harmless. Whitespace, punctuation and controls remain literal;
there is no extra proper-name grammar. CR/LF never cross a physical line.
No names means no enforcement. Other rules' list domains are unchanged.

`code_blocks=true` admits only actual fenced/indented CodeBlock Content, one
physical line at a time after parser-owned prefixes. Payload stays literal,
including URL-looking text. Fences, info strings and prefixes stay excluded.
Inline CodeSpan remains protected in both modes. Provenance barriers still apply.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
Use github.
````

Accepted input:

````markdown
Use GitHub.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Future correction policy: change capitalization only, using the exact configured name; preserve URLs and code by default.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
