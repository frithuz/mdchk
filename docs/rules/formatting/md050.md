# MD050: Bold delimiter style

Status: analysis, configuration and correction implemented for CommonMark and
GFM.

Area: [Formatting](index.md).

## Behavior

Require bold emphasis to use the configured delimiter or the first bold delimiter encountered.

Only actual parsed Strong syntax with two-byte markers participates, including
nested Strong, Strong within italic or GFM strike, consumed roles in triple and
longer runs, authored link labels and image alternatives. Italic and malformed
whitespace candidates neither seed nor report bold style. Consistent selects the
minimum eligible original opening position once per document, including disabled
intervals whenever the callback executes. Containers, directives and selected
inspection lines do not reset it; documents have independent baselines.

Each mismatch produces one finding on the complete original two-byte
Opening: `Bold delimiter style does not match the expected style.` Opening START
alone controls suppression, independently of the closer. Actual code, raw HTML
lifetimes and closing tails, comments, recognized metadata and URL owners remain
protected. Ordinary CommonMark URL-looking Text follows its actual parse; actual
GFM bare links remain protected. Transformed children within actual Strong remain
eligible.

## Configuration

Default enablement: Enabled.

style: consistent, asterisk, or underscore; default consistent.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
**one** and __two__
````

Accepted input:

````markdown
**one** and **two**
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` rewrites both two-byte markers of a reported Strong to the expected marker
in one group, so `**one** and __two__` becomes `**one** and **two**`; a Strong is
never half-corrected. The rewrite applies only when reparsing the document with
both markers changed gives the same Strong nodes, in count, nesting and content,
and the same text. These findings stay manual with `fix_available: false`:

- a Strong whose rewrite would change the parse, such as `foo**bar**baz` under
  `style: underscore`, where `__` can't open or close inside a word;
- a Strong whose markers belong to a run of three or more delimiters, such as
  `***x***` or `___x___`;
- a Strong whose markers touch another `*` or `_` and could merge with or rebind
  an adjacent or nested run, such as `**outer __inner__**`;
- findings under a disable directive, decided at the Opening START, and in a
  document opening with an unrecognized `---` or `+++` block.

Code, raw HTML, comments, recognized metadata and URL owners keep their bytes.
Line endings and container prefixes are never edited.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
