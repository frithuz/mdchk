# MD049: Italic delimiter style

Status: analysis, configuration and automatic correction implemented for
CommonMark and GFM.

Area: [Formatting](index.md).

## Behavior

Require italic emphasis to use the configured delimiter or the first italic delimiter encountered. Bold is checked separately.

Only actual parsed italic emphasis participates, including italic nested in bold,
triple delimiter runs, authored link labels and image alternatives. Strong-only
syntax and malformed whitespace candidates do not establish a style. In
consistent mode, the earliest eligible opening marker in the original document
establishes one document-wide style, including disabled intervals whenever the
rule executes. Containers and directives do not reset it; separate documents
have independent styles.

Each mismatch produces one finding on its original one-byte opening
marker: `Italic delimiter style does not match the expected style.` Directives
filter at that opening position, even if the closing marker has different state.
Code, actual URL owners, recognized metadata, comments and raw HTML payloads
retain their shared protections. Ordinary CommonMark URL-looking text may still
contain actual emphasis; GFM bare links remain protected.

## Configuration

Default enablement: Enabled.

style: consistent, asterisk, or underscore; default consistent.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
*one* and _two_
````

Accepted input:

````markdown
*one* and *two*
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` rewrites both one-byte delimiters of a mismatched italic to the expected
marker, the configured `style` or, in `consistent` mode, the document-wide style,
so `*one* and _two_` becomes `*one* and *two*`. An italic is never
half-corrected, and no other byte changes. Strong delimiters are never edited:
in a triple run such as `___x___` only the italic member's byte changes, giving
`*__x__*`.

A rewrite is offered, with `fix_available: true`, only when reparsing the
corrected document gives the same emphasis nodes, nesting and text. Every other
finding stays reported with `fix_available: false` and its bytes are left
alone. That covers intraword cases such as `a*b*c` with `style: underscore`,
whose rewrite would no longer be emphasis, rewrites that would pair differently
with neighbouring delimiter runs, such as `_x *y_ z*`, and triple runs whose
italic/strong split would change, such as `**_b_**`. Findings under a disable
directive, italics whose closing marker lies in a different directive state than
the opening, and findings in a document opening with an unrecognized block stay
manual too. Code, URLs, raw HTML, comments, recognized front matter and GFM bare
links keep their protections, and italics inside them are never edited. Link
labels, image alternatives, headings, list items, block quotes and table cells
are corrected like any other prose.

MD049 edits wait for a round in which no other rule proposes an edit, after
MD044 and ahead of MD064 and MD038, and only an eligible MD047 edit shares that
round. A document with MD009, MD047 and MD049 findings converges in one run.

Every correction satisfies the [shared preservation contract](../index.md#implementation-contract). Remaining findings are reported after checking the corrected document again. The [MD049 correction design](../../engineering/fixes.md#md049-corrections) describes the producer and checker.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
