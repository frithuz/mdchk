# MD088: Quote and dash normalization

Status: analysis, configuration and correction implemented for CommonMark and
GFM.

Area: [Formatting](index.md).

## Behavior

Report only literal original-source U+2018, U+2019, U+201C, U+201D,
U+2013 and U+2014 in actual paragraph, ATX/Setext heading and GFM prose
cell text. Emphasis, strong and strikethrough wrappers are transparent.
Each eligible scalar produces one finding with the exact message
`Use ASCII quotes and dashes in prose.` Its exclusive range selects exactly
three original UTF-8 bytes and one Unicode code-point column. Adjacent scalars
are separate findings; em dash is one finding despite its two-hyphen mapping.

Only Exact text contributions matching original source bytes qualify. Entity
spellings such as `&ldquo;` and `&#x2014;`, escapes and normalized/partial-tab
contributions create no punctuation candidates. A backslash before a non-ASCII
curly quote does not escape it. Other Unicode punctuation remains unreported.

Protect all actual links, including visible labels and inline, reference,
angle-autolink and GFM bare-link forms. URL protection follows parser ownership:
bare URL-looking Text in CommonMark remains prose. No separate URI scanner is
used. Entire images, including descriptions, destinations and titles, are opaque.
Unresolved or malformed bracket syntax follows actual Text ownership.

Protect code spans, fenced/indented code and info strings, comments, tag attributes,
raw HTML payloads, recognized opaque metadata and retained reference definitions.
Ordinary Text between nonraw tags remains prose. Genuine raw transitions inside
links affect surrounding protection; image descendants cannot open or close it.
Raw lifetime crosses owners and private closing tails. Recognized unterminated
headers retain protection and incomplete coverage rather than clean analysis.

Analyze full original context before directive START suppression or inspect
intersection filtering. Hidden or unselected raw openers still affect later prose.
TAB and astral scalars each count one public column; original entity spellings,
container prefixes, BOM and physical line endings retain their source geometry.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

`style`: string, only `ascii` (default). The fixed mapping is U+2018/U+2019 to ASCII apostrophe, U+201C/U+201D to ASCII quote, U+2013 to one hyphen and U+2014 to two. `replacements` is not an option and is rejected even when the rule is disabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
“Guide”—example
````

Accepted input:

````markdown
"Guide"--example
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` replaces each reported scalar with its fixed mapping, one edit per finding
covering exactly its three bytes: U+2018 and U+2019 become `'`, U+201C and
U+201D become `"`, U+2013 becomes `-` and U+2014 becomes `--`. No other byte
changes, so `“Guide”—example` becomes `"Guide"--example`. Quotes in headings
are corrected.

A replacement applies only when reparsing the document with it gives the same
nodes, in kind, order, nesting and properties, and the same text, except that a
Text value may hold a mapping where it held the scalar. The dashes of one line
are reparsed as one unit, so a line is never half-rewritten. Reparsing every
candidate fails when any one of them changes the structure; mdchk then splits
the candidates in halves, keeping those already accepted, until each unsafe
one is isolated. At most 64 reparses run per document and round; candidates
still undecided then stay manual.

These findings stay reported with `fix_available: false` and no
`deferred_fixes` record:

- an en or em dash in an ATX or setext heading, since the heading anchor keeps
  `-` but drops the dash, so the anchor would change;
- the dashes of a line that, after its container prefix, opens with an en dash
  before a space, TAB or line end, such as `– item`, which would become a list
  marker, or holds only dashes, hyphens, spaces and TABs, such as `– – –` or a
  `———` line under a paragraph, which would become a thematic break or setext
  underline;
- a dash in a GFM table delimiter cell, such as `| – |` under a header row;
- `<!—` at the start of a block, which would open a comment;
- a scalar after a backslash, such as `\“` or `\—`, which would become an
  escape;
- a scalar the mapping would pull into a GFM bare autolink, such as the dash in
  `www.example.com.—x` or `a—b@example.com`;
- any other scalar whose replacement changes the reparsed structure;
- findings under a disable directive, and in a document opening with an
  unrecognized `---` or `+++` block.

Code spans, fenced and indented code, link labels and destinations, images,
raw HTML and its attributes, comments, reference definitions and recognized
front matter hold no findings and keep their bytes. Line endings and container
prefixes are never edited.

MD088 edits wait for a round in which no other rule proposes an edit, after
MD050, MD044 and MD049 and ahead of MD064 and MD038, and only an eligible MD047
edit shares that round, so a document with MD009, MD047 and MD088 findings
converges in one run.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.
