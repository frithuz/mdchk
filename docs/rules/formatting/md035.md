# MD035: Horizontal rule marker style

Status: analysis, configuration and automatic correction implemented for
CommonMark and GFM.

Area: [Formatting](index.md).

## Behavior

Require final parsed thematic breaks outside protected content to use the selected
marker family or the first eligible break's exact original marker pattern.

`consistent` compares the bytes from the first marker through the last marker.
Marker count and every interior ASCII SPACE or TAB matter: `---` differs from
`----`, and `* * *` differs from `***`. Outer indentation, trailing whitespace,
line endings and container prefixes are excluded. The first eligible break is
its own baseline and never violates this mode.

The baseline is global across root, blockquotes and list items in original source
order. Disabled or suppressed eligible breaks still establish it; inspection
selects lines after complete analysis. Code, HTML-owned payload, semantic raw HTML
lifetimes, recognized opaque metadata, Setext underlines and malformed literal
candidates supply neither baselines nor findings. Matching actual raw closers, including those in HTML-block tails, end
protection; tail openers retain their own protection. Image-alternative tags do
not alter outer state.
Incomplete required syntax produces affected coverage rather than guessed styles.

`dash`, `asterisk` and `underscore` require `-`, `*` and `_` respectively. Each
accepts any parsed marker count and interior spacing of its family, including on
the first break. Conforming breaks are never normalized, so `-----` is accepted
under `dash`.

One finding covers the original first-to-last marker envelope, including
interior gaps, with exclusive Unicode scalar coordinates. Its original first
marker START controls directive suppression. Analysis reports every finding with
`fix_available: false`; `fix` corrects the ones its
[correction policy](#correction-policy) accepts.

## Configuration

Default enablement: Enabled.

style: consistent, dash, asterisk, or underscore; default consistent.

All rules also accept the [shared settings](../index.md#configuration-and-findings). These defaults are implemented.

## Examples

Violating input:

````markdown
---

***
````

Accepted input:

````markdown
---

---
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` and `fix --dry-run` replace only the reported first-to-last marker
envelope. Under `dash`, `asterisk` or `underscore` the replacement is `---`,
`***` or `___`. Under `consistent` it is the exact first-to-last pattern of the
first eligible break, the same baseline analysis uses, including when that
baseline is disabled or suppressed: with a first break of `* * *`, a later `---`
becomes `* * *`. Indentation, container prefixes, trailing whitespace and LF,
CRLF or CR endings stay byte for byte, so `> ***\r\n` under `dash` becomes
`> ---\r\n`.

One break is one atomic correction. It is deferred, and its finding stays
reported with `fix_available: false`, when:

- the corrected document would parse differently, for example `---` directly
  under a paragraph line, which would become a Setext heading underline, or a
  change that would start a list item or merge or split a paragraph;
- the break lies outside the rule's enabled directive intervals.

Breaks inside code, HTML and front matter produce no finding and so no edit. A
document that opens with an unrecognized block gets no MD035 correction.

MD035 waits for a round in which no other rule proposes an edit, MD010, MD003,
MD027 and MD089 included, since its checker compares whole parses and block
envelopes. MD064 waits for MD035 in turn. An MD047 edit that analysis already
offers goes first; one it withheld waits for MD035. A document with MD009,
MD012, MD035 and MD047 findings converges in one `fix` run.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Corrections cover the reparse guards, composition with MD009, MD012 and MD047, preview and saved modes and second-run idempotence.
