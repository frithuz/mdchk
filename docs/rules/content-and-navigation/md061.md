# MD061: Configured prohibited vocabulary

Status: analysis and configuration implemented for CommonMark and GFM;
automatic correction is not offered (report-only).

Area: [Content and navigation](index.md).

## Behavior

Report configured prohibited terms in prose using whole-word, case-insensitive matching unless configured otherwise. Empty terms disable matches.

Matching uses pinned Unicode 17 full default C/F case folding, without
normalization, locale tailoring, trimming or whitespace changes. With
`case_sensitive: true`, terms compare against the original UTF-8 bytes with no
folding. A whole occurrence requires both outside semantic neighbors to be absent
or outside Unicode Letter, Number, Mark and ASCII underscore, so `blacklisted`,
`myblacklist` and `_blacklist` do not match `blacklist`. Separators in multiword
terms are literal, and a term never crosses a physical line.

Scan left to right; at each eligible start report the match reaching the farthest
original endpoint, then continue after it. Findings never overlap: terms
`[black, blacklist]` report `blacklist` once. Duplicate and fold-equal terms give
one finding per occurrence. The fixed message is `Configured prohibited term.`
and the range covers exactly the matched original bytes.

Prose is what [MD044](../formatting/md044.md) analyzes with code blocks off:
Exact, touching, single-line Text in paragraphs, headings, GFM table cells,
authored link labels and image alternatives, including inside block quotes and
list items. Code spans, fenced and indented code, HTML blocks, inline HTML and
raw-tag lifetimes, angle autolinks, GFM bare links, link destinations, titles,
reference definitions and recognized frontmatter are protected. Entities,
escapes, normalized NUL and partial tabs are barriers whose semantic word facts
still bind the neighbors. Unreliable required syntax produces affected
incomplete coverage.

The examples use terms: [blacklist]. No terms are prohibited by default.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

terms: string list, empty; case_sensitive: boolean, false.

Every term must be valid UTF-8, even when disabled. Empty terms are inert;
duplicates are harmless. No terms means no findings.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
Use blacklist.
````

Accepted input:

````markdown
Use denylist.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only for terms [blacklist]; replacement vocabulary must be chosen by the author.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
