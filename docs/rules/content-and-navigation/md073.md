# MD073: Table of contents versus headings

Status: planned for implementation.

Area: [Content and navigation](index.md).

## Behavior

Recognize marker-only lines in parser-confirmed eligible HTML comment spans, after accounting for container prefixes and surrounding spaces/tabs. Match configured comment text exactly and case-sensitively. Ignore marker text in code, metadata, raw payloads or other protected contexts. No markers means no TOC requirement.

Allow multiple sequential, nonoverlapping pairs. Each pair must remain in one container. Unmatched, nested or cross-container markers produce a located problem and no inferred regeneration extent; independently reliable regions may still be analyzed. Any affected analysis that requires uncertain region or heading ownership remains explicitly incomplete.

Every TOC covers the same whole-document selection, in document order, filtered to min_level..max_level. Include parsed main-flow headings, including headings in ordinary parsed Div/section wrappers, but exclude headings inside blockquotes, list items, code, metadata and all marked TOC regions. Frontmatter virtual titles and arbitrary ID-bearing non-heading nodes are not TOC entries. Do not infer local/section-only TOCs.

Allow one optional leading heading inside each marked region. Preserve that heading byte-for-byte and exclude it from TOC entries. Do not guess TOC titles from text such as Contents. Headings outside a marked region use the ordinary eligibility rules.

Use parsed visible heading text as the link label, with safe Markdown escaping, and the settled shared anchor service for destinations. Explicit anchor mode includes only eligible headings with usable explicit IDs; no new generated IDs. Known policy exclusions are not incomplete coverage. Actual parse/anchor uncertainty, including ambiguous target identities, blocks affected comparison/correction.

Compare entry order, visible labels, resolved fragment destinations and logical outline nesting. Equivalent bullet spelling, indentation or inline presentation alone is not an MD073 mismatch; existing formatting rules own those details.

Generate a deterministic unordered list. Choose parents from the preceding eligible heading stack: pop headings of greater-or-equal level, attach beneath the remaining nearest shallower heading, and never invent empty levels for heading jumps. Honor effective bullet marker, indentation, root-indent and marker-spacing settings; use resolved document style for consistent-marker mode, or dash when no marker exists. Preserve source newline style and container prefixes. Empty heading selection removes entries while preserving markers and the optional title.

Replace only the list portion inside a valid marked region, preserving both markers, the optional leading heading and all outside content. Automatic regeneration is allowed for an empty region or one containing only that optional heading, whitespace and an ordinary TOC list. Unexpected prose, comments, directives or other blocks make the region report-only. Reparse candidates and require stable heading/anchor identities, intended list structure and the existing fix-safety guarantees.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

start_marker: string, `<!-- toc -->`; end_marker: string, `<!-- /toc -->`; min_level: 1; max_level: 6.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
<!-- toc -->
- [Usage](#usage)
<!-- /toc -->

## Install
````

Accepted input:

````markdown
<!-- toc -->
- [Install](#install)
<!-- /toc -->

## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Regenerate only the marked region, using the selected anchor convention and preserving enclosing container prefixes.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
