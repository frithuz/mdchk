# MD074: MkDocs navigation file targets

Status: analysis and configuration implemented; report only.

Area: [Content and navigation](index.md).

## Behavior

Check local MkDocs navigation entries against the configured documentation root. Ignore remote URLs; directory entries use shared `resources.index_file`, default `index.md`, exactly once.

Use the [resource contract](../index.md#resource-dependent-checks). Resolve resources read-only; never create missing targets.

Enabling MD074 opts into the [static MkDocs 1.6.1 contract](../../engineering/integrations.md#mkdocs-navigation). Resolve `config_path` from the operation resource root; default `docs_dir` is `docs` beside that configuration, confined to the resource root. `check_absolute: true` treats root-relative source paths relative to that docs root. `check_omitted` requires a complete build-eligible inventory, independent of lint exclusions. Absent/null nav is automatic; `[]` is manually empty. Never execute plugins, includes or environment tags. Run once per project; Markdown directives do not control it.

`mdchk lint` runs MD074 once per operation, outside the per-document rules, even when no Markdown target is selected. It reads the configuration and documentation tree through the same read-only resource session as MD051 and MD057, and never creates, changes or deletes a file. The configuration is a finding location only: it is not added to `files` or `checked_files`.

Each missing local nav target is one finding at the configuration's cwd-relative path. Its range is exactly the target's scalar value, such as `missing.md` in `nav: [{Guide: missing.md}]`, and its message is `MkDocs navigation target does not exist: <destination>.` with the destination as written. Nested titled sections report the inner entry. Query strings and fragments do not affect existence, any existing regular file passes, and a directory entry passes only when its single `resources.index_file` exists. Remote and protocol-relative entries are ignored, and so are leading-slash entries unless `check_absolute` is true.

With `check_omitted: true` and a manual nav, each build-eligible page that no nav target names is one finding at the `nav` value, with the message `Page is not included in MkDocs navigation: <path>.` and the page path relative to the docs root. Pages excluded through `exclude_docs`, `draft_docs` or `not_in_nav` are not reported. Absent or `null` nav is automatic and reports no omissions; `nav: []` reports every eligible page.

Uncertainty is never a clean result. Each case below is MD074 coverage with reason `context-unavailable` at the configuration path, so lint returns `15`:

- a missing, unreadable or non-regular configuration, without a range; the message names `config_path`;
- malformed YAML, duplicate keys, custom tags, `INHERIT`, `hooks`, active plugins other than `search`, unsupported nav entries, a `docs_dir` escape or a missing docs directory, at the producer's range and with its message;
- a target that is blocked, invalid, of unknown existence or of the wrong type, at the target's range;
- a missing target while plugins, hooks or other dynamic settings make the navigation non-static, at the target's range instead of a finding;
- omissions that cannot be checked because the inventory is incomplete or the navigation is not static, at the `nav` value.

Runtime limits, deadlines and cancellation add an interruption. An unreadable configuration or target also reports an I/O error. Findings already established are still reported next to unrelated coverage.

`mdchk fix`, including `--dry-run`, and `mdchk inspect` do not check MkDocs navigation. With MD074 enabled, each records one unlocated MD074 coverage entry, `MkDocs navigation is checked only by lint.`, and returns `15` unless an error takes precedence. They report no MD074 findings, edits or previews.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

enabled: false; config_path: string, mkdocs.yml; check_omitted: boolean, false; check_absolute: boolean, false.

`config_path` must be a canonical path relative to the operation resource root: not empty, not absolute, without a drive, backslashes, `.` or `..` segments or a URL. Other values are configuration errors, and lint and `config validate` return `12`.

All rules also accept the [shared settings](../index.md#configuration-and-findings). Unknown keys and values of the wrong type are rejected, even when `enabled: false`. `allow_directives` is accepted but has no effect, because document directives do not control MD074.

## Examples

Violating input:

````markdown
nav: [{Guide: missing.md}]
````

Accepted input:

````markdown
nav: [{Guide: guide.md}] where guide.md exists.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only. MD074 has no automatic correction and never creates missing files or nav entries. It requires an explicit MkDocs project context and a bounded parsed configuration; unavailable resources are reduced coverage.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
