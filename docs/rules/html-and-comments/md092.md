# MD092: Unresolved version-control conflict markers

Status: implemented for CommonMark and GFM; report-only.

Area: [Html and comments](index.md).

## Behavior

Report unresolved conflict-marker runs at **physical column 1** of the original
source, before removing Markdown container prefixes. Count the maximal contiguous
run of one ASCII character from `<`, `>`, `|`, or `=`. All four require at least
seven bytes. Any suffix is allowed, including an adjacent label, another marker
character, or Unicode. The diagnostic covers the entire run only, excluding its
suffix and physical line ending, with the message
`Unresolved version-control conflict marker.`

One Boolean conflict state applies across the whole document:

- An opening `<` run reports and activates the state; repeated openings saturate.
- A closing `>` run reports even without an opening and clears the state.
- A diff3 ancestor `|` run reports even without an opening and leaves state unchanged.
- An `=` run reports only while active and leaves state unchanged.

There is no nesting stack, matching-label or matching-width requirement, phase
ordering, or synthetic missing-close finding at EOF. State starts fresh for each
document and evaluation. Blank lines, headings, owner/container changes,
protected regions, directives and inspection focus do not reset it. Protected
markers neither report nor change state. The full original inventory is computed
before directive START attribution and inspection focus; a hidden opening can
activate a later visible separator and a hidden closer can clear that context.

Leading SPACE, TAB, BOM, Unicode whitespace, list/quote/task prefixes and
indentation are not skipped. `> <<<<<<< ours` and `- <<<<<<< ours` are outside
this grammar. A literal `>>>>>>> theirs` still qualifies even if Markdown treats
its bytes as quote prefixes; quote ownership alone is not protection. Escaped or
entity-spelled characters never synthesize a marker.

Exclude a run when any marker byte overlaps actual code, recognized metadata,
HTML/comment/token ownership, semantic raw HTML payload, or a whole Image.
Code-block protection includes its owned physical prefix and delimiter lines.
A later unrelated code span, comment or tag in the suffix does not hide an
earlier marker. Recognized metadata stays opaque without semantic decoding.
Original owned HTML tokens and tails preserve actual raw lifetimes across owners:
an incoming inline raw tag needs its corresponding closer, while an actual
form-1 HTML block retains the parser's existing ANY4 closing boundary. Image-local
markup cannot alter outer raw state. Known unclosed protected remainders remain
protected. Unknown required protection context withholds the entire MD092
inventory with explicit reduced coverage, including any provisional prefix.

## Configuration

Default enablement: Enabled.

No rule-specific options. Shared `enabled` and `allow_directives` settings are
booleans. Omitted or empty settings retain default ON. Null, nonbooleans and
unknown options reject even when the rule is disabled. Inherited directive denial
cannot be relaxed by a child configuration. See the
[shared settings](../index.md#configuration-and-findings).

## Examples

Violating input:

````markdown
<<<<<<< ours
Text
=======
Other
>>>>>>> theirs
````

The opening, separator and closing each report their seven-byte run.
`|||||||base` and `>>>>>>>theirs` also report independently.
`=======suffix` reports after an admitted opening, but not on its own.

Accepted input:

````markdown
Resolved text.
````

A bare `=======` without active conflict context is accepted. A quoted
`> <<<<<<< ours` is outside the physical-column-one grammar. The conflict
sequence inside an actual fenced code block is protected.

LF, CRLF, CR and absent final newline retain their original byte offsets;
columns are one-based Unicode code points with exclusive ends. U+2028/U+2029 do
not introduce physical lines. Invalid UTF-8 belongs to the mandatory input gate.

## Correction policy

Report only. Merge the conflict deliberately. MD092 produces no edits, previews,
corrected content or automatic correction eligibility. Independently enabled
MD047 corrections remain attributed to MD047.

## Validation

Reusable exact-source fixtures cover default/configuration boundaries, every
marker family and threshold, suffixes, physical prefixes, global state,
protected code/metadata/HTML/Images, original raw lifetimes, Unicode/endings,
directives, MD087 observations and unknown-context atomic withholding. Engine
and inspection fixtures compare whole visible, suppressed and audit inventories,
original byte identity and absence of MD092 corrections. Compiled native tests
cover actual lint/inspect/fix/config behavior and all four reporters. MCP parity
remains downstream in #196, #200 and #206.
