# MD086: Comments lacking a closing delimiter

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Html and comments](index.md).

## Behavior

Report an actual eligible HTML comment opener without a matching closer in its
logical HTML owner. EOF is the final decision deadline: a later literal closer
in another owner, Markdown block or container cannot repair an ended owner.
Ordinary unowned Text such as `text <!-- open` is deliberately excluded with
complete coverage; no malformed inline-candidate grammar is introduced.

The population includes form-2 HTML blocks, comments lexed from actual form-6/7
mapped HTML content, eligible actual InlineHTML and closing-line HTML tails,
exactly once in source order. Comments do not nest: the first eligible closer
ends the comment, and nested-looking openers are payload. Markdown backticks,
fences and backslashes inside an established comment do not protect `-->`.
Entity spellings are never decoded into delimiters. Actual short `<!-->` and
`<!--->` forms remain closed, including their overlapping block close spans
and special inline closing proofs.

Protect code, recognized opaque YAML/TOML headers, whole Images and descendants,
link destinations/titles, autolinks and retained reference definitions. Actual
Link-label HTML remains eligible. Complete tags/quoted attributes, processing
instructions, declarations and CDATA are opaque tokens; their interiors cannot
start or close an independent comment. Actual `pre`, `script`, `style` and
`textarea` raw lifetimes remain protected. Form-1 blocks end at the first literal
closer of any of those four names; their following owned tail can be eligible.
Other raw lifetimes require genuine same-name closing ownership. Image HTML
cannot start or end an outer raw lifetime.

An established eligible comment lacking its closer is a violation. A failed
named token in actual unprotected HTML context instead makes subsequent token
ownership unreliable: withhold the entire MD086 inventory and findings with
explicit context-unavailable coverage, including an earlier genuine prefix.
Unclosed unnamed PI/declaration/CDATA protects the remaining owner without
guessing comments. Existing unterminated recognized metadata retains parse
coverage; disabled metadata recognition follows ordinary selected parsing.

## Configuration

Default enablement: Enabled.

No rule-specific options. Shared `enabled` and `allow_directives` accept strict
booleans, using exact case-sensitive MD086. An empty mapping keeps defaults;
null, scalars, undocumented options and invalid shared values reject even when
disabled. See [shared settings](../index.md#configuration-and-findings).

```yaml
version: 1
rules:
  MD086:
    enabled: true
    allow_directives: true
```

## Examples

Violating input:

````markdown
<!-- note
````

Accepted input:

````markdown
<!-- note -->
````

An owned interior opener also violates:

````markdown
<div>
<!-- open
````

A container boundary ends the first owner, so the later closer does not repair it:

````markdown
> <!-- open

-->
````

Quoted attributes, raw payload and ordinary unowned Text are excluded:

````markdown
<div title="<!-- literal">

<script>
<!-- raw payload
</script>

text <!-- ordinary Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>`
describe source characters rather than literal Markdown.

## Diagnostics and directives

Emit one manual finding per eligible unmatched opener, with fixed message
`HTML comment is missing a closing delimiter.` The range is exactly the original
four contiguous bytes `<!--`, not the owner/payload envelope or an EOF insertion
point. Public one-based Unicode scalar positions have exclusive ends; TAB and
astral scalars each count one column and CRLF is one ending.

Full original context precedes shared diagnostic START suppression and inspection
intersection. A prior complete permitted disable can suppress the opener. An
unclosed directive-looking comment cannot suppress itself; apparent instructions
inside comment payload have no effect. Inherited permission denial preserves
configured state. Inspecting only later payload lines does not intersect the
opener-only finding. Existing directive comment extraction remains unchanged.

## Correction policy

Permanently report only; guessing where the comment ends can expose hidden
content. MD086 produces no edits, fix eligibility, previews or corrected content.
MD047 remains the sole current correction producer. Its eligible final LF can
coexist with a surviving manual MD086 finding in an earlier ended owner. An
unclosed comment at physical EOF keeps MD047 deferred.

## Validation

Reusable frozen fixtures assert original source identity, exact message and
byte/scalar ranges, both flavors, shared configuration/directive controls,
protected content, nested containers, owner endings, LF/CRLF/TAB/astral geometry
and atomic unavailable context. Producer/facade/comparison/outer publication
checks preserve original finite work/record authority and caller/origin controls.
Analysis leaves source unchanged. MCP parity remains downstream in #196, #200
and #206; no additional transport support is implied.
