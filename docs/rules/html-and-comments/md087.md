# MD087: Suppressions that hide no findings

Status: planned for implementation.

Area: [Html and comments](index.md).

## Behavior

Keep MD087 disabled by default, with no rule-specific options, and report-only. Apply the ordinary MD087 state at each prospective finding anchor; later enabling does not retroactively activate earlier comments. Never remove directives automatically.

Evaluate each deduplicated target rule in a valid, allowed mdchk:disable directive independently. Ignore enable directives, invalid directives, globally inactive directives, protected literal comments, permission-blocked targets and rules for which document directives do not apply (including project-scoped MD074). Preserve their ordinary inspection/diagnostic treatment.

Use the existing actual per-rule state intervals: each allowed instruction owns its interval from immediately after its closing marker until the next allowed instruction for that rule or EOF. A repeated disable takes ownership even when state remains false. Credit a hidden finding only to the disable owning its diagnostic start/EOF anchor. This is interval attribution, not independently deleting each comment and replaying all remaining disables; repeated comments must not all be credited for one observation.

Evaluate target-rule observations using the same immutable source, full-document parser context, flavor, options, integrations, resource context and limits as ordinary analysis, without generating edits or emitting hidden target-rule findings as active violations. Use a separate would-be-enabled state initialized from effective configuration and honoring permitted enable directives while ignoring disable directives. An observation is otherwise reportable only where that state is enabled. A target configured off and never explicitly enabled therefore cannot make a disable useful merely because forced evaluation could find violations.

When MD087 is active at a candidate target token, obtain enough target-rule observations to decide whether its interval contains an otherwise reportable finding, even if ordinary lint would skip that target because it is disabled everywhere. Reuse analysis where possible; keep observational execution separate from active/inactive counts. No required counterfactual evaluation when MD087 is disabled. Do not expand resource authorization or execute code; this work consumes shared operation budgets.

A proved otherwise-reportable finding owned by the target disable makes that target used, even if other parts of its interval are incomplete. Report unused only when every relevant would-be-enabled part of the owned interval has complete reliable evaluation with no such finding, or the interval is proved incapable of hiding one (for example configured-off with no enabling instruction). Proven dialect inapplicability can establish no findings; missing required integration/context cannot.

If no hidden finding has been proved and required observations are unavailable because of an unimplemented rule, uncertain parsing, missing resources/context, cancellation or exhausted limits, withhold that unused claim and report affected MD087 coverage as incomplete. Reliable conclusions for other targets remain available. Do not synthesize a target-rule violation or treat absence of execution as a clean check. Existing configuration validation and operational-error precedence still apply.

Exclude MD087 itself from suppression usefulness analysis; do not recursively run MD087 or count its own findings as evidence that a suppression is useful. For a mixed disable naming MD087 and other rules, analyze the other eligible targets normally. The MD087 exclusion is intentional scope, not incomplete coverage.

Emit one MD087 finding per proved-unused target rule, anchored to its first source ID token in the comment. Repeated names inside one directive remain deduplicated. The message identifies the target rule; shared directive attribution links its effective interval. A mixed directive can therefore contain both used and unused targets without labeling the entire comment unused. Keep blocked/uncertain/used outcomes distinct in inspection.

Use the shared diagnostic start-position rule, including file-wide and EOF anchors, rather than edit spans or overlap. Preserve all existing permission, configured-option and protected-source behavior. Recompute after any separately authorized safe fix against the candidate source.

See the [complete rule contract](../../engineering/rule-behavior.md).

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
A disable directive for MD001 in a document with no heading jumps.
````

Accepted input:

````markdown
A disable directive for MD001 spanning an otherwise reportable heading jump.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; removal changes future suppression behavior. Evaluate counterfactual findings without recursively evaluating MD087.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
