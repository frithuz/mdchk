# MD077: Indentation of list continuation content

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Lists](index.md).

## Behavior

Align eligible continuation content with its actual nearest parsed list item.
Report at most one finding per original physical line. The item's opening marker
line, including its payload, is exempt. Every nested item marker opening line is
also exempt; marker indentation belongs to MD007 and related rules. Later content
uses the final inner owner. Root-owned paragraphs are outside this rule, even
when adjacent to a list.

Eligible content includes every nonblank paragraph contribution after the opening
line: subsequent paragraph starts, wrapped lines and parser-confirmed lazy lines.
It also includes nonliteral block openings (headings, thematic breaks and quotes),
actual fenced-code opening and closing markers, the first line of a recognized
reference definition, and each actual GFM table header, delimiter and body row
once. A heading contributes only its final block opening line: a Setext underline
or later heading contribution does not become a paragraph continuation. Task
checkboxes do not change the item's content baseline. CommonMark uses its actual
paragraph classification for table-like text.

Fenced payload, false or absent closers, all indented code, complete raw HTML and
comment blocks, directive-only comments, recognized metadata and blank body lines
are protected. Actual multiline inline code, HTML and comments protect subsequent
payload and closing lines; paragraph indentation before their opening inline
token can still be checked. An actual empty quote opening is a structural target,
but later quote-only blank lines are exempt. Eligibility is established before
checking any quote prefix; prefixes cannot make protected payload eligible.

### Item columns and quotes

Expected indentation is the sum of local parsed `ContentIndent` values for all
actual ancestor items through the nearest owner. Lazy continuation can omit
ancestor indentation without removing that expected numeric obligation. Final
ownership is authoritative: a closed inner item cannot remain the baseline.

Actual indentation uses four-stop structural columns at the original physical
tab phase. Only columns actually consumed by recognized quote prefixes before
the selected boundary are neutralized. Missing lazy quote markers contribute no
width. Quote byte extents cannot substitute for consumed columns: a tab may be
partly shared by quote and item indentation. Public positions still count Unicode
scalars, with a tab occupying one scalar column.

A quote above the nearest item is ancestor structure. A quote after that item
selects the first item-facing `>` as the comparison boundary. Compare indentation
before that marker and ignore postquote body spaces and deeper quotes. This same
boundary applies to eligible prose, real fence closers and actual table rows.
An absent lazy quote selects the actual content token instead.

### Diagnostic evidence

Surplus selects the smallest original offending indentation suffix up to the
actual boundary, excluding tokens, line endings and nonoffending structure. A tab
is indivisible: include its whole byte even if required prefix columns share it.
Deficit selects a zero-width position at the actual content or structural token
start. Structural columns never become byte offsets by subtraction. Shared
directive filtering uses the selected range START after final ownership and
eligibility; later comments cannot suppress a finding retroactively.

## Configuration

Enabled by default, with no rule-specific options. An empty mapping keeps these
defaults. Shared `enabled` and `allow_directives` settings apply, including inherited
permission restrictions. Unknown options and invalid shared types, including null,
are rejected even on disabled rules. See [shared settings](../index.md#configuration-and-findings).

## Examples

Violating input (the later paragraph is actually item-owned):

````markdown
- One

   Text
````

The three-space continuation reports its third space: original bytes `[9,10)`,
public range 3:3–3:4, actual 3 and expected 2. Two spaces pass:

````markdown
- One

  Text
````

`- One\n\n Text\n` is a root-owned outside paragraph and exempt. In
`- - One\n Text\n`, the inner item still owns the lazy line: expected 4,
actual 1, one zero-width finding at `[9,9)`. With no space, the finding is
`[8,8)`, actual 0. In `> - One\n> Text\n`, neutralizing the actual quote
columns gives expected 2, actual 0 and `[10,10)`. An absent quote adds no width:
`> - - One\n Text\n` gives expected 4, actual 1 at `[11,11)`.

`- - > One\n  > Text\n` passes: the inner item closes and the later quote
belongs to the outer item, with expected and actual 2. An aligned descendant
quote permits extra body indentation, including this actual closing fence:

````markdown
- One

  > ```
  > literal
  >   ```
````

Changing only that closing line to `   > ``` ` (without the trailing space)
reports the surplus before `>` at `[29,30)`. Literal payload stays protected.
Aligned quote prefixes also permit additional postquote table-row indentation.

For `- One\n\n\tText\n`, actual 4 exceeds expected 2: the whole tab is
reported at `[7,8)`, public 3:1–3:2, despite sharing required item indentation.
`> - One\n>\n> \tText\n` passes because the tab begins at physical column 2
and supplies exactly two item columns. `> - One\n>\n>\tText\n` also passes:
the quote consumes only one of the tab's three columns, leaving two for the item.

In `- > - One\n\t> Text\n`, the outer item consumes two columns of
that tab. The quote then consumes four columns over three original bytes,
including the tab's remaining two columns. The nearest inner item still requires
four item columns: actual 2, expected 4, one deficit at `[13,13)`, public 2:4.
Neutralizing the quote's three-byte extent would incorrectly report actual 3.

Escaped `\n` and `\t` above describe source newline and tab characters.

## Correction policy

Pass 1 supplies manual findings with `fix_available: false`. PlannedFix metadata
reserves a future correction policy; MD077 produces no edits, executable previews,
writes or returned corrected content. MD047 remains the sole executable
correction. Future corrections must preserve confidently attributed ownership and
satisfy the [shared preservation contract](../index.md#implementation-contract).

## Validation

Reusable literal fixtures cover both flavors, final ownership and protection,
cumulative lazy baselines, first-facing quote boundaries, atomic partial tabs,
original byte and scalar ranges, Unicode, LF/CRLF/CR/EOF, metadata recognition,
directives and configuration. Completed-original production authority, detached
output and the original operation's cancellation and resource limits are required.
