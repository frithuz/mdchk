# MD030: Whitespace after list markers

Status: analysis and configuration implemented for CommonMark and GFM.
Findings remain manual; automatic correction is future work.

Area: [Lists](index.md).

## Behavior

Require the configured number of structural separator columns between each actual
bullet or ordered marker and source content on its first physical line. Container
indentation follows the item's resulting content column. Each item is independent,
including same-line nested lists and quoted items. Definitions, task notation,
markup and comments count as first-line source content even when they render empty.
An empty marker line is exempt, including bare markers, trailing whitespace and
items whose paragraph or code starts on a later line. Marker-looking prose such
as `-no` is not a list item.

Compare the parser's effective padding directly with `spaces`. Tabs retain their
physical tab-stop phase: `-<TAB>One` has padding 3; `> -<TAB>One` has padding 1.
Either passes when the configured value matches; MD010 owns literal tab checks.
More than four nonblank padding columns fall back to one owned separator column:
`-     code` passes the default because the remaining four spaces indent code.
For `-<TAB>  code`, one tab byte contributes both the one-column separator and
residual code indentation. The default passes; `spaces: 2` reports that full tab.

Findings select the entire original owned separator, from marker end to consumed
prefix end, excluding the marker, ancestor indentation, payload and line ending.
For `-  One`, this is bytes `[1,3)`, line 1 columns 2–4. Tabs remain indivisible
original bytes and one scalar diagnostic column. Empty markers never create a
virtual or zero-width missing separator. Directive filtering uses separator start
after the full parser inventory. This pass does not check continuation indentation.

## Configuration

Default enablement: Enabled.

spaces: positive integer, 1.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The positive integer has no additional cap; values above four remain valid but
cannot match a nonempty item’s effective padding. Invalid values and unknown
settings fail even when the rule is disabled.

## Examples

Violating input:

````markdown
-  One
````

Accepted input:

````markdown
- One
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Future work: normalize marker separators and validated continuation indentation
together. PlannedFix is catalog metadata only: this implementation produces no
MD030 edits, previews, writes or corrected content. MD047 remains the sole
production edit provider.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
