# MD069: Repeated list markers

Status: analysis implemented for CommonMark and GFM; permanently report-only.

Area: [Lists](index.md).

## Behavior

Report each maximal run of at least two identical lexically valid ASCII bullet
markers at actual nested item beginnings on one physical source line. Each
parent/child marker gap must contain only one or more original ASCII spaces or
tabs. A mixed pair, ordered marker or intervening quote prefix ends a run; an
inner identical subrun remains eligible. For example, `- + + Text` reports the
plus run, while `- - + + Text` reports two runs. `- - - Text` reports once.

The diagnostic range extends from the first marker start through the last
marker end, including original intervening whitespace. It excludes indentation,
ancestor prefixes, trailing separator, payload and line ending. Thus
`- - - Text` reports bytes [0,5), while `- > - - Text` reports only [4,7).
Tabs retain one original byte and one Unicode scalar column.

The bounded candidate projection uses actual parser list items, direct item
ancestry, the original physical line index and immutable source gaps. The parser
owns thematic breaks, code, raw/comment content and recognized metadata.
`- -` and `* *` at EOF contain a valid empty inner item and report; `- - -`
and `* * *` are thematic breaks and do not. `- - * * *` reports its outer dash
pair before the nested thematic break. `- - - <!-- c -->` reports its complete
three-marker run before the protected HTML payload. Protection applies to each
owned region, rather than excluding all markers in the containing item.

Escaped markers, nonlexical tokens, NBSP separators, ordinary payload such as
`- Text - - More`, code and ordinary nesting across separate lines are excluded.
A separate valid pair on a later line reports independently. Intentional
ambiguous exclusions do not reduce coverage. Unreliable or missing required
parser context still produces affected incomplete coverage. This implements the
MD069 parser-backed candidate grammar; other malformed-candidate rules remain
separate work.

See the [candidate contract](../../engineering/rule-behavior.md#malformed-syntax-candidates).

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). MD069 is available and enabled by default.

## Examples

Violating input:

````markdown
- - Text
````

Accepted input:

````markdown
- Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; the nested list may be intentional.

Findings are manual with `fix_available: false`. MD069 supplies no correction
producer, preview, source write or returned corrected content. MD047 remains the
sole executable correction.

## Validation

Reusable fixtures cover maximal and mixed subruns, protected content, nested
containers, empty/task/definition items, tabs, Unicode/NUL, LF/CRLF/CR/EOF,
configuration, directives and exact original ranges. Compiled CLI tests verify
manual results and composition with MD047 first and second newline previews.
