# MD029: Numbered list prefixes

Status: analysis, configuration and automatic correction implemented for CommonMark and GFM. Renumbering that can't be proven safe stays a manual finding.

Area: [Lists](index.md).

## Behavior

Require numeric prefixes to follow the configured sequence within each actual
parser-owned ordered list group. In `ordered` style, preserve the numeric start
of the first direct item. Each subsequent direct item must equal that start plus
its zero-based direct ordinal. A wrong or suppressed item still consumes its
ordinal: `5., 9., 7.` reports only `9.`; `5., 9., 10.` reports both later items.
Nested groups keep independent counters while their enclosing group continues
across nested lists and quotes. A delimiter change (`.` versus `)`) creates a
separate group. Ordinary blank lines alone need not create another group.

In `one` style every actual ordered item, including the first, must equal numeric
1. Leading zeros do not change numeric equality: `003., 0004.` passes `ordered`,
and `01), 001)` passes `one`. Zero is a valid start in `ordered` style. Numeric
values never wrap: two `999999999.` items violate on the second item, whose
expected value is 1000000000. A ten-digit prefix is not an actual list marker.

Only actual ordered items are targets. Ordered descendants below bullets still
participate; literal code, HTML, comments, escaped syntax and recognized opaque
metadata do not. Parser membership and paragraph-interruption rules apply: a
non-1 nested prefix may need a blank before it to start a list. The full original
item-marker token (digits plus delimiter) owns the diagnostic, excluding container
prefixes, indentation, padding, task markers, payload and line endings. Full
context is compared before diagnostic-start directive suppression.

## Configuration

Default enablement: Enabled.

style: ordered or one; default ordered.

All rules also accept the [shared settings](../index.md#configuration-and-findings). Omitted or empty options use `ordered`. Values are exact and case-sensitive;
null, wrong types, unknown keys and unsupported styles fail even when disabled.

## Examples

Violating input:

````markdown
1. One
3. Two
````

Accepted input:

````markdown
1. One
2. Two
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` and `fix --dry-run` replace the digits of a flagged marker with the value
the configured style expects, written in plain decimal without leading zeros.
`1., 3.` becomes `1., 2.`, and `0009., 0011.` becomes `0009., 10.`. In `one`
style every flagged marker becomes `1`. The delimiter, container prefixes,
indentation, task markers, payload and line endings stay byte-for-byte.

When the new number is wider, the padding after the marker shrinks by the same
amount, so the content column stays put; at least one space must remain. When it
is narrower and the item has more lines, the padding grows instead. A narrower
single-line item keeps its padding. Continuation and lazy lines are never edited.

The finding stays reported with `fix_available: false` and no edit when:

- the width changes and the padding contains a tab, is too short to absorb the
  growth, or the item has no content on its marker line;
- the expected value needs more than nine digits;
- the marker is inside protected content, a directive-disabled interval or
  leading front matter, recognized or not;
- the edit conflicts with another correction;
- the corrected document parses differently: list groups and their boundaries,
  item count and order, nesting and parent items, containers, delimiters, content
  indentation and paragraph or lazy-line membership must all be unchanged. A
  non-1 number that would have to interrupt a paragraph is such a difference.

Each round derives expected values from that round's parse, so a later item whose
expected value shifts is corrected or reported again after the document is
checked once more. MD009 suffix corrections wait until no MD029 correction
remains in the round.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Correction tests cover both styles, exact edit spans, width changes, deferrals,
forged proposals, composition with MD009, MD019, MD021 and MD047, preserved
meaning and a second fix run with no further changes. Current analysis fixtures also cover numeric boundaries, direct
ordinals, suppression, full marker ranges and immutable source snapshots.
