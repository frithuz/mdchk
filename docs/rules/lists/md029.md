# MD029: Numbered list prefixes

Status: analysis and configuration implemented for CommonMark and GFM.
Findings are manual; PlannedFix metadata does not grant correction authority.

Area: [Lists](index.md).

## Behavior

Require numeric prefixes to follow the configured sequence within each actual
parser-owned ordered list group. In `ordered` style, preserve the numeric start
of the first direct item. Each subsequent direct item must equal that start plus
its zero-based direct ordinal. A wrong or suppressed item still consumes its
ordinal: `5., 9., 7.` reports only `9.`; `5., 9., 10.` reports both later items.
Nested groups keep independent counters while their enclosing group continues
across nested lists and quotes. A delimiter change (`.` versus `)`) creates a
separate group. Ordinary blank lines alone need not create another group.

In `one` style every actual ordered item, including the first, must equal numeric
1. Leading zeros do not change numeric equality: `003., 0004.` passes `ordered`,
and `01), 001)` passes `one`. Zero is a valid start in `ordered` style. Numeric
values never wrap: two `999999999.` items violate on the second item, whose
expected value is 1000000000. A ten-digit prefix is not an actual list marker.

Only actual ordered items are targets. Ordered descendants below bullets still
participate; literal code, HTML, comments, escaped syntax and recognized opaque
metadata do not. Parser membership and paragraph-interruption rules apply: a
non-1 nested prefix may need a blank before it to start a list. The full original
item-marker token (digits plus delimiter) owns the diagnostic, excluding container
prefixes, indentation, padding, task markers, payload and line endings. Full
context is compared before diagnostic-start directive suppression.

## Configuration

Default enablement: Enabled.

style: ordered or one; default ordered.

All rules also accept the [shared settings](../index.md#configuration-and-findings). Omitted or empty options use `ordered`. Values are exact and case-sensitive;
null, wrong types, unknown keys and unsupported styles fail even when disabled.

## Examples

Violating input:

````markdown
1. One
3. Two
````

Accepted input:

````markdown
1. One
2. Two
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Future correction policy: replace numeric prefixes and adjust padding only if
item nesting is unchanged. This delivery emits no MD029 edits, previews, writes
or corrected content; MD047 remains the sole executable correction.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Future corrections must verify preserved meaning and a second fix run with no
further changes. Current analysis fixtures also cover numeric boundaries, direct
ordinals, suppression, full marker ranges and immutable source snapshots.
