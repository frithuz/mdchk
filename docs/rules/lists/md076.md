# MD076: Consistent spacing between list items

Status: analysis and configuration implemented for CommonMark and GFM. Findings
remain manual; PlannedFix is future correction metadata only.

Area: [Lists](index.md).

## Behavior

Compare adjacent direct sibling items within each actual parsed list. Tight
requires exactly zero separating blank body lines; loose requires exactly one.
Consistent adopts the exact first sibling separator count, including counts above
one, and retains it for that list. The first adopted separator cannot violate its
own count. Singletons and trailing blanks after the final item have no separator.

Each actual group has its own baseline. Bullet, type, delimiter, block and
container boundaries reset groups; ordered item numbers do not. Nested groups
have independent baselines and do not reset their outer list's context. All
original siblings establish context before directive filtering, including hidden
first separators and suppressed later findings.

Count whole original physical blank body lines after the previous item's terminal
source content and before the following marker line, at the list's parent body
level. Only actually owned ancestor prefixes are removed. Include owned trailing
blanks inside item envelopes and otherwise unowned empty-item gaps, counting each
physical line once. Empty markers and recognized reference definitions are content
floors. Terminal nested lists may propagate their boundary; internal block gaps,
nonterminal nested blanks and quote/code/HTML content do not. External blanks
after closed protected content still count. ASCII spaces and tabs are blank;
NBSP, NUL and comments are content. Final list tightness is not a spacing verdict.
Recognized metadata remains opaque; unavailable reliable syntax reduces coverage.

## Configuration

Default enablement: Enabled.

`style`: `consistent`, `tight`, or `loose`; default `consistent`. Counts are exact.
Unknown options, wrong case, null and invalid types fail even while disabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The catalog defaults are unchanged.

## Examples

Violating input:

````markdown
- One

- Two
- Three
````

Accepted input:

````markdown
- One

- Two

- Three
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Findings and correction policy

Emit one finding per mismatching boundary with actual and expected counts. A
deficit uses a zero-width point at the next direct sibling's actual marker start,
after ancestor prefixes. A surplus retains the required first N blank lines and
highlights only the first extra line's original body suffix through its complete
LF, CRLF or CR ending. Exclude ancestor prefixes, later surplus lines and markers.
For `- A\n\n\n- B\n`, tight reports [4,5), while loose reports [5,6).
Tabs occupy one original byte and one Unicode scalar column. Suppression uses the
chosen original range START; enabling on the following item cannot retroactively
enable a surplus anchored on an earlier blank.

Pass 1 reports every source separator mismatch. Rendering preservation concerns
future correction eligibility only and cannot veto analysis. Findings have
`fix_available: false`; MD076 provides no edits, previews, writes or returned
content. MD047 remains the sole executable correction.

Any future correction must satisfy the [shared preservation contract](../index.md#implementation-contract).

## Validation

Literal reusable fixtures cover both flavors, exact count modes, original ranges,
protected and nested ownership, metadata, configuration, directives and LF/CRLF/CR.
Analysis preserves source SHA and size. Authority, budgets and final publication
are checked at producer, facade and callback boundaries.
