# MD032: Blank lines around lists

Status: analysis and configuration implemented for CommonMark and GFM.
Findings are manual; no edits, previews, writes or corrected content are supplied.

Area: [Lists](index.md).

## Behavior

Require at least one blank body line between a list and each adjacent non-list
source block in the same Document, BlockQuote or ListItem body. Actual recognized
reference definitions participate even though absent from rendered children.
First and last source participants are exempt on their container-edge side.
Adjacent List groups are exempt, including changes of bullet, type or delimiter.
ListItem wrappers and lazy item continuations do not create outside neighbors.

A blank body line contains only ASCII spaces or tabs after removing actual
**enclosing parent** container prefixes. The target list's markers and deeper
container prefixes remain content. List-owned trailing blanks can separate a
following block even inside the List span. Empty final markers, definition source
and internal code/HTML/quote blanks cannot become outside separators. A terminal
line ending does not create a phantom blank line. This rule imposes no item-spacing
or tightness requirement.

Each missing side produces one zero-width original-source point: before, at the
first actual list-item marker; after, at the following non-list source block's
first physical body start after enclosing parent prefixes. For `Text\n- One`,
the point is [5,5), line 2 column 1; for `- One\n# H`, [6,6), line 2 column 1.
These are diagnostic anchors, not executable insertion instructions. Full source
context is established before suppression at the selected point's start.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
Text
- One
````

Accepted input:

````markdown
Text

- One
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Pass 1 is analysis only. PlannedFix catalog metadata grants no correction authority.
MD047 remains the sole production edit provider. Future corrections may insert
blank lines only if the parsed list structure and tightness are preserved.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
