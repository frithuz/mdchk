# MD007: Bullet list nesting indentation

Status: analysis, configuration and automatic correction implemented for CommonMark and GFM. Items indented with tabs, items in blockquotes and items holding protected content stay manual findings.

Area: [Lists](index.md).

## Behavior

Require each nested bullet list to indent by the configured number of spaces relative to its parent bullet marker. Lists nested within numbered items align to that actual item's content column, with no additional configured indent.

Each actual root bullet marker must have exactly zero container-relative indentation by default, or exactly `indent` when `start_indented` is true. The option applies to roots only. Quote prefixes are excluded from structural indentation; intervening quotes retain actual list ancestry. Each child uses its actual parent marker width and padding, even when the parent itself is misindented or suppressed. A bullet parent with three padding spaces therefore places a directly nested child four spaces from its marker.

The parser decides actual list membership. Four-space root text can be code even with `indent: 4` and `start_indented: true`; the rule does not turn that text into a list. Every positive admitted integer is valid, including 1 and the maximum representable integer. Findings select only the original bullet marker byte.

## Configuration

Default enablement: Enabled.

indent: positive integer, 2; start_indented: boolean, false.

All rules also accept the [shared settings](../index.md#configuration-and-findings). These defaults are implemented. `indent` must be a positive integer and `start_indented` must be a boolean, including when the rule is disabled. Unknown options are rejected.

## Examples

Violating input:

````markdown
- One
   - Two
````

Accepted input:

````markdown
- One
  - Two
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` and `fix --dry-run` move a misindented bullet item to the column MD007
expects, by adding or removing the same number of leading spaces on the item's
marker line and on every later nonblank line up to the item's end: continuation
paragraphs, nested lists and their content, including ordered children. Blank lines
and all bytes after the leading spaces stay as they are, so LF, CRLF and CR endings
and non-ASCII text are kept byte for byte. Ordered items are never targets, but move
with a shifted bullet ancestor. For example:

````markdown
- One
   - Two
     more
````

becomes:

````markdown
- One
  - Two
    more
````

When a nested item and its ancestor are both misindented, one round shifts the
ancestor with its content and the next round regenerates the nested finding, so a
single `fix` run converges.

The finding stays manual, with `fix_available: false`, when any line that would move:

- contains a tab, because its width depends on its column
- has a blockquote prefix, or opens a blockquote inside the item
- is a lazy continuation, indented less than the item's content
- holds protected content, such as fenced or indented code, an HTML block or an
  HTML comment

It also stays manual when the marker is directive-disabled, when the document opens
with an unrecognized front matter block, or when the shift would add more than 16
columns, so a large `indent` can't multiply a file's size.

The edit is applied only when the reparsed candidate keeps the same list structure:
the same items in the same order, with the same parents, lists, kinds, markers and
tight or loose state, and the same block content. A shift that would make an item
indented code, or move it out of its parent list or into a neighbouring one, is
reported under `deferred_fixes` and the file keeps that item unchanged. With
`indent: 1`, for example, a nested item can't reach one column past its parent's
marker without leaving that parent, so its correction is deferred.

When the same run also removes trailing whitespace (MD009), the MD007 shifts follow
in the next round of that run.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
