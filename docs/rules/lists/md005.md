# MD005: Alignment of sibling list items

Status: analysis, configuration and correction implemented for CommonMark and GFM.

Area: [Lists](index.md).

## Behavior

Report sibling list items whose marker indentation differs from the first direct
item in their actual parsed list group. Each group has its own fixed baseline,
including nested groups; returning from a nested group retains its parent
baseline. Hidden or disabled first items still establish original context.

Compare structural marker indentation relative to the enclosing container, after
list and blockquote prefixes: content indentation minus marker width and padding.
Changes in ordered marker width (`9.` versus `10.`), marker padding or outer
container prefixes do not themselves misalign marker starts. Parser membership
determines sibling groups; marker-style changes or intervening blocks may split
groups. Empty, task and definition-only items participate.

Findings select exactly the offending marker: one bullet byte or all ordinal
digits plus their delimiter. They exclude indentation, prefixes, padding and task
checkboxes. A finding is fixable when re-indenting only the offending marker
aligns it: `fix` replaces the spaces before the marker, after any container
prefix, with spaces matching the group's first item. The marker, padding, task
checkbox, content and every other line stay byte-identical, so `- One` followed
by ` - Two` becomes `- One` followed by `- Two`. Other findings are manual, with
`fix_available: false`.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
- One
 - Two
````

Accepted input:

````markdown
- One
- Two
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Align markers only when reparsing preserves sibling membership and item content.
Every list item must keep its group, parent, nesting and content, and the edited
marker must reach the group's baseline indentation; otherwise the correction is
deferred.

A finding stays manual, with `fix_available: false`, when:

- the item's indentation or the first item's indentation contains a tab;
- the item has any line after its first, such as a continuation, lazy or nested
  child line, because those lines would have to move too;
- the item has no indentation to edit, because aligning it would insert spaces
  rather than replace them;
- the edit lies in a directive-disabled interval, protected context or a leading
  front matter block, recognized or not. A disabled or hidden first item still
  sets the baseline.

MD005 corrections wait for a round with no MD009 edit, then apply in a later
round of the same `fix` run.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
