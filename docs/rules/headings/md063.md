# MD063: Heading capitalization

Status: analysis, configuration and correction implemented for CommonMark and GFM. Disabled by default.

Area: [Headings](index.md).

## Behavior

Require visible heading text to follow the configured capitalization convention, preserving code spans and configured proper names.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

style: sentence or title; default sentence; proper_names: string list, empty. Sentence uppercases the first cased letter; title uppercases each word's first cased letter. Neither lowercases protected names.

Only required initials must be uppercase or titlecase. All remaining spelling is
unrestricted; this check never demands lowercasing. Cased scalars use the pinned
Go toolchain's `unicode.IsUpper`, `IsLower` and `IsTitle` categories, rather than
locale rules, full case folding or the broader derived Unicode Cased property.

Sentence style selects the first cased scalar of the entire visible heading.
Title style selects the first cased scalar of each word. Code and exact configured
name initials still consume those positions but are exempt: sentence
`` `lower` guide `` is clean; title style reports the g in guide. Numbers and
uncased letters do not consume a cased position.

Title words contain Unicode letters, marks, numbers and connector punctuation.
ASCII `'` and curly `’` join only when immediately between those base scalars;
other punctuation, symbols and whitespace delimit words. Thus `A_b` is one word,
while `A-b` has two; `Don't Stop` does not require an uppercase t.

Nonempty proper names match exact case-sensitive literal semantic phrases within
one heading. No normalization, markup parsing or entity decoding of option values
occurs. Phrases can cross formatting, links, image alt and code owners; overlapping
matches union protection. Empty names are ignored, and literal multiword, punctuation
or newline names retain ordinary string-list admission. Both exterior neighbors
must be absent or outside the base letter/mark/number/connector classes. This name
endpoint test deliberately treats apostrophes as boundaries even when they join
title words: configured `iPhone` protects `iPhone's` and `iPhone’s`, but does not
protect `myiPhone` or `iPhone_case`.

Use the parser's actual visible text across all body headings and nested containers;
raw payload and protected fake headings do not participate, and metadata does not
invent a virtual heading. Emit at most one finding per violating heading, on its
first unprotected required lowercase initial. Exact text selects the original
scalar byte span; entities and other transformed semantic segments select their
complete atomic source token. Compute full context before directive filtering;
suppressing a chosen finding does not select a later word in the same heading.
These are explicit project comparison choices, not an upstream parity claim.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
## installation guide
````

Accepted input:

````markdown
## Installation guide
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` and `fix --dry-run` uppercase every required lowercase initial of a
reported heading in one edit group: the first cased initial under sentence style,
and each word's under title style, exactly the scalars the check treats as
violations. Each one becomes its `unicode.ToTitle` form, so `ǆ` becomes the
titlecase `ǅ`. Nothing is ever lowercased, and no other spelling changes:
`HELLO world` stays as it is.

A heading is corrected whole or not at all. Its finding has `fix_available: true`
only when every required initial passes all of these checks; otherwise the heading
stays unchanged and its finding is reported with `fix_available: false`:

- The initial is a literal source scalar. An initial written as an entity, numeric
  reference, escape or other transformed segment is never rewritten.
- It isn't autolink text, which is also the link's destination: `<http://a.b/c>`
  and GFM bare links never change, so a title-style heading containing one stays
  manual.
- Its titlecase form is a different single uppercase or titlecase scalar. `ß`, for
  example, has none.
- With nonempty `proper_names`, its title-style word neither contains nor sits next
  to a protected name, and overlaps no span matching a configured name under simple
  case folding. `iPhone` defers `## iphone setup` and title-style `# iPhone case`,
  but `## setup for iPhone` still becomes `## Setup for iPhone`.
- Its edit is allowed in context: not in code, raw HTML, comments, front matter or
  other protected content, not where a directive disables MD063, and not in a
  document with unreliable syntax, parse uncertainty or an unrecognized opening
  `---` or `+++` block. A heading that no blank line separates from recognized front
  matter also stays manual.

Code spans are never edited, though a later word in the same heading can still be
corrected under title style. Locale-specific casing and multi-scalar case mappings
are out of scope. Findings suppressed by directives are not corrected. MD063 waits
for MD009, MD019 and MD021 corrections in the same run, then applies in a later
round of the same `fix`, so the run still ends with no further changes.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
