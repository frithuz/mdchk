# MD022: Blank lines around headings

Status: analysis and configuration implemented for CommonMark and GFM. This rule is report-only; automatic correction remains future work.

Area: [Headings](index.md).

## Behavior

Require configured blank body lines before and after headings, except at document boundaries. Container prefixes do not count as body content. Counts are minimum consecutive blank body lines; extra blanks pass, and zero disables that side. A blank body contains only ASCII spaces and tabs after that physical line's actual parser-owned quote/list prefixes. NBSP, NUL, comments and marker-looking prose remain content. An actual marker-only empty list item can count as blank body. Lazy continuation acquires no invented prefix.

Count from the whole actual ATX or Setext heading, including empty headings and all multiline Setext text plus its underline. Container transitions neither waive a side nor stop its blank run: evaluate each neighbor using that neighbor's own actual prefixes. Heading-like text in code, raw HTML, comments or recognized metadata is excluded; protected content adjacent to a real heading still counts as surrounding body content.

A side is exempt when its outward adjacent blank run reaches actual BOF or EOF before any nonblank body line, even if shorter than the configured minimum. A terminal line ending creates no extra selectable blank line. Container boundaries and the end of a recognized header are not document edges. Header recognition off follows the selected flavor's actual parsing; unreliable required syntax produces reduced coverage.

Emit one finding per deficient side, before then after. The original zero-width before point is the first heading physical line's content start, ahead of container prefixes. The after point is the last heading physical line's content end, including trailing padding and before its ending; Setext uses the underline's end. Consecutive headings retain distinct side observations. Directive suppression follows each point's start, so an inline directive within a heading can suppress its after observation independently. These points are diagnostic anchors and grant no insertion authority.

## Configuration

Default enablement: Enabled.

before: nonnegative integer, 1; after: nonnegative integer, 1.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the implemented analysis contract.

## Examples

Violating input:

````markdown
Text
## Install
Text
````

Accepted input:

````markdown
Text

## Install

Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

For `Text<NEWLINE>## Install<NEWLINE>Text`, report before at byte 5 (line 2, column 1) and after at byte 15 (line 2, column 11). For `# A<NEWLINE># B`, report after A at byte 3 (line 1, column 4) and before B at byte 4 (line 2, column 1); the outer document sides are exempt.

With `before: 2` and `after: 2`, `<NEWLINE># H<NEWLINE><NEWLINE>Text` waives before because the single leading blank reaches BOF, but reports after because one blank before Text is short. A parser-owned prefix-only `>` line can provide one blank body line across a quote boundary.

## Correction policy

Future correction: insert required blank lines while retaining blockquote and list container prefixes.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
