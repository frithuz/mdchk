# MD022: Blank lines around headings

Status: analysis, configuration and correction implemented for CommonMark and GFM.

Area: [Headings](index.md).

## Behavior

Require configured blank body lines before and after headings, except at document boundaries. Quote prefixes and item indentation do not count as body content. Counts are minimum consecutive blank body lines; extra blanks pass, and zero disables that side. A blank body contains only ASCII spaces and tabs after that physical line's actual parser-owned quote prefixes and item indentation. A list marker is content and is not removed when deciding whether a line is blank, so a marker-only empty list item is nonblank: it stops a blank run, and a run cannot reach a document edge through it. A quote opened after a marker, such as `- >`, leaves the line blank. NBSP, NUL, comments and marker-looking prose remain content. Lazy continuation acquires no invented prefix.

Count from the whole actual ATX or Setext heading, including empty headings and all multiline Setext text plus its underline. Container transitions neither waive a side nor stop its blank run: evaluate each neighbor using that neighbor's own actual prefixes. Heading-like text in code, raw HTML, comments or recognized metadata is excluded; protected content adjacent to a real heading still counts as surrounding body content.

A side is exempt when its outward adjacent blank run reaches actual BOF or EOF before any nonblank body line, even if shorter than the configured minimum. A terminal line ending creates no extra selectable blank line. Container boundaries and the end of a recognized header are not document edges. Header recognition off follows the selected flavor's actual parsing; unreliable required syntax produces reduced coverage.

Emit one finding per deficient side, before then after. The original zero-width before point is the first heading physical line's content start, ahead of container prefixes. The after point is the last heading physical line's content end, including trailing padding and before its ending; Setext uses the underline's end. Consecutive headings retain distinct side observations. Directive suppression follows each point's start, so an inline directive within a heading can suppress its after observation independently. These points are diagnostic anchors and grant no insertion authority; a correction inserts at physical line boundaries instead.

## Configuration

Default enablement: Enabled.

before: nonnegative integer, 1; after: nonnegative integer, 1.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the implemented analysis contract.

## Examples

Violating input:

````markdown
Text
## Install
Text
````

Accepted input:

````markdown
Text

## Install

Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

For `Text<NEWLINE>## Install<NEWLINE>Text`, report before at byte 5 (line 2, column 1) and after at byte 15 (line 2, column 11). For `# A<NEWLINE># B`, report after A at byte 3 (line 1, column 4) and before B at byte 4 (line 2, column 1); the outer document sides are exempt.

With `before: 2` and `after: 2`, `<NEWLINE># H<NEWLINE><NEWLINE>Text` waives before because the single leading blank reaches BOF, but reports after because one blank before Text is short. A parser-owned prefix-only `>` line can provide one blank body line across a quote boundary.

## Correction policy

`fix` inserts the missing blank lines on each deficient side, up to the configured minimum. It never removes or changes an existing line, and exempt sides, a `0` setting and sides already at the minimum get no edit. For the before side, the lines go at the start of the heading's first physical line; for the after side, at the start of the line that follows the heading.

Each inserted line is the heading line's own blockquote prefix with its trailing spaces and tabs removed, followed by the nearest original line ending, so CRLF input gets CRLF lines and MD009 never flags them. `> Text<NEWLINE>> ## H<NEWLINE>> Text` becomes `> Text<NEWLINE>><NEWLINE>> ## H<NEWLINE>><NEWLINE>> Text`, and a heading outside any quote gets empty lines. When one heading's after side and the next heading's before side share a boundary, the larger shortfall is inserted once, so `# A<NEWLINE># B` becomes `# A<NEWLINE><NEWLINE># B`.

The finding stays manual, with `fix_available: false`, when:

- the heading is inside a list item, because a blank line between item children can make a tight list loose;
- the neighbouring line doesn't carry the heading's quote prefix, such as a lazy continuation line or a different quote;
- the neighbouring line is or touches fenced or indented code, raw HTML, a comment or front matter, or the document opens with an unrecognized block;
- the anchor is suppressed by a directive, or the parse is uncertain;
- the shortfall is larger than the whole document.

When another correction in the same round conflicts with the insertion, the planner applies one of them, by catalog rule order and then proposal ID, and the other waits for the next round. MD022 sorts before MD023, so its blank line goes first and the indentation is removed in the next round. A trusted checker reparses the candidate and requires the same headings, with the same level, style, text and containers, the same block and inline meaning, and exactly the expected pure insertion of prefix-only lines.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
