# MD026: Punctuation at heading ends

Status: analysis and configuration implemented for CommonMark and GFM. Disabled by default; report-only, with no edits or previews.

Area: [Headings](index.md).

## Behavior

Report configured punctuation at the end of visible heading text, excluding a closing code span's internal punctuation.

Select only the final non-whitespace Unicode scalar of the parser's visible
heading text. Trim CommonMark Unicode whitespace (Zs plus TAB, LF, FF and CR),
including NBSP; VT, NEL, LS, PS and zero-width space remain significant.
Formatting, link labels and image alt text retain their visible contribution;
destinations, titles, raw tags, comments and active raw payload do not.
A terminal code-span or escaped scalar is excluded without falling back to
earlier punctuation. Whitespace-only trailing code can trim away first.

Report one original token: the selected literal rune's bytes, or the entire
atomic character reference. Multi-scalar references use only their final scalar
for membership. Normalized NUL uses U+FFFD semantically and its original byte
for the range. Findings use the original token start for directive suppression.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

punctuation: string, .,:;!?; default is those six characters.

Membership is exact Unicode scalar membership, without normalization, folding or
category restrictions. Duplicate scalars are immaterial; an empty string is valid
and matches nothing. Configured trim-class whitespace cannot become a candidate.
A final nonmatching scalar blocks earlier configured punctuation.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
## Installation!
````

Accepted input:

````markdown
## Installation
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; punctuation may carry meaning.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
