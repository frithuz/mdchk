# MD024: Repeated heading text

Status: analysis and configuration implemented for CommonMark and GFM; report only.

Area: [Headings](index.md).

## Behavior

Report duplicate normalized heading text. Strip formatting, collapse whitespace, and compare case-insensitively.

Semantic text retains decoded literal/code text, link labels and image alternative
text while excluding formatting wrappers and opaque raw HTML payload. Trim and
collapse CommonMark Unicode whitespace (Zs plus TAB, LF, FF and CR) to one ASCII
space, then apply Unicode 17.0.0 full default case folding. No Unicode composition,
accent removal, punctuation stripping or anchor slug generation is performed.
For example, Straße and STRASSE match; composed é and decomposed e plus an acute
accent remain distinct. Entity and escape decoding happens once in the parser.

The empty normalized key participates. Each occurrence after the first in its
comparison scope reports `Heading text must not repeat.` The default scope is the
whole document. With `siblings_only: true`, the parent is the nearest preceding
strictly shallower actual heading, identified by its occurrence rather than its
text, or the document root. Skipped levels introduce no synthetic parent. Headings
of different levels can share a parent, and containers do not reset the outline.
Suppressed and configured-off earlier headings still establish comparison and
parent context when the rule is enabled later.

The diagnostic selects the complete original raw label, including inline markup,
but excludes outer hashes, closing hashes, Setext underlines, outer padding and
the terminal ending. Multiline Setext labels include unavoidable interior endings
and container prefixes. Raw-empty ATX headings use a zero-width point immediately
after the opening hash run; semantic-empty headings with raw markup retain that
markup range. For `## Install\n\n## install`, only the second label is reported:
bytes [15,22), line 3 columns 4–11, with an exclusive end.

These normalization, parent, empty-key and label choices are reasoned local
interpretations of the shared structural-diagnostic contract.

## Configuration

Default enablement: Enabled.

siblings_only: boolean, false; when true, compare headings sharing a parent heading.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
## Install

## Install
````

Accepted input:

````markdown
## Install

## Usage
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; renaming sections requires author intent.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Analysis preserves original bytes and produces no edits, previews or corrected content. Renaming and correction validation remain outside this report-only rule.
