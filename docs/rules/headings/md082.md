# MD082: Sections without content

Status: analysis and configuration implemented. Correction remains manual.

Area: [Headings](index.md).

## Behavior

Report a heading with no substantive body content before the next heading of equal or higher level. Child sections count as content; comments and blank lines do not.

Use one global source-ordered outline of actual headings per document, including
headings in quotes and lists and headings hidden by directives. The next deeper
heading itself supplies content to its parent, even when that child is empty.
A heading's own inline label never supplies its body. With `allow_final_section:
true`, only the globally last actual heading is exempt; hidden later headings
still determine finality. There is no virtual frontmatter title.

Substantive content includes nonwhitespace semantic Text (using the parser's
CommonMark whitespace definition), code blocks/spans, images, thematic breaks,
tables, actual task checkboxes and noncomment HTML objects, including empty
objects. Formatting and links are wrappers: an empty link alone does not count.
Empty quote/list shells, removed reference definitions and unprotected confirmed
comments do not count. Entity-produced spaces/NBSP remain whitespace; escaped or
code-protected comment-looking text retains its actual syntax meaning. Confirmed
comment tails use actual owned content, so container prefixes are never body.
Protected comments in an existing raw HTML context remain authored HTML content.

Findings select the complete original raw heading label, including a present point
for an empty ATX label. Context is resolved before original-start directive
filtering. Anchor style and HTML-ID availability have no effect on this check.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

allow_final_section: boolean, false.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The sole rule-specific option is `allow_final_section`, default `false`.

## Examples

Violating input:

````markdown
## Install

## Usage
Text
````

Accepted input:

````markdown
## Install
Instructions.

## Usage
Text
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; the section may need content or removal.

MD082 produces no edits or preview authority. When MD047 supplies a newline-only
candidate, MD082 rechecks that candidate and reports remaining manual findings
against its actual snapshot and original label geometry.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
