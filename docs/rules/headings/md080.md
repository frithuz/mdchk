# MD080: Colliding heading anchors

Status: analysis and configuration implemented for CommonMark and GFM. Disabled by default; report-only, with no edits or previews.

Area: [Headings](index.md).

## Behavior

Report headings whose unsuffixed anchor bases collide, even if the renderer would disambiguate them by appending numeric suffixes.

Use the [anchor contract](../index.md#anchor-resolution).

Use the same shared anchor policy as MD051 and MD073. This rule compares heading anchor bases only; it is not a general duplicate-ID check for arbitrary nonheading nodes.

The first occurrence of each exact unsuffixed base is clean; report every later
heading with that base, on its complete original raw label. An empty raw heading
has a legitimate point label. All actual headings participate across containers
and hidden/configured-off intervals before directive filtering; state resets per
document. No metadata title is invented.

Use the shared index's present Base even when empty or its allocated ID is unusable.
For example, punctuation-only headings can collide on an empty base. Allocated
suffixes and arbitrary nonheading HTML IDs do not establish heading-base equality.
`A` and `A-1` have distinct bases; HTML IDs occupying `a` do not change A/A equality.

This is the existing shared anchor algorithm, not MD024 full case folding or a new
renderer: Unicode lower mapping, punctuation filtering, retained symbols, whitespace
and non-normalized combining forms retain their documented anchor meanings.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

No rule-specific options. Anchor policy is shared through [`resources.anchor_style`](../../configuration.md#shared-resource-settings), default `github`.

Both `github` and `explicit` policy selections are admitted locally. Under current
`explicit` policy, Markdown headings have no supported explicit-heading records,
so their bases are absent and a complete index produces no finding. Arbitrary HTML
IDs are not treated as explicit Markdown heading IDs. Removed attribute syntax is
not revived.

A complete index is required. If required HTML/parse context is unavailable or
uncertain (including filtered GFM script HTML), report reduced coverage and no
dependent collision findings. Do not invent fallback slugs. An available empty or
absent-base index can be clean; an unavailable index cannot prove that result.
Policy and original source ownership carry through candidate analysis. Local
anchor selection does not enable `resources.index_file` or cross-file resource
reads. These empty/absent and later-occurrence choices are explicit project policy.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
## Hello!

## Hello
````

Accepted input:

````markdown
## Hello!

## Welcome
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; changing headings or anchors affects links.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
