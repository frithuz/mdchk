# MD003: Heading syntax style

Status: analysis, configuration and delimiter-style corrections implemented for CommonMark and GFM.

Area: [Headings](index.md).

## Behavior

Require one heading syntax throughout a document or the configured syntax.
In consistent mode, the first actual Markdown heading chooses one exact style
for the whole document: open ATX (`# Title`), closed ATX (`# Title #`), or
Setext. Empty headings count: `#` is open and `# #` is closed. Actual parser
closing markers determine style; escaped or nonclosing hashes are content, and
closing run width need not match the opening run.

The baseline never resets after a violation or at quote/list boundaries. Earlier
headings retain this context even when suppressed or initially disabled before a
permitted enable directive. Recognized YAML/TOML metadata titles never establish
a baseline. Code, raw HTML, comments and recognized opaque headers do not supply
Markdown headings. With header recognition disabled, ordinary Markdown parsing
applies; unreliable parsing produces reduced coverage rather than guessed styles.

Explicit styles apply from the first heading. Setext permits H1/H2 only: every
ATX H3–H6 is a mismatch under `setext`, including when the first Setext heading
selects that style in consistent mode. Documents with no headings pass.

Emit one finding per mismatched heading over its complete original structural
envelope, including multiline Setext text and underline, original line endings
or EOF. Container prefixes follow parser-provided ranges. Public coordinates
use Unicode code-point columns, count tabs as one column and have exclusive ends.
Analysis preserves source bytes. A finding has `fix_available: true` only when
the correction policy below can rewrite the heading's delimiters and every edit
is outside protected content, front matter and disabled directive intervals.

## Configuration

Default enablement: Enabled.

style: consistent, atx, atx_closed, or setext; default consistent. Setext permits only H1 and H2.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
# Guide

Install
-------
````

Accepted input:

````markdown
# Guide

## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Convert only heading delimiters while preserving level and inline content bytes:

- Open ATX to closed ATX appends one space and a closing run as wide as the opening run: `## A` becomes `## A ##`.
- Closed ATX to open ATX removes the parser's closing run and the whitespace before it.
- ATX H1/H2 to Setext removes the opening run and its separator, plus any closing run, and adds an underline line after the heading: `=` for H1, `-` for H2. The underline is as many characters as the content has code points, at least 3, and repeats the heading line's block quote prefix and line ending.
- Single-line Setext to ATX prefixes the text with `#` or `##` and one space, adds a closing run for `atx_closed`, and removes the underline line with its line ending.

These cases stay reported with `fix_available: false`:

- ATX H3–H6 under `setext`, and empty headings under `setext`.
- Setext headings with multiline text.
- Content whose trailing `#` run would become a closing sequence, such as `Foo #` converted to ATX.
- Content that could start another block once it stands alone, such as a list marker, `>`, `#`, `=`, `-`, `[`, a fence or HTML, when converting to Setext.
- An ATX heading converted to Setext when the previous line isn't blank, since the text could join a paragraph, or when the heading line has no line ending.
- ATX headings inside list items converted to Setext, and block quote prefixes that don't match the heading's containers, such as lazy continuation.
- Headings inside or overlapping front matter, recognized or not, protected content, or a disabled directive interval.

Edits keep every original line ending and change no bytes outside the delimiters. The MD003 checker proves that the corrected document reparses with the same block structure and the same headings, levels, inline text, containers and anchors, and that each changed heading now has the target style. MD003 edits wait for a round in which no MD009, MD019, MD021 or MD047 edit is proposed, so one `fix` run applies all of them without overlapping edits.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Analysis fixtures also verify first-style retention, empty headings, real closing markers, directives and unchanged source. Correction tests cover every `style` value, including each `consistent` baseline, precise edit spans, LF and CRLF, Unicode underline widths, block quote and list containers, the deferrals above, forged groups the checker rejects, composition with MD009, MD019, MD021 and MD047, and a second fix run with no further changes.
