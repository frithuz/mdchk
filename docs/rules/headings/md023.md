# MD023: Indented headings

Status: analysis, configuration and automatic correction implemented for CommonMark and GFM. Partially consumed tabs and lazy lines stay manual findings.

Area: [Headings](index.md).

## Behavior

Report indentation before parsed headings relative to their enclosing container's content column.

Assess every actual physical heading line: the ATX line, or all Setext text,
continuation and underline lines. Any positive indentation after that line's
actual matched container prefixes produces one finding per heading. Container
padding belongs to the container; partially consumed tabs can still leave leaf
indentation. Missing prefixes on lazy lines are not synthesized.

The finding covers the full opening hash marker for ATX or the full underline
marker for Setext, even when a text line triggered it. Directive suppression uses
that marker's start. Removed reference definitions and ordinary paragraphs or
tables do not contribute heading indentation. Empty headings still participate.
Four-column indented code, fenced code, raw HTML, comments and recognized headers
retain their parser ownership. Unreliable required syntax reduces coverage.

For example, `> # H` and `-  # H` pass; `>  # H` and a quote prefix followed by a
partially consumed tab and `# H` violate. `Alpha`, an indented continuation and
`===` form one Setext finding on `===`.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
 ## Install
````

Accepted input:

````markdown
## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

`fix` and `fix --dry-run` delete the leaf indentation on every physical heading
line: the ATX line, or each Setext text, continuation and underline line. Each
deleted span starts right after the line's matched container prefixes and their
padding and ends before its first non-indentation byte, so ` ## Install` becomes
`## Install`, `>  # H` becomes `> # H`, and a list continuation `   # H` under
`- Text` becomes `  # H`. Container prefixes, container padding, line endings and
all other bytes stay. A whole tab that the line consumes is deleted whole. All of a
heading's deletions form one group, applied or deferred together, so a Setext
heading is never half corrected.

A heading's finding has `fix_available: false`, and the heading is not edited, when:

- a deleted span would start inside a tab that the container prefix already partly
  consumed, such as a quote prefix followed by a tab and `# H`;
- a heading line is a lazy continuation line missing its container prefix; mdchk
  doesn't synthesize the prefix;
- a span lies in protected context, or the finding's marker start lies in a
  directive-suppressed interval or MD023 is otherwise disabled there;
- the document opens with a complete `---` or `+++` block that isn't recognized,
  because `frontmatter.enabled` is false or the block's format isn't in
  `frontmatter.formats`. Recognized front matter stays byte-identical, and the body
  after it is still corrected.

A conflicting group is deferred by shared proposal validation and the heading stays
reported. An independent checker reparses the candidate and rejects the group
unless only heading indentation changed: the block tree, container structure and
membership, every heading's level, style, text and containers stay the same, and
the corrected heading no longer produces an MD023 finding. MD023 composes with
MD009, MD019, MD021 and MD047 corrections in the same run.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Correction tests cover preview and saved modes, precise edit spans, partial and whole tabs, Setext multi-line headings, lazy lines, directives, front matter, forged proposals, composition with MD009, MD019, MD021 and MD047, preserved meaning and a second fix run with no further changes.
