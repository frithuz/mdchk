# MD023: Indented headings

Status: analysis and configuration implemented for CommonMark and GFM. Automatic correction remains future work.

Area: [Headings](index.md).

## Behavior

Report indentation before parsed headings relative to their enclosing container's content column.

Assess every actual physical heading line: the ATX line, or all Setext text,
continuation and underline lines. Any positive indentation after that line's
actual matched container prefixes produces one finding per heading. Container
padding belongs to the container; partially consumed tabs can still leave leaf
indentation. Missing prefixes on lazy lines are not synthesized.

The finding covers the full opening hash marker for ATX or the full underline
marker for Setext, even when a text line triggered it. Directive suppression uses
that marker's start. Removed reference definitions and ordinary paragraphs or
tables do not contribute heading indentation. Empty headings still participate.
Four-column indented code, fenced code, raw HTML, comments and recognized headers
retain their parser ownership. Unreliable required syntax reduces coverage.

For example, `> # H` and `-  # H` pass; `>  # H` and a quote prefix followed by a
partially consumed tab and `# H` violate. `Alpha`, an indented continuation and
`===` form one Setext finding on `===`.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
 ## Install
````

Accepted input:

````markdown
## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Future correction may remove excess indentation only if container membership is unchanged. Current findings are report-only: no edits, previews or corrected documents.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Future correction validation must verify preserved meaning and a second fix run with no further changes.
