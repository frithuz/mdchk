# MD018: Missing space after opening hashes

Status: analysis and configuration implemented for CommonMark and GFM. Report-only; no edits, previews or corrected content.

Area: [Headings](index.md).

## Behavior

Report a line beginning with one to six unescaped hashes followed immediately by text, when it is a heading candidate rather than a parsed code or literal block.

A candidate is an original physical line finally owned by an ordinary paragraph,
after actual quote/list prefixes and fewer than four structural indentation
columns. Ordinary and lazy continuation lines participate using their actual
retained line start. A deeply indented continuation remains paragraph content,
but falls outside this candidate grammar. Tabs use their physical structural
column phase; diagnostic columns count Unicode code points.

The opening run must be maximal: seven or more hashes do not supply a six-hash
prefix. Bare hashes and hashes followed by ASCII space, tab or a line ending are
accepted. A preceding backslash prevents an opening run; a backslash after the
run does not escape preceding hashes. NBSP and em-space are text. `#5`,
`#hashtag`, `#\#` and `##text##` all lack the required separator. There are no
number or hashtag exemptions, and trailing hashes do not repair the opener.

Preserve valid parser ownership: exclude ATX and Setext headings (including
paragraphs later promoted to Setext), reference definitions and their fields,
link destinations/titles, and GFM table rows/cells. For example, `##Title\n===`
is a valid Setext title and is excluded; `##Title | value\n--- | ---` belongs
to a GFM table and is excluded there, while CommonMark treats it as paragraph
text and reports the opening run. These deliberate exclusions do not reduce
coverage.

Exclude runs overlapping actual code spans, raw HTML, comments or literal
regions, including multiline forms. Testing only the insertion point is
insufficient when it lies on a protection boundary. Recognized opaque YAML/TOML
headers are excluded; disabled recognition follows ordinary Markdown ownership.
Unreliable required parsing produces explicit incomplete coverage.

Report one zero-width original-source point immediately after the entire run.
`##Install` reports byte range `[2,2)`, line 1 column 3; `> ##雪` reports
`[4,4)`, column 5; `> - ##雪` reports `[6,6)`, column 7. Both range ends coincide.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
##Install
````

Accepted input:

````markdown
## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; converting ordinary text into a heading requires intent.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Reusable fixtures cover lexical boundaries, paragraph and final-construct ownership, nested containers and lazy continuations, multiline protection, header recognition, directives and inherited denials, LF/CRLF/CR/EOF, and exact original points. Analysis leaves source bytes unchanged and offers no automatic correction.
