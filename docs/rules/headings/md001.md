# MD001: Heading increments

Status: analysis and configuration implemented for CommonMark and GFM. Report only; no automatic correction.

Area: [Headings](index.md).

## Behavior

Report a heading whose level exceeds the preceding heading level by more than one. A decrease may skip levels; the first heading establishes the starting level.

Only the exact top-level title key with a decoded nonblank string counts. Missing, blank or non-string title values do not count. The existing frontmatter_title options remain opt-in; MD001 uses a virtual H1, MD025 counts one title at its configured title level, and MD041 accepts the title as satisfying its existing opening-heading requirement.

See the [metadata contract](../../engineering/frontmatter.md#metadata-values-and-corrections).

## Configuration

Default enablement: Enabled.

frontmatter_title: boolean, false; when true, a recognized title acts as H1.
Header recognition must be independently enabled. Known missing, blank and
non-string titles add no baseline. An unavailable title reduces affected coverage;
reliable later body-to-body comparisons still run. With the option false, metadata
is not decoded.

All rules also accept the [shared settings](../index.md#configuration-and-findings). These defaults are the mdchk contract.

## Examples

Violating input:

````markdown
# Guide
### Install
````

Accepted input:

````markdown
# Guide
## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.
