# MD090: Horizontal rules before headings

Status: analysis and configuration implemented. Correction remains manual.

Area: [Headings](index.md).

## Behavior

Report a thematic break whose next nonblank body block is a heading in the same container. With `allow_slides: true`, exempt documents matched by `documents.slides`; false checks them normally. No filename or syntax implicitly marks slides. See the [slide contract](../../engineering/integrations.md#slide-documents).

Same container means direct actual body-block siblings in one document, quote or
list item. Blank lines and removed reference definitions are absent; an actual
comment block or any other intervening block interrupts adjacency. Containers are
not flattened and separate list items do not form pairs. Multiple separators before
a heading report only the last adjacent separator. Actual parser precedence and
protected code/HTML determine whether a heading or thematic break exists.

Each finding selects the original span from the first thematic marker through the
last marker, including internal spacing but excluding indentation, container
prefixes, trailing whitespace and line ending. Full context precedes directive
filtering at the chosen start. This differs from MD082's substantive-content policy.

Slide patterns annotate only selected documents and use case-sensitive direct
matching relative to the selected configuration directory. The first match is
retained for inspection; directory-only patterns do not inherit to descendants.
Outside-base targets and unmatched documents remain ordinary. No filename,
frontmatter field or separator syntax implicitly marks slides. Known matched slides
with `allow_slides: true` intentionally make MD090 inapplicable before its syntax
prerequisite; independent source/parser/operation failures remain visible.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

allow_slides: boolean, true.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The sole rule-specific option is strict boolean `allow_slides`, default `true`.

## Examples

Violating input:

````markdown
***

## Install
````

Accepted input:

````markdown
## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; removing a separator can change intended layout.

MD090 produces no edits or preview authority. When MD047 proposes a newline-only
candidate, MD090 rechecks that actual candidate with the same selected slide policy
and option, and reports remaining manual findings on its candidate snapshot.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
