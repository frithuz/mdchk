# MD025: Multiple document titles

Status: analysis and configuration implemented for CommonMark and GFM. Report-only; no edits or previews.

Area: [Headings](index.md).

## Behavior

Report the second and every later actual heading at the configured title level. Other levels do not count or reset the baseline. All containers share one document-wide count; hidden or configured-off headings still establish context. Empty headings count.

With `frontmatter_title: true`, a recognized title counts once at the configured level. Unknown title semantics reduce coverage and withhold the first body title comparison; second and later matching body headings remain certain duplicates. Known positive titles count even beside unrelated metadata uncertainty. Recognition remains independently configured.

Findings cover complete original raw heading labels, preserving inline markup and interior multiline gaps. Raw-empty ATX headings use the end of the opening marker. Directive filtering uses the original label start.

Only the exact top-level title key with a decoded nonblank string counts. Missing, blank or non-string title values do not count. The existing frontmatter_title options remain opt-in; MD001 uses a virtual H1, MD025 counts one title at its configured title level, and MD041 accepts the title as satisfying its existing opening-heading requirement.

See the [metadata contract](../../engineering/frontmatter.md#metadata-values-and-corrections).

## Configuration

Default enablement: Enabled.

level: integer 1 through 6, 1; frontmatter_title: boolean, false.

All rules also accept the [shared settings](../index.md#configuration-and-findings). These defaults are implemented.

## Examples

Violating input:

````markdown
# Guide

# Usage
````

Accepted input:

````markdown
# Guide

## Usage
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.
