# MD021: Extra spaces within closed headings

Status: analysis and configuration implemented for CommonMark and GFM. Report-only; automatic corrections remain future work.

Area: [Headings](index.md).

## Behavior

Require exactly one literal U+0020 (ASCII space) in each delimiter gap of a
parser-confirmed closed ATX heading. Tabs neither count nor expand; one ASCII
space accompanied by tabs passes. Other Unicode spaces remain heading content.
Open ATX, Setext and malformed terminal-hash candidates are outside this rule.

Raw nonempty content has two gaps: after the opening hashes and before the
closing hashes. Raw-empty closed headings have one shared gap, checked once.
Raw content remains nonempty even when its visible text is empty, such as an
inline comment or an empty-label link. Unlike MD019, MD021 has no empty-heading
exemption. A zero-byte gap cannot form a parsed closer.

For excess spaces, report the smallest contiguous range from the second through
the last ASCII space, excluding edge tabs. Intervening tabs may lie inside that
range. A tab-only gap reports a zero-width point after the opening hashes or
before the closing hashes; an empty shared gap uses the opening point.

[MD019](md019.md) independently checks opening gaps of all raw-nonempty ATX
headings, including closed ones. When both rules are enabled, the same opening
excess can produce both IDs. Enablement and directive suppression apply to each
ID independently.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the implemented analysis contract.

## Examples

Violating input:

````markdown
## Install  ##
````

Accepted input:

````markdown
## Install ##
````

`#   #` reports one shared-gap excess; `#<TAB>#` reports one missing-space
point. `#<TAB>Title<TAB>#` reports opening and closing missing-space points.
`#<TAB><SPACE><TAB>Title<TAB><SPACE><TAB>#` passes.

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Future work: normalize delimiter spacing without changing the heading text.
Analysis currently produces no edits, previews or corrected content.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.
