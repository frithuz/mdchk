# MD020: Missing spaces within closed headings

Status: analysis and configuration implemented for CommonMark and GFM. Report-only; no edits or previews.

Area: [Headings](index.md).

## Behavior

Report a parser-confirmed open ATX heading whose maximal terminal raw hash run
lacks a separating ASCII space or tab. Require a valid opening prefix; Setext,
missing-opening-space candidates, escaped openers and seven-hash openers are
outside this rule. A genuine parser closing marker already supplies a separator,
so `# literal### ##` passes, including its literal content hashes.

Any positive terminal width is eligible, including seven or more hashes and
widths unequal to the opening. Trailing ASCII space/tab padding and physical line
endings do not move the candidate. NBSP before the run is content; NBSP after it
means the hashes are not terminal. Inspect original raw bytes, never decoded
entities or visible heading text.

Count original consecutive backslashes immediately before the first hash. Odd
parity conservatively excludes the entire maximal run, including any later hash
suffix; even parity can remain eligible. Thus `# text\###` passes and
`# text\\###` violates (one and two literal backslashes respectively). This is
an intentional ambiguity boundary under the [candidate policy](../../engineering/rule-behavior.md#malformed-syntax-candidates),
not an upstream-prescribed algorithm for malformed closers.

Exclude any run overlapping actual code, raw HTML, comments or literal ownership,
including active raw-text regions. Completed protected syntax adjacent to an
unprotected terminal run does not exclude it: `# ` followed by `` `x`### ``
violates. Recognized opaque headers do not supply body headings; disabling header
recognition follows ordinary Markdown ownership. Unreliable syntax retains
explicit reduced coverage.

Report one original zero-width point immediately before the entire run:
`## Install##` uses bytes `[10,10)`, line 1 column 11; `> - ## 雪##` uses
`[10,10)`, line 1 column 9. Coordinates, source validation and directive suppression
use the shared engine contract.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
## Install##
````

Accepted input:

````markdown
## Install ##
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; the terminal hashes may be intentional heading content.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. Analysis leaves source/configuration bytes unchanged and returns no edits, previews or corrected documents. Correction validation remains future work.
