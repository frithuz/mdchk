# MD036: Emphasis used as a heading

Status: analysis and configuration implemented for CommonMark and GFM. Disabled by default; report-only, with no edits or previews.

Area: [Headings](index.md).

## Behavior

Report a paragraph consisting entirely of bold or italic text on one source line when followed by ordinary body text, as a possible simulated heading.

Use a conservative structural interpretation: the paragraph's trimmed raw payload
must be exactly one outer bold or italic span, with nonblank text and only nested
bold, italic or text inside it. Separate adjacent spans, outside text/comments,
and code, links, images, HTML or GFM strikethrough inside are excluded. Nonblank
uses CommonMark whitespace (Zs plus TAB/LF/FF/CR), without new normalization.
The original payload must occupy one physical source line; line endings and
outer indentation/padding are excluded. A multiline paragraph does not qualify.

The immediately next block must be an ordinary paragraph in the same immediate
container. It must contain nonblank prose outside bold, italic, links, images,
code and raw HTML payload; mixed formatting or code alongside prose is allowed.
Blank separator lines and actual container prefixes are allowed. Do not skip
reference definitions, comments, other blocks, a container boundary or EOF to
find prose. Another entirely emphasized paragraph is not ordinary body text.
GFM task-label paragraphs are excluded as both candidates and followers.

Report the complete original outer emphasized span, including both delimiter
markers and excluding container prefix, indentation, padding and ending. Its
original start governs directive suppression. These conservative choices avoid
inferring heading level or author intent from mixed inline content.


## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
**Install**

Run the command.
````

Accepted input:

````markdown
## Install

Run the command.
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; heading level and author intent are unknown.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
