# MD041: Opening document heading

Status: analysis and configuration implemented for CommonMark and GFM. Enabled by default; report-only, with no edits or previews.

Area: [Headings](index.md).

## Behavior

Require the first nonblank body block to be a heading at the configured level. Skip recognized frontmatter and introductory comments.

Inspect the first actual document-root body block. A heading inside a quote or
list does not satisfy this requirement, and a later heading cannot rescue an
earlier body block. Actual ATX and Setext headings count even with empty visible
text. Reference definitions have no body block and are naturally omitted.

Skip an introductory block only when its entire original envelope consists of
actual unprotected HTML comments plus ASCII space, tab, CR or LF. Multiple
comments and a confirmed unclosed comment through EOF can qualify; do not skip
comments mixed with prose/other HTML or comment-looking code/raw payload.
Recognized frontmatter is outside the body; disabled recognition uses ordinary
Markdown parsing. Unreliable syntax remains explicit incomplete coverage.

Emit at most one zero-width finding at the first considered body block's
original start, including for a wrong-level heading. Empty, blank-only,
comment-only, reference-only or header-only bodies use original EOF. The point
is an insertion location, not a heading-label range; its original start governs
directive suppression. These structural choices define this project's scope.

Only the exact top-level title key with a decoded nonblank string counts. Missing, blank or non-string title values do not count. The existing frontmatter_title options remain opt-in; MD001 uses a virtual H1, MD025 counts one title at its configured title level, and MD041 accepts the title as satisfying its existing opening-heading requirement.

A correct opening body heading already satisfies the rule without decoding
irrelevant metadata. Otherwise, with the title option enabled, a known valid
title satisfies the rule at any configured level; known absence retains the
normal missing-heading point. An unavailable title withholds that possible
finding and produces affected incomplete coverage. Existing Unicode White_Space
title blankness and known positives beside unrelated metadata uncertainty are
preserved. Metadata cannot erase independent Markdown syntax uncertainty.

See the [metadata contract](../../engineering/frontmatter.md#metadata-values-and-corrections).

## Configuration

Default enablement: Enabled.

level: integer 1 through 6, 1; frontmatter_title: boolean, false; a metadata title satisfies the rule when enabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the mdchk contract.

## Examples

Violating input:

````markdown
Introduction text.
````

Accepted input:

````markdown
# Introduction
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; moving or inventing headings changes document structure.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
