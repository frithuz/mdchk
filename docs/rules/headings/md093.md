# MD093: Inline formatting in headings

Status: analysis and configuration implemented for CommonMark and GFM.

Area: [Headings](index.md).

## Behavior

Report each actual emphasis, strong emphasis, inline code, link, or image inside
an ATX or Setext heading. Escaped markers and plain text are permitted. Each
finding covers the complete offending construct, including its own delimiters
and original interior source gaps, without surrounding heading markers.

Nested constructs are independent: allowing a link does not allow strong emphasis
in its label, and allowing an image does not allow emphasis in its description.
All actual parser link origins count, including resolved references, angle
autolinks and GFM bare autolinks. Unresolved reference-looking text and URLs that
remain text in the selected flavor do not count. GFM strikethrough itself is
outside this rule; targeted constructs within it still count.

Code payload, destinations, titles, raw HTML, comments and recognized metadata
remain opaque. A code span itself is checked, without reinterpreting its contents.
A construct opening inside active raw HTML text is excluded. Actual closing tags
inside structural wrappers restore eligibility for later constructs; HTML-looking
image-description or code payload cannot close an outer raw region. Raw state is
local to each heading. A construct opening outside raw text remains eligible even
when it contains raw markup.

## Configuration

Default enablement: Disabled; enable explicitly for projects that require this check.

`allowed_constructs`: list of `emphasis`, `strong`, `code`, `link`, `image`; default
empty. Values are exact and case-sensitive; duplicate valid entries are harmless.
Non-list, null, non-string or unknown values are configuration errors even while
the rule is disabled.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
## **Install**
````

Accepted input:

````markdown
## Install
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; removing formatting can discard links or alter meaning. MD093 emits
no edits or automatic preview authority. If MD047 supplies a newline-only
candidate, MD093 analyzes its actual bytes with the same immutable allowed list.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
