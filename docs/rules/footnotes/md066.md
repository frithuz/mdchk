# MD066: Unmatched footnote references and definitions

Status: planned for implementation.

Area: [Footnotes](index.md).

## Behavior

Report footnote references without definitions, definitions without references, and duplicate definitions. Compare labels using the selected format's normalization.

Run only when the selected format recognizes footnotes. Footnote syntax in a format without that extension is ordinary text.

Under the [Pandoc contract](../../engineering/pandoc-compatibility.md), compare named-note labels as exact, case-sensitive UTF-8 without unescaping or Unicode normalization. Keep all source references and definitions, including unused, unresolved, duplicate, and empty ones; the resolved semantic note alone is insufficient. Definitions in containers bind globally. Invalid labels follow ordinary reader interpretation and may instead be ordinary link-reference syntax.

Named references inside a named-note body stay literal and do not count as usage. Named references inside anonymous inline notes do count as body references. Anonymous notes have no label to match. Ignore escaped syntax, code, raw content, and comments.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
Text[^a]
````

Accepted input:

````markdown
Text[^a]

[^a]: Note
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Report only; missing content and unused notes require author judgment.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
