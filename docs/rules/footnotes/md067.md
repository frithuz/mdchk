# MD067: Definition order versus reference order

Status: planned for implementation.

Area: [Footnotes](index.md).

## Behavior

Require footnote definitions to appear in order of their first body reference. Repeated references do not change that order.

Run only when the selected format recognizes footnotes. Neither CommonMark nor the selected GFM profile recognizes footnotes, so this reserved contract is inactive for both supported formats. Footnote syntax follows ordinary text interpretation.

## Configuration

Default enablement: Enabled.

No rule-specific options.

All rules also accept the [shared settings](../index.md#configuration-and-findings). The defaults here are the planned mdchk contract.

## Examples

Violating input:

````markdown
Text[^a][^b]

[^b]: B
[^a]: A
````

Accepted input:

````markdown
Text[^a][^b]

[^a]: A
[^b]: B
````

Angle-bracket placeholders such as `<SPACE>`, `<TAB>`, `<EOF>`, and `<NEWLINE>` describe source characters rather than literal Markdown. Prose examples describe cases that cannot be represented directly in a UTF-8 document.

## Correction policy

Reorder complete definition blocks only when associated comments and multi-block content remain intact. Never move definitions across containers or apply a correction with ambiguous missing/duplicate definitions, nested definitions, comment ownership, or multi-block boundaries; report the finding without a fix.

Any correction must satisfy the [shared preservation contract](../index.md#implementation-contract). Report remaining findings after checking the corrected document again.

## Validation

Cover the examples, every option, protected content, nested containers, LF and CRLF input, and precise diagnostic ranges. For corrections, verify preserved meaning and a second fix run with no further changes.
